# Разбор списка задач клиента

Метод отработан на ProfiMet (2026-10-14): из 84 открытых задач получилось 30, по шести темам. Один клиент = одна сессия, клиенты
независимы. Правила ведения — `CLAUDE.md`, раздел «Правила ведения задач».

## Когда запускать
По запросу пользователя («разбери задачи <клиент>»), по одному клиенту за сессию. Не мешать с работой по кампаниям.

## Шаги (порядок важен)
1. **Подготовка (только чтение).** Прочитать `Клиенты/<Имя>/index.md`, последние ~15 записей `Журнал_изменений.md`, `Эксперименты.md`, `Хроника_*`;
   запустить `Скрипты/state_digest.py --customer-id <ID> --client-folder <Имя> --hours 168` — что изменилось в кабинете и у сторожа.
2. **Копия до.** Сохранить `Задачи.md` как есть в scratchpad (откат).
3. **Сверка каждой открытой задачи** с фактами, не с памятью: закрыта более поздней записью журнала? кампания/объект ещё существует?
   срок прошёл? Что можно проверить по кабинету/данным — проверить самому (скрипты `Скрипты/`, API чтение), пользователю списком «не знаю» не отдавать.
4. **Закрыть** выполненное и устаревшее с пометкой «ЗАКРЫТО ГГГГ-ММ-ДД (проверено): что именно и чем подтверждено». «СОСТОЯНИЕ…» и
   «СЛЕДУЮЩАЯ СЕССИЯ…» — не задачи: состояние уходит в `index.md` (строка) и `Хроника`, задача закрывается.
5. **Сократить** до одной строки: действие + срок + ссылка на И-/Э-номер (≈ до 300 знаков); полный прежний текст — дословно в
   `Задачи_подробности_<дата>.md` рядом.
6. **Слить** однотипное: сверки на одну дату — в одну, ревью окна покоя — в одну.
7. **Разложить по темам** тегом `#тема/…`: `кампании`, `тексты`, `трекинг`, `аудитории`, `инструменты`, `клиент`; внутри темы — по дате.
   Для клиента без части тем разделы пустыми не создавать. Новую тему — только при реальной необходимости.
8. **Вынести** закрытые в `Задачи_архив.md`; не клиентские задачи (инфраструктура, база знаний) — в корневой `Задачи.md`.
9. **Показать пользователю** итог: было → стало, что закрыто и чем подтверждено, что предлагается выбросить (решает пользователь).
   Выбрасывать только по его слову; «дальний ящик» (бэклог) — без срока, не мешает.
10. **Записать:** строка в `Инфраструктура.md` только если менялся метод; в `index.md` клиента — актуальный статус одной строкой.

## Что не делать
- Не закрывать задачу без проверки («на всякий случай»).
- Не переписывать длинные строки вслепую: терять уникальные цифры нельзя — оригинал в `Задачи_подробности`.
- Не менять кампании и цели: это только разбор списка.

## Что даёт пользователю
Список, где видно: что на неделе, что по датам, что в дальнем ящике; тег темы для сводного запроса в `Обзор-задач.md`.
