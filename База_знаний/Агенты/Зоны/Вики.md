# Область «Вики»: карточка для агента wiki-recorder

**Кто читает:** `wiki-recorder`. Файлы клиента большие (Журнал Landver 378 КБ, Хроника ProfiMet 150 КБ, Задачи Landver 153 КБ): целиком не читать никогда. Форматы ниже; образец своего клиента берёшь из ОДНОГО последнего блока файла (см. «Как вставлять»).
**Кто обновляет:** тот, кто меняет формат записи, в тот же ход. Нашёл расхождение формата с этой карточкой - в ответ, карточку не правь.
**Что НЕ делаешь:** цифры только из `40_запись.md`; номера И-/Э- следующий свободный (grep по заголовкам, не выдумывать); ничего из Решений, архива задач, Инфраструктуры, Бэклога, Инбокса.

## Как вставлять, не читая файл целиком
1. `Grep` по файлу: шаблон `^## ` (Журнал: `^## \[`), `output_mode: content`, `-n`. Вывод - только заголовки с номерами строк (дёшево).
2. **Порядок определяет клиент (разный!)** - сравни даты первого и последнего заголовка из вывода:
   | Клиент | Журнал_изменений | Хроника_<ГГГГ-ММ> | Эксперименты |
   |---|---|---|---|
   | EkspertAgro | новое СВЕРХУ (сразу после вводного абзаца) | новое сверху (по факту 12.11; старые 09.11 идут по возрастанию) | активные в разделе «Идут сейчас», завершённые - «Завершены / ретро» |
   | ProfiMet | новое СНИЗУ (конец файла) | новое снизу | по разделам файла |
   | Andverpersonalinjury | новое снизу | новое снизу | по разделам файла |
   Другой клиент - тот же приём: два заголовка с краёв, по датам видно направление.
3. `Read` с `offset`/`limit` ТОЛЬКО на последний блок (от заголовка до следующего `## `, обычно 10-25 строк) - это образец формата и место вставки.
4. `Edit`: якорь `old_string` - строка заголовка соседнего блока (она уникальна, содержит дату и номер И-/Э-); `new_string` = твой блок + пустая строка + этот заголовок (вставка сверху) либо последняя строка файла + пустая строка + блок (вставка снизу; в конце файла якорем служит последняя строка последнего блока, её читаешь тем же `Read`).
5. Читать обратно только вставленный фрагмент (`Read` offset/limit), не файл.

## Журнал_изменений.md (источник для ежемесячного отчёта клиенту)
Заголовок: `## [ГГГГ-ММ-ДД] <И-NNN | Э-NNN> [(ретро)] | <тип> | <объект с id> | <суть одной фразой> | <скрипт/команда>`
Список строк `- Метка: текст`, порядок и состав (все обязательны, нет данных - так и пиши):
- `Зачем` (из «почему» плана)
- `Что было → что стало` (EA) / `Что стало` + `До` (ProfiMet, Andver)
- `Тест до публикации` / `Прочитано из API ДД.ММ` - только когда есть в `40_запись.md`
- `Снимок «до»` (путь к файлу или «версия N в самом сервисе»)
- `Откат` (команда скрипта, по «да»)
- `Что мерить и когда` (дата оценки + команда измерения)
- `Результат на сегодня`: измерено / гипотеза / нет данных - не смешивать
- `Не проверено` (если есть)
- `Для отчёта клиенту (EN)`: одно простое предложение о пользе, без выдуманных результатов
- `Связано: И-/Э-номера` (ProfiMet)
Запись, восстановленная после факта: `(ретро)` в заголовке. Ошибка при записи, исправленная в тот же ход, - отдельной строкой `Ошибка при записи` (образец - ProfiMet И-107).

## Хроника_<ГГГГ-ММ>.md (лог «для себя» и для агента отчётов)
Заголовок: EA/Andver `## ДД.ММ (время или период) - <что сделано>`; ProfiMet `## [ГГГГ-ММ-ДД] ProfiMet / тема | действие | ключевое число`.
Тело: 2-5 строк-пунктов: кто решил («по «да» пользователя»), ссылка `[[Журнал_изменений]] Э-NNN`, прочитано обратно (что именно), `Не сделано`. Время записи в кабинет - Варшава, из `40_запись.md`; нет - «время не указано».
Итог сессии (Andver) - пункты жирным: **Решения пользователя**, **Найдено**, **Записи в кабинет**, **Новое знание**, **Следующая сессия (скопировать)**, **Каталог операций**. Это только когда задание просит итог сессии; иначе запись о действии.

## Эксперименты.md (только если в задании есть Э-номер и тест)
Блок `### Э-NNN | <что тестируем> | идёт | ДД.ММ.ГГГГ` в разделе «Идут сейчас»; строки: Гипотеза / Основание (срез, источник) / Альтернативы и почему не они / Что сделали (ссылка на Журнал) / Ожидание / Порог успеха / Стоп-правило / Базовые значения «до» / Измеряем (команда) / Не проверено на момент записи / Дата оценки / `Итог (ДД.ММ): ожидали - / получили - / вывод - / дальше -` (в день оценки заполняет другой ход). Порог и стоп-правило, которых пользователь не подтвердил, помечай «предложен ассистентом, НЕ подтверждён».
Если задание не называет Э-тест - в Эксперименты не пиши.

## Паспорт.md
Короткие строки `- Факт: значение - источник (скрипт/файл)`; разделы клиента (EA: «Адреса и аккаунты», «Кампании PMax», «GTM: клик по номеру»; Andver: «Страницы», «Аккаунты и ID», «Открытое»; ProfiMet: «Аккаунты и ID», «Где что искать»). Правка точечная: найди строку Grep-ом по ключу (id, имя тега), замени её; новый факт - в подходящий раздел. Frontmatter `updated:` - сегодняшняя дата.

## Задачи.md
Строка: `- [ ] #задача #клиент/<Имя> #тема/<тема> <действие> 📅 ГГГГ-ММ-ДД` (до ~300 знаков). Закрытая: `- [x] ... ЗАКРЫТО ДД.ММ (проверено): <чем>`. Закрывать - Grep-ом по id/номеру Э-/И- нашёл строку, Edit по её тексту. Новая задача «проверить эффект» - в раздел темы клиента (EA: «Трекинг», «Кампании»; ProfiMet: по темам; Andver: «Активные» или раздел направления), с датой оценки из плана. Разделы по темам, внутри по дате; не заводить новую тему.

## Ловушки
- В Andver Задачи (153 КБ) и Журнал (378 КБ) - не читать подряд: Grep + offset/limit.
- Порядок «сверху/снизу» разный по клиентам - сначала шаг 2, потом вставка.
- Хроника EA содержит записи в смешанном порядке (12.11 сверху, 09.11 по возрастанию): вставляй сверху, не перестраивай файл.
- `Edit` требует предварительного `Read` файла; хватает ли чтения фрагмента (offset/limit) для `Edit` - см. результат замера в `Оптимизация_агентов.md` («Замер 2026-11-12, вторая часть»), до замера считать не проверенным.
