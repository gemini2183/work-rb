# Область GTM: карточка для агентов

**Кто читает:** `gtm-checker` (режим чтения/проверки) и `gtm-executor` (запись по «да»). Каталог `Агенты/index.md` им читать не нужно: здесь всё, что есть по GTM. Нет подходящего скрипта — раздел «Пробел» в конце.
**Кто обновляет:** тот, кто добавляет или меняет скрипт GTM (агент «сборщик скриптов» или супервайзер), в тот же ход. Строка: скрипт, режим, что делает, параметры, ловушка.
**Аккаунт и контейнер клиента:** `Клиенты/<Имя>/Паспорт.md`. Сначала Паспорт, потом скрипты. Запуск: из `D:\GitHub\work-rb\Скрипты`, `PYTHONUTF8=1 python <скрипт> --help` (справка без чтения исходников).

## Правила области
00. Скрипты записи (`gtm_tel_click_tag.py`, `gtm_publish_version.py`, `gtm_apply_plan.py`) запускать с `--log-file Клиенты/<Имя>/Работы/<дата>_<задача>/файлы/<скрипт>_<план|execute>.log`: вывод (версия, чтение обратно, откат) сохраняется сам, `40_запись.md` собирается из лога. Для остальных GTM-скриптов записи `--log-file` пока нет.
0. Экономия вызовов (замер 12.11: агент сделал 7 вызовов, из них 6 лишних `--find`): сначала один `--summary`; `--find` — только за деталями конкретного тега из сводки (по одному на тег); поиск по «синонимам» одного слова не повторять.
1. Новые теги и триггеры — в НОВОЙ рабочей области от последней версии; старые объекты контейнера не править без отдельного пункта плана. Живая версия должна быть последней, иначе в версию попадут чужие правки (скрипты это проверяют).
2. Перед публикацией — проверка во временной среде (`gtm_*_test*.py` / `gtm_test_version.py`): новая версия даёт событие, прежняя нет.
3. Записей в Ads, Ringostat, Tilda, Supabase агенты GTM не делают. Таблицу Supabase создаёт человек.
4. Метки тестовых заходов: `utm_campaign=test`, имя «claude» в метках не писать.
5. Ключи в ответы и файлы не писать.

## Пробел (нет скрипта на строку плана или вопрос)
Агент не пишет код и не придумывает обход. В свой файл (`12_gtm.md` / `40_запись.md`) и в ответ: раздел «Пробел»: строка плана или вопрос; что искал в карточке; что нужно (вход, выход, чтение или запись). Супервайзер решает, вызвать ли «сборщика скриптов».
