# Агент «Проверка GTM под форму» (gtm-checker)

Решение пользователя 2026-11-12: задачи по GTM отдавать узкому агенту с конкретными входными данными, без контекста сессии (а не скиллу: у агента свой контекст, скилл загружается в основную сессию). Файл агента — `.claude/agents/gtm-checker.md`, модель haiku, только чтение.

## Зачем
Случай Landver Motorcycle 12.11: форма `ldv-moto-form` исправлена, но Tilda шлёт `submit_ldv-moto-form`, а триггеры GA4 `form_submit` его не ловили. Заявка не стала бы целью. Нашли ручной пробой в основной сессии. Проверка «форма страницы ↔ триггер GTM» должна идти до включения рекламы на любую новую страницу.

## Вход (всё, что нужно агенту)
- адрес страницы и клиент (папка в `Клиенты/`);
- GTM: аккаунт и контейнер (Landver: `6353362488` / `261134482`; в `Паспорт.md`, «Аккаунты и ID»);
- id форм — агент берёт сам из `page_tracking_check.py`; можно передать готовые.

## Шаги агента
1. `page_tracking_check.py` (метка `utm_campaign=test`) → id форм страницы.
2. `gtm_form_event_check.py --form-id …` → «ловится / не ловится», какой триггер. Скрипт строит событие `submit_<id>` (правило Tilda) и сверяет с триггерами тегов GA4 `form_submit`.
3. Не ловится → черновик плана `update_triggers` (JSON) и проверка плана `gtm_apply_plan.py` без `--execute`.
4. Результат — `12_gtm.md` в папке задачи.

## Запись: агент `gtm-executor` (решение пользователя 2026-11-12: запись тоже отдаётся агенту, экономия контекста основной сессии)
Файл агента — `.claude/agents/gtm-executor.md`, модель sonnet. Задание ему: папка задачи + путь к JSON-плану + **цитата «да» пользователя с датой, где названа публикация** (без слова про публикацию он создаёт версию и не публикует).
1. Версия «до» запоминается как номер отката.
2. `gtm_apply_plan.py --execute` (версия без публикации).
3. `gtm_test_version.py --push-event submit_<id> --events form_submit`: новая версия даёт `form_submit`, прежняя нет; иначе не публикует.
4. `gtm_publish_version.py --execute`, затем `gtm_form_event_check.py` по живой версии (код 0).
5. Пишет `40_запись.md`; Журнал, Хронику, Паспорт и Задачи записывает `wiki-recorder`.

## Что остаётся основной сессии
- Показать пользователю вердикт `gtm-checker` и план «было → станет», получить «да» (с публикацией).
- Передать «да» агенту `gtm-executor` цитатой.
- Тестовая заявка пользователя (имя TEST) после публикации; сверка GA4 Realtime и получателей.

## Ограничения
- Имя события выводится по коду Tilda (`tilda-forms-1.0.min.js`: `dataLayer.push({event:"submit_"+formId})`, formId = атрибут `id` формы; проверено 12.11), живой отправкой подтверждено только для `vb-b2s-form`; подтверждено живой отправкой только для `vb-b2s-form` (испанская, 11.11). Для остальных — по аналогии, до тестовой заявки.
- Регэкспы проверяются питоновским `re.search`; для простых выражений совпадает с JS GTM.
- Триггеры типов «клик», «видимость», «отправка формы GTM» скрипт не разбирает (помечает «не разобран»).
- Агенты `gtm-checker` и `gtm-executor` ещё не запускались (созданы 12.11); хук чтения агентов не подтверждён (П-021).
