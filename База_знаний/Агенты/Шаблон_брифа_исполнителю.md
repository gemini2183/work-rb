# Шаблон брифа исполнителю

**Зачем.** В пилоте 11.11 исполнитель 3 читал 13 источников и историю, чтобы найти несколько решений (П-016). Бриф — это эти решения и данные в одном месте. Исполнитель читает бриф и максимум 5 файлов из него; Хронику, Решения и чужие скрипты целиком — нет.

**Когда заполняется.** В тот же ход, когда пользователь принял решение (гео, язык, бюджет, ставка, стоп-правило, «да» на шаг). Не в момент постановки задачи исполнителю: тогда решения уже собраны, а не раскопаны.

**Где лежит.** `Клиенты/<Имя>/Брифы/<задача>.md`. Задание агенту = путь к брифу + контракт ответа (ниже), другого списка нет.

## Шаблон

```
# Бриф: <задача> (<клиент>, <дата>)
Цель одной фразой и критерий готовности:
Режим: подготовка / запись по «да» (дата и формулировка «да» пользователя дословно):

## Решения пользователя (дословно или кратко, с датой)
- ...

## Данные (значения, а не ссылки на историю)
- ID, адреса, номера (из Паспорта):
- Гео / язык / бюджет / ставка / расписание:
- Образец (одна эталонная кампания/страница и её файл настроек):

## Файлы, которые читать (максимум 5, полные пути)
1.
2.

## Нельзя
- запись в кабинеты без «да»; чужие объекты; ...

## Что вернуть (контракт, до 15 строк)
Сделано / Проверено (источник, время) / Не проверено и как проверить / Блокеры / Что нужно от пользователя / Пути к файлам.
```

## Правила супервайзеру
1. Не писать в задании «прочитай CLAUDE.md и Хронику»: CLAUDE.md агент получает при старте. Нужна запись из Хроники — вынести её выжимкой в раздел «Данные».
2. Режим сессии (Auto / Manual) выбирать до запуска исполнителя, который будет писать: отказы классификатора стоили двух возвратов в пилоте 11.11.
3. Правка плана после ответа пользователя — новый короткий агент с путём к файлу плана, а не `SendMessage` старому (его история на 200+ тыс. перечитывается в каждом вызове).
4. Рутинная запись в вики после записи в кабинет (Журнал, Хроника, Паспорт, Задачи) — отдельный короткий агент на дешёвой модели или скрипт, не продолжение сборщика.
