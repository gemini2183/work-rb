# Как это делают в практике, что берём себе, что требует решения

Карта: [[Анализ_и_оптимизация.canvas]]. Концепция: [[Концепция]]. Инвентаризация: [[1_инвентаризация]].
Надёжность источников: **П** = первоисточник (справка Google Ads), **В** = вторичный (блог агентства, коммерческий, не проверялся), **Сн** = только сниппет поиска, страницу не открывал.

## 1. Что нашёл в практике

| Тема | Что говорит практика | Источник |
|---|---|---|
| Смена цели на автостратегии | Ставочная система реагирует на смену цели сразу (минуты); выйти на новую цель может за 1–2 «конверсионных цикла» (цикл = типичное время от клика до заявки; если большинство кликов конвертируется за 7 дней, подстройка около 7 дней). Крупная смена цели даёт сопоставимо крупное изменение расхода или объёма. Не менять цель несколько раз внутри одного цикла | П: support.google.com/google-ads/answer/10433846 |
| Лаг заявок | Google отчитывает конверсии по дате клика, поэтому недавние дни показывают завышенную цену заявки; есть отчёт «conversion lag» с прогнозом доборных конверсий для Search и Performance Max | П: support.google.com/google-ads/answer/9347141 |
| Эксперименты | Рекомендуют 4–6 недель и 1–2 конверсионных цикла; первые 7 дней в результатах отбрасываются; долю трафика/бюджета после старта менять нельзя; несколько экспериментов одновременно не рекомендуется; есть разделение по бюджету (Search) и по трафику (PMax, Demand Gen) | П: support.google.com/google-ads/answer/13826584 |
| Обучение стратегии | Крупные структурные изменения (новая кампания, новая стратегия) могут показывать статус «Learning» до 7 дней; при наличии истории в аккаунте стратегия не стартует с нуля | П: тот же FAQ |
| Рекомендации по целям (в разделе про PMax) | Цель CPA/ROAS держать в пределах 15 % от фактической истории; у новой кампании первые 15–30 конверсий без цели (Max conversions/clicks); не делать реактивных правок первые 2 недели обучения | П: тот же FAQ |
| Мало конверсий | Заменять конверсии опережающими показателями (показы, клики, посещения, микро-действия), на которых больше событий; решения заранее: главный показатель, минимум расхода и срока, порог остановки, порог роста, кто решает; не объявлять победителя каждую неделю; не дробить отчёт до пустых ячеек; для малых данных годятся переключательные тесты (включил-выключил), изоляция по одному каналу, гео-холдауты | В: stackmatix.com/blog/low-volume-marketing-measurement-startups (примеры гипотетические, SaaS-контекст) |
| Малые выборки и бюджет | Байесовская оценка: не переносить большую долю бюджета в сегмент только потому, что у него выше сырой CR на малой выборке; брать стартовую оценку из истории аккаунта и уточнять данными кампании. Google сам использует данные на уровне запросов по аккаунту для редких ключей | В: effectivewebsolutions.biz (рекламный пост агентства) |
| Пейсинг | Распространённые калькуляторы: линейный темп «потрачено/прошло дней × дней в месяце», допуск-«коридор»; в моих результатах поиска нет методов прогноза заявок с интервалом на конец месяца | Сн (калькуляторы, страницы не открывал) |
| Порог данных для автостратегий | Google публикует 15 конверсий за 30 дней для tROAS, рабочая цифра ближе к 50 за 7 дней | Сн (lgg.media), не проверено |

Чего поиск НЕ дал (не нашёл, не утверждаю, что этого нет): методы прогноза итога месяца по заявкам с интервалом; готовые правила «ноль заявок» с подтверждённой долей ложных срабатываний; сроки отклика ручных ставок и бюджета (не нашёл, только автостратегия).

## 2. Что это значит для нас (выводы)
1. **Правило «смена цели CPA сбрасывает окно» в наших файлах (Процедура_догон_плана_месяца_лог.md стр. 84; Методология стр. 41) расходится с первоисточником Google**: смена цели не сбрасывает, а даёт задержку 1–2 цикла. «Learning» до 7 дней упоминается для новых кампаний и стратегий. Это основание пересмотреть правило, решение за вами (см. D5).
2. **Ваш конверсионный цикл = срок ожидания отклика.** Его надо измерять на ваших данных: у ProfiMet `gclid` в формах пуст до 27.10 (Калибровка стр. 25), значит клик-уровня «клик → заявка» может не быть, и лаг придётся оценивать грубее (по дням). Это техническая проверка, не вопрос владельцу.
3. **Google-эксперименты слишком долгие для месячного цикла** (4–6 недель, первые 7 дней не считаются). Для вас годятся как фоновая линия. Для быстрых проверок внутри месяца практика предлагает опережающие показатели, переключательные тесты и «разнести правки по времени».
4. **Идея сжатия оценки к истории (приор) подтверждается практикой** (В) и уже есть в `campaign_prior` (стр. 147–163), но с недостатками из блока 1.
5. **Предварительно записанные правила решений** (порог остановки, порог роста, кто решает) практика советует как защиту от погони за шумом. Это совпадает с вашей задачей «чтобы оправдать действия перед начальством»: у нас есть форма «было → станет + допущения» (Алгоритм, Этап 3); не хватает порогов, выведенных из данных (блок 4).
6. **Оптимизировать по одному показателю**: практика советует один главный показатель с достаточным объёмом, у вас это цена заявки. Сходится с вашим решением 20.11.

## 3. Что требует решения владельца
| № | Вопрос | Моя рекомендация |
|---|---|---|
| D1 | Утвердить принцип: метод анализа выбирается по остатку дней и объёму данных (таблица в чате 20.11), пороги выводятся из данных в блоке 4 | Да |
| D2 | Вес недельного ритма (4 разбора в месяц на клиента) по токенам: Конституция п. 9, бюджет ≤ 10 $/мес сверх подписки. Не оценён | Сначала измерить вес одного разбора на ProfiMet |
| D3 | Критерий зоны 3 (KPI недостижим) и допустимые приёмы «спасения»; граница: урезание охвата ради цены допустимо (ваше 20.11), но лучше проекция с вероятностью | Критерий вывести из «достижимости» в блоке 4 |
| D4 | Клиенты с продажами (ProfiMet): основной показатель по-прежнему цена заявки или цена продажи? У ProfiMet допуски привязаны к цене продажи (Калибровка стр. 33) | Для таких клиентов добавить цену продажи как ограничитель, цена заявки главная |
| D5 | Пересмотреть правило «смена цели CPA = класс А, сбрасывает окно» по справке Google (см. вывод 1) | Да, после проверки на истории клиента |
| D6 | Фоновые тесты: оставляем долю 10–15 % бюджета, оцениваем по опережающим показателям, не по заявкам | Да |
| D7 | Разрешить заказ новых скриптов: нужная цена на остаток с допуском ±15 %, вероятность попасть в допуск, перенос бюджета между сегментами (после пробы цикла ProfiMet) | Да, после пробы |

## 4. Что делаю я без вашего решения (не вопрос)
- Дочитываю оставшиеся скрипты и калибровки других клиентов (блок 1).
- Проверяю, есть ли в данных клик-уровень лага.
- Готовлю заказы на скрипты D7.
- Свожу блок 1: что берём, что убираем, какие пороги противоречат друг другу.
