# Шаг 0: план и продажи

Документ общий для всех клиентов.

## 1. Цель
Оценить, насколько проект отстаёт от плана месяца и реалистично ли догнать. Рассчитать показатели, которые нужны на остаток месяца.

## 2. Вход
- План месяца из таблицы «Цели2»: бюджет, число заявок, плановая цена заявки. Продаж в таблице нет.
- Допустимая цена заявки (KPI). У клиентов без продаж это плановая цена заявки из таблицы. У клиентов с продажами (ProfiMet, EkspertAgro) её корректируем на актуальную цену продажи: цена продажи × текущая доля «заявка → продажа». ProfiMet: цена продажи 40–45 €, ориентир 43 €.
- Факт месяца на сегодня: расход, заявки, у клиентов с продажами ещё продажи.

## 3. Что считается
- Доля «заявка → продажа» и как она двигается по неделям (только для клиентов с продажами).
- Отставание от плана на сегодня.
- Прогноз закрытия месяца по текущему темпу.
- Показатели на остаток месяца.

## 4. Скрипты
Описано по шапкам скриптов, запуском не проверено. Все скрипты только читают.

| Что считаем | Скрипт | Что уже умеет | Дыра |
|---|---|---|---|
| План, факт на сегодня, отставание, прогноз закрытия, нужный расход и допустимая цена заявки в будний день на остаток | `pace_vs_plan.py` | Читает план из «Цели2», расход из Google Ads, заявки из `leads_standard`. Будний день = 1, выходные один вес из последних недель. Пишет CSV в `Клиенты/<Имя>/Статистика/` | Нет интервала у прогноза. Нет клики, CPC, конверсия на остаток. Праздничные дни (11.11, расход 0) в веса не попадают. Лаг заявок не учтён. План читается только на сегодня, истории версий нет |
| Доля «заявка → продажа» по неделям, допустимая цена заявки, прогноз цены продажи, заявки на остаток для выхода на цель | `sales_pace.py` (только ProfiMet и EkspertAgro) | Когорты заявок по неделям пн–вс, зрелая доля (недели старше 80-го процентиля задержки), интервал Уилсона 95 %, «данных мало», если зрелых недель меньше 4 или продаж меньше 10. Допустимая цена заявки = цена продажи × доля | Заявка считается по `leads_standard`, определение заявки не решено. Скрипт перезаписывает `pace_vs_plan_<месяц>.csv`. Продажи привязаны к кампании не все |
| Тренд заявки → продажи по источникам, последние 7 дней | `profimet_sales_trend.py` | Дашборд HTML и CSV по дням, медиана задержки | Только ProfiMet, по источникам, а не по кампаниям; нужен ли шагу 0, не решено |
| Определение зоны 1, 2, 3 | нет | | Скрипта нет. Критерий зоны 3: три вопроса в Концепции (Д7), пороги не откалиброваны. Зоны 1 и 2: коридор прогноза внутри допуска или задевает границу |
| Клики, CPC, конверсия на остаток | нет | | Скрипта нет |

Состав расчёта по клиентам:
- Клиенты без продаж: только `pace_vs_plan.py`.
- ProfiMet и EkspertAgro: `pace_vs_plan.py`, затем `sales_pace.py`.

## 5. Роли
| Роль | Что делает на шаге 0 | Чего не делает |
|---|---|---|
| Оркестратор | Пишет бриф аналитику: клиент (папка и ID кабинета), месяц, дата «сегодня», основной источник заявок, папка задачи `Клиенты/<Имя>/Работы/<дата>_<задача>/`, применить шаг 0. Запускает аналитика, затем контролёра. Отвечает владельцу по Конституции, раздел 7 | Не читает сырой вывод скриптов. Не считает |
| Скрипты | `pace_vs_plan.py`, для ProfiMet и EkspertAgro затем `sales_pace.py`. Считают план, факт, отставание, прогноз, долю «заявка → продажа», допустимую цену заявки, показатели на остаток | Выводов и рекомендаций словами не пишут |
| Аналитик | Запускает скрипты по порядку из пункта 4. Читает таблицы. Пишет вердикт по `Контракт_ответа.md`: утверждение, число, источник: отставание на сегодня, прогноз закрытия, зона, показатели на остаток. Если расчёта нет (зона, клики, CPC, конверсия), пишет «в расчёте этого нет» и заказывает скрипт | Не считает сам. Не выдумывает цифры. Не повторяет скрипт с другими аргументами для «починки». Не подставляет определение заявки, если оно не задано в брифе |
| Контролёр | После вердикта независимо перепроверяет каждую цифру повторным запуском скриптов чтения и по источникам | Ничего не меняет в кабинетах и данных |
| Исполнитель | На шаге 0 не участвует: шаг только читает | Запись в кабинет |

## 6. Выход
- Отставание от плана на сегодня: по расходу, по заявкам, по цене заявки; у клиентов с продажами ещё по продажам и цене продажи.
- Прогноз закрытия месяца с интервалом.
- Зона: реалистично ли догнать (1, 2 или 3).
- Показатели на остаток месяца: нужный расход в день, допустимая цена заявки, нужное число кликов, CPC, конверсия.

## 7. Не решено
- Что считать заявкой.
- Критерий зоны 3 (в Концепции три вопроса, пороги не откалиброваны).
- Скрипты, роли, куда идёт выход на шаг 1.
