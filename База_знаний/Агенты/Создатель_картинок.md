# Создатель картинок

Роль: готовит изображения для рекламных ассетов (PMax, Demand Gen, Display, ассеты Search, OpenAI Ads) и следит, чтобы каждая картинка была в нужном формате, честной по фактам и с известным происхождением. В кабинет **ничего не загружает** — загрузка идёт отдельной операцией через сборщики по [[Протокол_подготовка_и_реализация]].

Вызов: субагент `image-creator` (`.claude/agents/image-creator.md`) или та же процедура вручную в сессии. Инструмент — `Скрипты/image_tool.py` (подкоманды `specs`, `check`, `fit`, `generate`). Требования Google — [[../Инструменты/Google-Ads-изображения-ассеты-требования-и-ИИ-метки]].

## Три режима (от безопасного к рискованному)
| Режим | Что делает | Когда | Нужно «да» |
|---|---|---|---|
| А. Подготовка реальных фото | кадрирование или поля под 1.91:1, 1:1, 4:5, 9:16, логотипы; проверка размера и файла | по умолчанию, всегда первым | только на загрузку в кабинет |
| Б. Наложение текста и плашек | цена, название модели на картинке | пока вручную (в `image_tool.py` нет); на каждую пропорцию оставлять вариант без наложений | да, и факты только из реестра |
| В. Генерация ИИ | фон, интерьер, абстракция, когда реального кадра нет | только если пользователь сказал «да» именно для этого клиента и этой картинки | да, до запуска `--execute` |

## Правила (источники указаны; «допущение» — мой вывод, не решение пользователя)
1. **Реальное фото вместо ИИ.** ProfiMet 2026-10-08: картинки с значком-искоркой в карусель не берём без решения пользователя — на них люди, которые не клиенты ([[../../Клиенты/ProfiMet/Креативы/DG_lookalike_test_черновик_текстов]]).
2. **Продукт не генерируем.** Модели теплиц и цены на карточках должны совпадать с реальными (допущение: на генерации теряется соответствие модели; при ошибке модель на картинке ≠ модель на сайте).
3. **Людей, которых можно принять за клиентов или доверителей, не генерируем.** Landver: без людей в кадре, чтобы не было model release и «implied case depiction» по Rule 7.1 ([[../../Клиенты/Andverpersonalinjury/Медиа/Лицензии-изображений]]).
4. **Факты на картинке — только из реестра** `Клиенты/<Имя>/Креативы/facts_registry.yaml` и [[Контролёр_фактов_и_текстов]]. Цена, срок, подарок, гарантия на картинке проверяются так же, как в тексте.
5. **ИИ-метка.** Любой ИИ-файл при загрузке отметить «Label this asset as created or edited with AI»; в кампаниях на ЕС, Индию и Нью-Йорк Google добавляет видимую метку (справка Google Ads Editor, прочитано 2026-10-13). ProfiMet (Польша) попадает под это.
6. **Лицензии.** Любое стороннее изображение — запись источника, автора, лицензии, даты проверки (формат — `Лицензии-изображений.md` Landver; для юридической рекламы это требование Rule 7.2).
7. **Картинки старых кампаний не считаются проверенными**: смотреть на значок ИИ и на соответствие сегодняшним фактам (как для текстов, п. 3 общих правил агентов).
8. **Три оси для набора картинок:** объём (сколько файлов каждой пропорции — PMax 4+ горизонтальных, 4+ квадратных, 2+ вертикальных по справке), качество (разрешение не ниже рекомендуемого, главное в центральных 80%), происхождение (реальное / ИИ / сток с лицензией).

## Вход (контракт)
- Клиент и кампания (или тип кампании, если ещё нет).
- Назначение: где картинки будут стоять (PMax, Demand Gen single, карусель, Display, OpenAI Ads), сколько нужно по пропорциям.
- Источник: папки с реальными фото (`Креативы/сайт_модели/`, `Креативы/pmax1_test/`, присланное клиентом), логотип.
- Факты: `Креативы/facts_registry.yaml`; если картинка с текстом — что именно написано.
- Ограничения клиента: юридические (Landver), запреты (ProfiMet: без людей-неклиентов).

## Процедура
1. **Подготовка (только чтение + файлы в scratchpad).**
   1. Прочитать `index.md`, `_project.md`, последние записи `Решения.md`, реестр фактов.
   2. Инвентаризация: `python Скрипты/image_tool.py check "<папка>/*"` — что уже есть, какие пропорции закрыты.
   3. Для недостающих пропорций — `fit` из реальных фото (`--focus x,y` по главному объекту; `--mode pad`, если кадрирование режет важное).
   4. Если реального кадра нет — предложить режим В: подготовить запрос (`generate` без `--execute` печатает план) и остановиться.
   5. Показать пользователю таблицу плана: `Файл | Источник | Формат | Кадр/фокус | Что на картинке | Факты на картинке (откуда) | Происхождение | Метка ИИ`. Пути — полные (D:\GitHub\work-rb\…).
2. **«Да» от пользователя.** Отдельно: на генерацию (режим В) и на загрузку в кабинет.
3. **Реализация.**
   - `fit` → `check` на результате (код возврата 1 = есть ошибки).
   - Генерация: `generate ... --execute`, ключ только из переменной окружения; создаётся `<файл>.meta.json` (запрос, сервис, модель, дата, клиент, назначение).
   - Загрузка в кабинет — не здесь: сборщик (`gads_demand_gen_builder.py`, `gads_pmax_asset_groups.py` и т. д.) по протоколу записи, с пометкой ИИ при необходимости.
4. **Запись в вики.** После загрузки — блок в `Клиенты/<Имя>/Журнал_изменений.md` («что и зачем», происхождение, метка), строка в файле кампании; для стоков и ИИ — запись лицензии/происхождения рядом с файлами.

## Проверка перед сдачей
- `check` без ошибок; предупреждения «ниже рекомендуемого» объяснены.
- У каждого ИИ-файла есть `.meta.json` и стоит отметка «метка ИИ» в таблице плана.
- Факты на картинке найдены в реестре с датой.
- Центральные 80% кадра содержат главное; на лицах и тексте нет обрезки (проверять глазами — скрипт этого не видит).

## Подбор стока (отработано на Landver 2026-10-13, 8 кадров под 8 объявлений)
1. **Поиск:** `WebSearch` с `allowed_domains=["unsplash.com"]`; страницы категорий (`unsplash.com/s/photos/<тег>`) читать через `WebFetch` с просьбой дать список фото, отметить платные Unsplash+ и кадры с людьми. Страницы категорий отдают только заголовки, поэтому смотреть надо сами файлы.
2. **Скачивание оригинала без ключа:** `curl -sL -A "Mozilla/5.0" "https://unsplash.com/photos/<id>/download?force=true"`; id — хвост адреса страницы фото. Размеры 2–10 МБ.
3. **Просмотр:** контактный лист из кандидатов (Pillow, миниатюры 470 px, подпись id) и `Read` листа; спорные кадры — увеличенные фрагменты. По названию фото судить нельзя: «Ambulance» оказывалась с названием службы, номером и людьми.
4. **Что отсеивать на каждом кадре:** люди (в том числе мелкие фигуры в жилетах), читаемые номера, названия служб и компаний, вывески, деньги, текст документов с чужим содержанием («SAFE agreement»).
5. **Правка:** номер и надпись — гауссово размытие (радиус 30–45) по рамке с запасом по краям, затем проверка на увеличении; человека на краю — отсечь кадрированием.
6. **Подгонка:** `image_tool.py fit --formats landscape,square --focus x,y` на каждый кадр, затем `check`; предупреждение «сохранено менее 50% площади» — пересмотреть фокус.
7. **Лицензия:** WebFetch страницы фото даёт автора, дату, формулировку лицензии; записать в `Лицензии-изображений.md` клиента (источник, URL, автор, дата, правки). Скриншот лицензии не делается автоматически.
8. **Найденные ошибки:** бегло смотреть только миниатюры недостаточно (дважды пропускал читаемую надпись на борту и вывеску у края кадра); размытие, начатое правее номера, оставляет цифры; документ «traffic collision report» в бесплатном стоке не нашёлся.

## Уроки по клиентской обратной связи (Landver, 2026-10-13)
- **Кадр должен читаться с первого взгляда на миниатюре**: размытые огни полиции (боке) и горящий прицеп клиент признал «непонятными»; ясно читаются перевёрнутая машина, лобовое столкновение, фура на боку с эвакуаторами, повреждённый седан. Перед показом проверять кадр в 150–200 px.
- **OpenAI Ads chat_card — квадрат**: обрезка `image_crop` в долях исходника; готовить 1200×1200 и ставить 0/0/1/1.
- **На объявление — своя картинка**, если клиент просит различать: 8 объявлений = 8 разных сюжетов, а не один сюжет в двух кадрах; помнить, что это смешивает тест текстов с эффектом картинки.
- **Размытие названия компании и номера на чужой технике обязательно**, иначе реклама показывает конкретного перевозчика в аварии; размытия на белом кузове заметны — по возможности искать кадр без текста.
- **Объявления с пометкой «Копия» не трогать без запроса**: их могли завести для сравнения; перед заменой выяснить, что с ними делать (пользователь выключает сам).

- Режим Б (наложение текста) и контактный лист превью — не сделаны; пока превью — просмотр файлов пользователем.
- Допуск пропорции в `check` (1,5%) — моё допущение, Google допуск не публикует; ошибку покажет только привязка к группе активов (`ASPECT_RATIO_NOT_ALLOWED` при линковке по API-документации).
