# Шаг 0: план и продажи

Документ общий для всех клиентов.

## 1. Цель
Оценить, насколько проект отстаёт от плана месяца и реалистично ли догнать. Рассчитать показатели, которые нужны на остаток месяца.

## 2. Исходные данные
Берутся снаружи, шаг их не считает.
- Клиент, месяц, дата «сегодня».
- План месяца из таблицы «Цели2»: бюджет, число заявок, плановая цена заявки. Продаж в таблице нет.
- Правило заявки клиента (раздел 3).
- Цена продажи (только для клиентов с продажами): из файла клиента (бриф или договорённости). В этом документе значений клиентов нет.

## 3. Что считается
- Факт месяца на сегодня: расход, заявки, у клиентов с продажами ещё продажи.
- Доля «заявка → продажа» и как она двигается по неделям (только для клиентов с продажами).
- Допустимая цена заявки (KPI). У клиентов без продаж это плановая цена заявки из таблицы. У клиентов с продажами: цена продажи × текущая доля «заявка → продажа».
- Отставание от плана на сегодня.
- Прогноз закрытия месяца по текущему темпу.
- Показатели на остаток месяца.

Что считать заявкой (общее правило для всех клиентов, условия задаются отдельно для каждого клиента):
- Если у клиента есть отдельные сборщики заявок (коллтрекинг для звонков, своя база или CRM для форм), считаем заявки по ним и сверяем с Google Ads. По разнице определяем, насколько можно доверять Google Ads. Если разница большая, используем данные сборщиков.
- Если сборщиков нет, считаем заявки только по Google Ads.
- Склейка звонка и формы одного человека в одну заявку возможна там, где CRM получает формы с номером телефона. Это на будущее, сейчас не склеиваем.
- Конкретное правило заявки клиента (какие источники, какая уникальность, склеиваются ли звонок и форма) задаётся в файле клиента и передаётся в брифе. В этом документе его нет.

## 4. Скрипты
Нужны четыре скрипта: три читают данные, один считает. Сопоставление с существующими скриптами и список дыр делается отдельным шагом.

Чтение:
1. **План и факт:** план месяца из «Цели2», расход из Google Ads по дням.
2. **Заявки по дням:** по правилу заявки этого клиента (пункт 3). Недели и факт на сегодня это суммы по дням, отдельного скрипта не нужно.
3. **Продажи:** из CRM, привязанные к заявке, с задержкой заявка → продажа. Только для клиентов с продажами.

Расчёт:
4. **Расчёт шага 0:**
   - доля «заявка → продажа» (общая и по неделям) и допустимая цена заявки;
   - отставание, прогноз месяца с интервалом 80 %, показатели на остаток;
   - зоны по каждому показателю.
   На выходе одна таблица (пункт 6).

Клиенты без продаж: скрипты 1, 2, 4 (без части про долю и продажи). Клиенты с продажами: все четыре.

## 5. Роли
| Роль | Что делает на шаге 0 | Чего не делает |
|---|---|---|

Запускает аналитика, затем контролёра. Отвечает владельцу по Конституции, раздел 7 | Не читает сырой вывод скриптов. Не считает |
| Скрипты | Четыре скрипта из пункта 4. Читают данные и считают | Выводов и рекомендаций словами не пишут |
| Аналитик | Запускает скрипты по порядку из пункта 4. Читает итоговую таблицу. Пишет вердикт по `Контракт_ответа.md`: утверждение, число, источник: отставание на сегодня, прогноз закрытия, зона, показатели на остаток. Если расчёта нет, пишет «в расчёте этого нет» и заказывает скрипт | Не считает сам. Не выдумывает цифры. Не повторяет скрипт с другими аргументами для «починки». | Исполнитель | На шаге 0 не участвует: шаг только читает | Запись в кабинет |

## 6. Выход
Итоговая таблица шага 0, передаётся на шаг 1.

1. **Допустимая цена заявки.** Плановая цена из таблицы. У клиентов с продажами ещё: цена продажи, доля «заявка → продажа» (общая с интервалом и по неделям), допустимая цена по ней.
2. **По каждому из трёх показателей (цена заявки, число заявок, расход):**
   | Показатель | План | Факт на сегодня | Прогноз месяца (интервал 80 %) | Отставание | Зона |
   |---|---|---|---|---|---|
3. **На остаток месяца:** нужный расход в день, нужное число заявок, допустимая цена заявки на остаток, нужные клики, CPC, конверсия.
4. **Служебное:** клиент, месяц, дата «сегодня», сколько дней осталось, по какому правилу считались заявки, пометка «данных мало» там, где мало.

Что выход даёт следующим шагам:
- Допустимая цена заявки: линейка для вердикта на шаге 5 (вилка цены против допустимой).
- Зона по каждому показателю: определяет, что делать. Зона 1: ничего не меняем без причины. Зона 2: обратимые шаги, размер зависит от оставшихся дней. Зона 3: цель «спасти следующий месяц», цикл идёт по другому сценарию. Шаг 1 по зонам видит, где искать проблему: в цене или в объёме.
- Показатели на остаток: целевые значения для прогноза правки на шаге 3.

Как передаётся: таблица от скрипта в файле задачи `Работы/<дата>_<задача>/`, шаги читают из неё допустимую цену, зоны и цели на остаток. Вердикт аналитика ссылается на эту таблицу и пишет вывод словами: что отстаём, где и реалистично ли догнать.

## 7. Не решено
- Период для доли «заявка → продажа»: решено 6 зрелых недель, как в замере 13.11. Зрелая неделя: с конца прошло не меньше 14 дней, свежие недели не берём. Допустимая цена по доле за всё окно, динамика по неделям для тренда. Если зрелых недель меньше 4 или продаж меньше 10, пишем «данных мало» с интервалом.
- Зоны: решено определять отдельно по каждому показателю, интервал прогноза для зон 1 и 2 берём 80 %. Для зоны 3 в Концепции три вопроса, пороги не откалиброваны.
- Склейка звонка и формы по CRM (на будущее).
