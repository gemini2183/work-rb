# Чекпоинт сессии: разрез на границе этапа

**Зачем.** По замеру 13.11 ([[Оптимизация_агентов]], «Замер 2026-11-13») 72 % веса основных сессий приходится на вызовы с контекстом выше 150 тыс. токенов; новая сессия стартует с ~64 тыс. Чекпоинт позволяет закрыть тяжёлую сессию и продолжить с нуля без потери состояния ([[Устройство_экосистемы]], разделы 3 и 6.8).

## Когда
- Контекст сессии > ~150 тыс. или > ~25 ходов (порог из скелета; модель, не замер) **и** мы на границе этапа: закончена правка, ответ получен, «да» на пункт дан и записан.
- Не посреди записи в кабинет: пункт `applied` без чтения обратно не оставлять. Сначала прочитать обратно, записать в Журнал, потом чекпоинт.
- Я сам называю контекст на границе этапа («контекст ~N тыс., предлагаю чекпоинт»), число беру из `python Скрипты/claude_usage.py --turns --session <id>` или оценкой по числу ходов, если счётчик недоступен (оценку так и называю). Пользователь может потребовать чекпоинт в любой момент.

## Куда писать
- Работа по клиенту с папкой задачи: блок «Чекпоинт» в `Клиенты/<Имя>/Работы/<дата>_<задача>/01_состояние.yaml` (если файла нет - в конец `Хроника_<ГГГГ-ММ>.md` клиента).
- Работа без клиента (оптимизация, инфраструктура): `База_знаний/Агенты/Чекпоинты/<ГГГГ-ММ-ДД>_<тема>.md`.
- Не дублировать то, что уже записано в `Решения.md`, `Журнал_изменений.md`, Задачи: ссылаться на запись.

## Порядок закрытия (решение 2026-11-13: пользователю напоминать не нужно)
1. Всё остальное (Решения, Журнал, `Инфраструктура.md`, Задачи, README, документ оптимизации) записано по ходу, не при закрытии.
2. Чекпоинт пишется последним; после него в этой сессии новых действий нет. Если действие было - чекпоинт обновить.
3. **Сверка перед выдачей промпта:** чекпоинт против реального состояния (что изменено в файлах и настройках, какие решения и «да» дал пользователь, что в «Следующем шаге» уже сделано, что в промпте старта не противоречит чекпоинту). Нашлось расхождение - исправить и сказать об этом.
4. Только потом выдать промпт старта.

## Шаблон (≤ 40 строк; длиннее - значит не чекпоинт, а пересказ)
```
## Чекпоинт ГГГГ-ММ-ДД ЧЧ:ММ | <тема> | контекст ~N тыс., ходов M
Цель: одна строка.
Сделано (факт, с путями): ...
Решено пользователем (дословно, с датой): ...
Моё предложение, не принятое: ...            # отдельно от решений
Открыто / следующий шаг: ровно один первый шаг, затем список.
Читать при старте (≤5 файлов, полные пути): ...
НЕ читать: ... (большие журналы, старые Хроники)
Незавершённое в кабинетах: нет | пункт, статус (applied/verified), как проверить
Проверка состояния: команды чтения (state_digest и т.п.), которые новая сессия запускает первыми
Допущения/что не проверено: ...
```

## Промпт старта новой сессии (короткий, пользователь вставляет в новый чат)
```
Продолжаем: <тема>. Прочитай <полный путь к чекпоинту> и файлы из «Читать при старте». Журналы и Хроники целиком не читай.
Первый шаг: <из чекпоинта>. Перед записью в кабинеты сверь состояние командами из «Проверка состояния».
```
Образец готового промпта: [[Промпт_старта_Motorcycle2]].

## Что нельзя
- Пересказывать в чекпоинт всю сессию; цифры без источника; выдавать моё предложение за решение пользователя.
- Автоматически открывать новую сессию (из сессии это сделать нельзя; автозапуск - фаза 3, раннер).

## Замер эффекта (дата оценки 2026-11-20)
- Скрипт: `Скрипты/usage_startup_share.py`. «До»: `--since 2026-11-06 --until 2026-11-12`. «После»: `--since 2026-11-13` (чекпоинт не заводится задним числом: сессии, начатые до 13.11, в «после» не входят).
- Метрики: **A** доля веса при контексте >150 тыс.; **B** медиана пикового контекста и число сессий с пиком >250 тыс.; **C** вес на сессию и на день работы.
- Базовые значения «до» (43 сессии, 06–12.11, 5 дней работы): A = 72 %; B = медиана 244 тыс., 19 из 43 сессий с пиком >250 тыс.; C = 1 914 тыс. на сессию (медиана), 21,7 млн на день.
- Ожидание: A < 50 %, медиана пика < 180 тыс. Порог успеха: A ≤ 55 % **и** вес на день не вырос. Стоп-правило: если после недели A остаётся >65 % или чекпоинты не используются (<3 за неделю) - пересмотреть триггер или ввести хук.
- Ограничения: объём работы по дням разный (метрика C шумная); вес не равен лимиту подписки; ещё не учтена цена самого чекпоинта (она входит в вес сессий «после», отдельно её не выделяем). Не учтены субагенты.
- Что считать «чекпоинтом» для отчёта о частоте: файл в `Чекпоинты/` или блок «Чекпоинт» с датой; считаем `grep -r "^## Чекпоинт"`.
