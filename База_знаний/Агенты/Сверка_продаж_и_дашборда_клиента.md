# Сверка продаж и дашборда клиента (метод ProfiMet, 2026-10-20)

**Когда применять.** Пользователь говорит «делаем сверку продаж / дашбордов» по клиенту, у которого есть выгрузка CRM с обращениями и заказами и клиентский дашборд, где цена продажи расходится с нашей. Первый кандидат — **EkspertAgro** (что известно — внизу). Результат ProfiMet и все решения по нему — `Клиенты/ProfiMet/Решения.md`, записи 2026-10-19 и 2026-10-20.

**Цель.** Понять, кто «неправильно» считает: мы или клиент. Ответ почти всегда «разные определения», а ошибки находятся в делителе, в метках и в потерянных UTM. Не доказывать правоту, а разложить каждую колонку клиентского дашборда на определение, которое воспроизводится из данных.

## Что запросить заранее (по одному, простыми словами)
1. Выгрузка CRM (Google-таблица): каждое обращение (звонок/форма) строкой, телефон, время, источник, UTM, `gclid`, номер заказа, статус заказа, даты продажи/отмены. Лист «О таблице» с описанием колонок прочитать первым.
2. Скрины клиентского дашборда **с видимым фильтром дат и переключателями**. Без дат период не определять и выводов не делать (см. ловушки).
3. Списки заказов за числами продаж (в дашборде числа продаж кликабельны: Дата, Заказ, Телефон, Товар, Кол-во, UTM, Площадка) — самое ценное для сверки.
4. Что открывает кнопка «Данные по продажам»: та же таблица или другая.
5. Доступы (проверять самому, не спрашивать): сервисный аккаунт `rb-cloud-admin` «Читатель» на таблице; Ringostat (ключ в боевом скрипте клиента); Google Ads; BigQuery (расход Facebook); GA4 (ключ `ga4-analytics`).

## Порядок работы
**1. Выгрузка и доступ.** Одной ссылки «по ссылке» мало: скрипты читают сервисным аккаунтом, Drive-коннектор отдаёт только выборку. Попросить добавить `rb-cloud-admin@redbird-196813.iam.gserviceaccount.com` как «Читатель». Прочитать лист «О таблице».

**2. Полнота и источники выгрузки** (`Скрипты/profimet_season_audit.py`): каждый звонок Ringostat сезона ↔ строка выгрузки (по номеру и времени ±10 мин, соответствие «один к одному», входящие раньше исходящих, поиск по всем листам; маркетплейсы и номера других сайтов отдельно; лаг ночной синхронизации). Источник строки против категории Ringostat; формы: источник против UTM/`gclid`. Что искать: потерянные лиды, перекрашенные каналы.

**3. Правило уникальности.** Прочитать боевой скрипт клиента (`google-cloud-jobs/adwhite/func/ringostat_<клиент>/main.py`), воспроизвести (`prod_unique()`), сверить с контрольными числами из его комментария. Один аккаунт Ringostat может обслуживать несколько сайтов — их различает набранный номер (`dst`).

**4. Метки и подмена номера**, если «Нет метки» велик: `phone_swap_check.py` (строгий, все элементы, `--sitemap`), `gads_landing_swap_check.py` (реальные посадочные из Google Ads), `gads_utm_template_audit.py` (UTM в шаблонах). Доля форм без метки по месяцам; если растёт — искать момент по неделям. Формы без метки сопоставлять с событиями GA4 по минуте: опознаётся реальный источник. Готовый скрипт — `Скрипты/profimet_forms_reconcile.py` (ProfiMet 2026-10-21: GA4 видит ~73% форм CRM; минутный срез GA4 ~60 дней; тестовые номера исключать).

**5. Построить СВОЙ дашборд, клиентский не разбирать, пока не попросят** (`Скрипты/profimet_sources_dashboard.py`): те же колонки, определения под таблицей, два режима (наш и «как у клиента»), Google Таблица с выбором периода. Пользователь сравнивает сам.

**6. Расшифровать клиентский дашборд по колонкам** (когда попросят). Что оказалось у ProfiMet — чек-лист гипотез для другого клиента:
- Цена/клики/показы: проверка по Google Ads API (период подтверждать фильтром, расход помогает как косвенный признак); Facebook — BigQuery `fb_stats_profimet` в долларах, курс подбирается по расходу клиента (0,8244).
- **Звонки:** первый звонок номера за ВСЮ историю (`our_unique` по Ringostat с 2023) против правила 60 дней; сравнить три варианта (`unique_call`, вся история, лестница 60 дн).
- **Конверсии:** звонки + формы из GA4 (сеансы `form_submit`, источник по `sessionSourceMedium`: `google / cpc` → Google, `facebook*` → Facebook, остальное → «Нет метки»). Телефонов в GA4 нет → дедупликации форм с звонками нет.
- **Продажи:** единицы товара, не заказы; источник — метка заказа в CRM (форма по UTM, заказ менеджера → «Телефон»); отбор заказов — проверять по спискам.
- Время в списках клиента — UTC; номер заказа с буквами = первые 8 символов нашего длинного.

**7. Сверка на уровне заказов.** Клиентский список ↔ наши проданные заказы: сначала по номеру заказа (префикс), затем по телефону и дате. Найти правило отбора: какие наши заказы клиент не считает (у ProfiMet — первая строка «Телефон»). Вкладка «Заказы» в Google Таблице (`profimet_orders_list.py`) с признаками.

**8. Проверка, что значит каждая метка:** «Телефон» (входящий на номер без метки? перезвон после исходящего менеджера?), «Нет метки» (звонки на номер сайта + формы без UTM), рекламный след у телефона (звонок/форма Google/Facebook раньше), состав клиентского «Телефон» по кампаниям.

**9. Итог для пользователя.** Три способа считать продажи по рекламе (все заказы; правило клиента; заказы с рекламным следом; первое обращение рекламное) с ценой продажи по каждому, ошибки обеих сторон, что остаётся неизвестным, решение за пользователем (делитель). Задачи — в `Задачи.md`, выводы — в `Решения.md`.

## Ловушки (все встретились на ProfiMet)
- Даты на скрине клиента не домысливать; период по расходу — только как гипотеза.
- Не путать **заказ**, **единицу товара** («продажи» у клиента) и **обращение**; называть точно.
- Пользователь просил «сделать наш дашборд, чтобы сравнить» — клиентский не разбирать без просьбы.
- Один аккаунт Ringostat на несколько сайтов; пустые UTM в журнале — звонки другого сайта.
- Соответствие звонок→строка «один к одному»; иначе исходящий «прилипает» к строке входящего.
- Регулярка номеров под страну (польские 11 цифр), сравнение по последним 9 цифрам.
- Правило привязки заказа к звонку в CRM (3 часа) — смотреть в «О таблице».
- BigQuery: скоуп `…/auth/bigquery`, не readonly; Google Таблица: локаль ru_RU, даты числами, JSON без NaN, очищать лист только после проверки данных.
- Выпадающие списки при конвертации xlsx в Google Таблицу теряются — ставить `batchUpdate`.
- Объяснять просто, одним примером, без жаргона; пользователь резко реагирует на «стены» и непонятные слова.

## Дополнение 2026-10-23 (ProfiMet): что добавилось в метод

- Рекламное касание искать по телефону в выгрузке CRM, Ringostat (входящие и исходящие, с начала истории) и Google Analytics (форма с платным кликом), и до заказа, и после; ответ формулировать как «в наших данных нет», не «не из рекламы».
- Отчёт для начальника: нет внутренних заметок и планов, каждое слово определено там, где впервые встречается, без «выше/ниже»; предложения собраны разделом «Что предлагаем»; дашборд отдаётся одним HTML-файлом (CSV построчной сверки не нужен).
