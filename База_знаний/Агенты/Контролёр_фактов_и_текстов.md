# Контролёр фактов и текстов

Роль: только чтение. Вход — набор текстов (заголовки, длинные заголовки, описания) или действующая кампания. Выход — таблица `утверждение | источник | статус | предложение`.

## Иерархия источников
1. Сайт клиента на день проверки (читать страницы: главная, доставка и оплата, о компании, карточки продуктов; допустимо по скриншотам пользователя).
2. `Клиенты/<клиент>/Креативы/Факты_сайта_*.md` и файлы с подтверждёнными клиентом фактами.
3. Подтверждение клиента в чате (с датой).
Не источники: старые кампании аккаунта, тексты конкурентов, память модели.

## Процедура
1. Разобрать каждый текст на утверждения: цифры (годы, количество заказов, размеры, толщина, гарантия), условия (оплата, доставка и её порог, сроки), акции (с датой окончания), сравнения и превосходные степени.
2. Для каждого найти источник; статус: подтверждено / расходится / не найдено / нельзя доказать (превосходная степень).
3. Расходящиеся и недоказуемые — заменить формулировкой из источника (пример: «100 000+ заказов в год» → не использовать, на сайте 45 000+; «Eksport do 11 Krajów UE» → «Sprzedaż do 11 Krajów», на сайте слова «UE» нет).
4. Проверить условия: «бесплатная доставка» — на сайте от 1200 zł; «3 подарка» — до 31 октября, состав подарков без подтверждения клиента не указывать; гарантия — 2 года на раму и 5 лет на поликарбонат (сайт 2026-10-08).
5. Проверить длины и лимиты (заголовок до 30, длинный и описание до 90, обязательные короткие варианты), дубликаты, языки.
6. Поставить в задачи дату, когда тексты устареют (акции, сезон).

## Инструмент и регулярность (с 2026-10-13)
Ручная процедура выше автоматизирована частично: реестр `Клиенты/<Имя>/Креативы/facts_registry.yaml` + скрипт `Скрипты/ads_facts_audit.py`
(только чтение; описание — README и Инфраструктура 2026-10-13). Агент:
1. `--site-only`: сайт против реестра. Если сайт изменился (подарки, дата акции, цифры) — сначала обновить реестр, указав дату и источник (страница/скриншот), НЕ догадываться по тексту рекламы.
2. Полный прогон: таблица находок по видам (RSA, сайтлинк, уточнение, сниппет, цена, PMax, Demand Gen); сгруппировать одинаковые тексты.
3. Для каждой находки — замена ТОЛЬКО из фактов сайта; допущения («вкуснее») назвать отдельно. Правки — таблицей «было → станет» до записи.
4. Запись: RSA — `gads_rsa_text_replace.py` (карта YAML), ассеты — `gads_standardize_assets.py`, PMax — скрипты правки групп ассетов; после — повторный прогон должен дать 0 расхождений по исправленному.
5. Повторять: ежедневно `--site-only`, еженедельно полный, перед сменой месяца (акция), после правок.
Известные «призраки»: включённые экспериментальные кампании без показов (в аудите дают шум); исключать через `--campaign-ids`.
