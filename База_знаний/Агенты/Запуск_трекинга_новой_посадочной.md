## Порядок
**1. Снять страницу (чтение).** `page_tracking_check.py` с `--click` по квизу (повторить селектор варианта ответа 5 раз) и `--faq`. Читать отчёт: что на странице сильно отличается от макета (живая важнее файлов исполнителя), какие события страница пушит сама, есть ли «мёртвые» якоря, окна форм и ссылки на них, поля форм (имена, скрытые поля квиза), подмена номера «до» (ожидаем 0 из N). Сохранить отчёт в `Статистика/` клиента.

**2. Доступы — самому.** GTM: `gtm_read_container.py --list-accounts/--list-containers`, id контейнера со страницы (`GTM-…`); GA4: ресурс по `G-…` (`accountSummaries`); Ringostat: список проектов `https://app.ringostat.com/project/projects` (ссылка «К проекту» → `project_id`), правила — `…/script_settings/xpaths?project_id=<id>`; Google Ads: customer id в вики клиента. Что-то из этого недоступно — сказать пользователю, что именно и какую роль выдать.

**3. Цели (чтение).** Какие конверсионные действия основные (форма: тег на сайте и импорт из GA4 — риск двойного счёта), что включено у кампании. Реальная отправка формы — только пользователь, своим номером; потом GA4 Realtime (минуты) и Google Ads (часы–сутки). Тестовые заявки не отправлять самому: уходят клиенту.

**4. GTM.** spec страницы → `gtm_landing_plan.py` → `gtm_apply_plan.py` (проверка, `--execute`) → `gtm_test_version.py` (десктоп+мобильный; квиз через `--click`; окно формы — `--eval` с созданием и кликом ссылки на хук; `--push-event submit_form<id>`) → регрессия на старой странице (если контейнер общий) → «опубликуй» → `gtm_publish_version.py --execute` → прогон на живом контейнере `page_tracking_check.py` (подождать несколько минут: `gtm.js` у Google кэшируется) → запись в `Журнал_изменений.md` (И-номер, «до», проверка, откат, «Для отчёта клиенту (EN)»).
События страницы без триггера (часто!), блоки с id вместо старых, место клика из атрибута кнопки, окно формы, FAQ, прокрутка 25/50/75, `form_submit` с местом формы и итогом квиза — см. [[../Инструменты/Tilda-формы-окно-и-события-для-GTM]].

**5. GA4.** `ga4_custom_definitions.py` по списку параметров, который печатает `gtm_landing_plan.py`.

**6. Ringostat.** Пул-файл страницы (+ канал ИИ, если есть), `phone_swap_check.py` — «до». `ringostat_xpath_plan.py` → таблица плана → «да» → ввод в кабинет через Chrome (расширение; вход уже выполнен): открыть `…/script_settings/xpaths?project_id=…`, в консоли страницы выполнить JS из отчёта (форма «Добавить XPath»: `data[Xpath][type]=manual`, `text`, `name`, `mask`, `geo_group=1` = All), нажать «Применить настройки» (зелёная кнопка справа сверху, появится «Действие выполнено успешно»). Результат из JS-консоли с масками блокируется фильтром вывода (`[BLOCKED: Cookie/query string data]`) — проверять скриншотом таблицы или счётом строк. Потом `phone_swap_check.py` до «ОК» во всех случаях и просмотр результата Playwright (`href` и текст из пула, вёрстка кнопок цела, нет вложенных `<a>`).
Динамические кнопки (результат квиза): не подменяются — патч кода страницы: взять номер из уже подменённой кнопки первого экрана (текст патча — `Клиенты/Andverpersonalinjury/Коллтрекинг/Правила_подмены_car_accident_lawyer_tilda.md`).

**7. ТЗ исполнителю страницы (по одному пункту, «найти → заменить на»)** — простым языком, без стрелок и ярлыков; формат: где (блок Tilda, номер блока), что найти (уникальная строка кода), на что заменить, как проверить. Типовое: кнопка на пустой якорь/хук окна, код кнопки звонка квиза, одинаковые имена полей форм, `lang`.

**8. Подключить рекламу.** Решение пользователя после готовности страницы (кнопки, подмена, форма). Предпочтительно менять адрес в объявлениях текущих групп, а не заводить новые (адрес только в объявлениях; новые группы = дубли ключей и потеря истории; при 4 кликах в день параллельный тест невозможен). Таблица плана (объявление → было → станет, ставки → было → станет), допущения, стоп-правило в деньгах, чистые дни для оценки → «да» → `gads_ad_final_url.py --execute`, ставки → чтение обратно → журнал (две записи), реестр экспериментов (`Эксперименты.md`: гипотеза, основание, альтернативы, база «до», ожидание, стоп, дата оценки), задачи. Совместное изменение «адрес + ставки в один день» допустимо по решению пользователя, но оценку вклада по отдельности не получить; совет — ставки через 2–3 чистых дня. Объявления после смены адреса уходят на повторную проверку Google (часы).

## Ловушки (из сессии 24–26.10)
- Живая страница ≠ наши макеты (исполнитель переверстал): классы, формы, id. Всё сверять по живой.
- Форма-окно Tilda открывается только по ссылке на её хук; якорь на пустой `<span>` не открывает. Проверка «есть ли элемент с таким id» этого не ловит — отчёт `page_tracking_check.py` показывает «якорь высотой 0 → ближайшая форма ниже».
- Событие отправки Tilda = `submit_<id формы>`; триггер — regex `submit_form*`.
- Подмена Ringostat запоминается внутри одного браузерного профиля: сравнение «с метками / без» — в разных контекстах.
- Режим «каждая ссылка tel: на отдельной загрузке» в `gtm_test_version.py` не показал событий, хотя клики внутри одной загрузки проходили: использовать `--click` и `--no-tel-places`.
- Тестовые среды GTM `claude-test-*` остаются после обрыва процесса; перед новым запуском удалить (ошибка «Found entity with duplicate name»).
- Новая версия GTM: `gtm.js` из кэша Google первые минуты; не делать вывод о сбое сразу.
- GA4: название измерения без скобок. События с задержкой (mailto) — ждать 5 с.
- Мобильная страница: нижняя плашка скрыта на десктопе, шапочный номер скрыт на мобильном — проверять оба режима.
- Нельзя считать «чистым» день правки (посреди дня); оценку по чистым дням (`window_check.py`).
- `gads_set_conversion_attribution.py` без `--execute` всё равно пишет файл снимка в Статистика/ — не запускать «для чтения».
