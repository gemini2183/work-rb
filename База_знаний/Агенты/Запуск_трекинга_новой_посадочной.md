# Запуск трекинга новой посадочной страницы

Триггер: «страницу собрали и опубликовали, проверь и настрой трекинг». Протокол — [[Протокол_подготовка_и_реализация]]: чтение и черновики без согласования, запись в боевое — по «да»/«опубликуй» пользователя (здесь пользователь заранее просил опубликовать через GTM).

## 0. Прочитать наше, не изобретать
`Клиенты/<Имя>/Трекинг/` (прежние планы GTM), `Коллтрекинг/` (пулы и правила), [[../Инструменты/Tilda-формы-окно-и-события-для-GTM]], [[../Инструменты/Ringostat-механизм-подмены-номера]]. **Живая страница важнее наших макетов:** её собирает исполнитель, разметка расходится с файлами (Landver 24.10: другие классы, другая форма B).

## 1. Снять живую страницу (Playwright, только чтение; GA4/пиксели перехватывать)
Скрипты-образцы лежат в черновиках сессии; повторяется — оформить как `page_tracking_check.py` (задача в `Клиенты/Andverpersonalinjury/Задачи.md`).
- GTM грузится (id контейнера), Ringostat-скрипт, пиксели, Clarity; ссылки `tel:` (текст, класс, видимость, `data-…`), формы (id, имена полей, скрытые поля квиза), блоки по `id`, inline-скрипты с `dataLayer.push` (какие события страница уже отдаёт), canonical/robots/description/lang.
- Каждый CTA: куда ведёт, открывает ли то, что обещает (якорь на форму-окно, пустые якоря).
- Мобильный и десктоп; метки google/cpc и канал ИИ.

## 2. Что уже есть в контейнере
`gtm_read_container.py --summary`, `--find <событие>`. Сопоставить: какие события страница пушит, а триггеров нет; какие селекторы блоков/классов принадлежат старой странице.

## 3. План GTM (JSON) → проверка → черновик → тест в среде → публикация
- Новые теги/триггеры/переменные + правка существующих (`update_tags`, `update_variables`, `update_triggers`) в `Клиенты/<Имя>/Трекинг/gtm_plan_<дата>.json`; старая страница должна продолжать работать (объединять списки блоков, не заменять).
- `gtm_apply_plan.py --plan …` (проверка) → `--execute` (черновик, живая версия прежняя) → `gtm_test_version.py … --click … --eval …` (десктоп+мобильный, GA4 перехватывается) → регрессия на старой странице → `gtm_publish_version.py … --execute` → прогон на живом контейнере (подождать несколько минут из-за кэша `gtm.js`).
- Минимум событий для страницы с квизом: шаги квиза, итог, клики по CTA и по номерам с местом, прокрутка 25/50/75, видимость блоков, время на блоках, вопросы FAQ, открытие окна формы, начало заполнения формы, `form_submit` с местом формы и итогом квиза.

## 4. GA4
`ga4_custom_definitions.py --property <ID> --dim <параметр> "<Название>" …` (название — буквы, цифры, подчёркивание, пробел; без скобок). Без регистрации параметры в отчётах не видны. Читать — `ga4_behavior.py`.

## 5. Подмена номера
- Пул-файл на новый адрес (`Коллтрекинг/Пул_номеров_<…>.yaml`), `phone_swap_check.py` — базовая строка «до».
- Правила Ringostat: по устойчивому признаку ссылки (у Landver — `data-ldv-cta`), XPath проверить на живой странице (число совпадений = ожидаемому, вместе покрывают все `tel:`), маски по раскладке внутренностей, ГЕО группа All; кнопка без номера в тексте — скрытый `<span>` с `+###########`. Динамические кнопки (квиз) — через код страницы: взять номер из уже подменённой кнопки. Внесение в кабинет — браузером после «да»; затем строгая проверка до OK.

## 6. Цели
Какие действия Google Ads основные и какие включены у кампании (`customer_conversion_goal`, `campaign_conversion_goal`), нет ли двух основных действий на одну форму (WEBPAGE и импорт GA4). Реальная отправка формы — только пользователь, своим номером; потом GA4 Realtime и Ads.
