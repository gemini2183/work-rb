## Порядок
**1. Снять страницу (чтение).** `page_tracking_check.py` с `--click` по квизу (повторить селектор варианта ответа 5 раз) и `--faq`. Читать отчёт: что на странице сильно отличается от макета (живая важнее файлов исполнителя), какие события страница пушит сама, есть ли «мёртвые» якоря, окна форм и ссылки на них, поля форм (имена, скрытые поля квиза), подмена номера «до» (ожидаем 0 из N). Сохранить отчёт в `Статистика/` клиента.

**2. Доступы — самому.** GTM: `gtm_read_container.py --list-accounts/--list-containers`, id контейнера со страницы (`GTM-…`); GA4: ресурс по `G-…` (`accountSummaries`); Ringostat: список проектов `https://app.ringostat.com/project/projects` (ссылка «К проекту» → `project_id`), правила — `…/script_settings/xpaths?project_id=<id>`; Google Ads: customer id в вики клиента. Что-то из этого недоступно — сказать пользователю, что именно и какую роль выдать.

**3. Цели (чтение).** Какие конверсионные действия основные (форма: тег на сайте и импорт из GA4 — риск двойного счёта), что включено у кампании. Реальная отправка формы — только пользователь, своим номером; потом GA4 Realtime (минуты) и Google Ads (часы–сутки). Тестовые заявки не отправлять самому: уходят клиенту.

**4. GTM.** spec страницы (**контейнер общий для всех страниц клиента: все теги и триггеры работают на каждой странице, условий по адресу нет. Старые объекты НЕ править** (решение пользователя 26.10): под новую страницу — новые объекты с суффиксом « [<страница>]» и условием «Page Path содержит <адрес>»; образец — `Клиенты/Andverpersonalinjury/Трекинг/build_gtm_plan_settlement_isolated.py`; `gtm_landing_plan.py` (он перезаписывает старые объекты) для общего контейнера не использовать. Перед публикацией сравнить версию с живой: «изменённых старых объектов 0», и числа событий на старых страницах равны живой версии; что без правки старого невозможно — вынести пользователю как отдельный вопрос «один блокирующий триггер на один тег») → `gtm_landing_plan.py` → `gtm_apply_plan.py` (проверка, `--execute`) → `gtm_test_version.py` (десктоп+мобильный; квиз через `--click`; окно формы — `--eval` с созданием и кликом ссылки на хук; `--push-event submit_form<id>`) → регрессия на старой странице (если контейнер общий) → «опубликуй» → `gtm_publish_version.py --execute` → прогон на живом контейнере `page_tracking_check.py` (подождать несколько минут: `gtm.js` у Google кэшируется) → запись в `Журнал_изменений.md` (И-номер, «до», проверка, откат, «Для отчёта клиенту (EN)»).
События страницы без триггера (часто!), блоки с id вместо старых, место клика из атрибута кнопки, окно формы, FAQ, прокрутка 25/50/75, `form_submit` с местом формы и итогом квиза — см. [[../Инструменты/Tilda-формы-окно-и-события-для-GTM]].

**5. GA4.** `ga4_custom_definitions.py` по списку параметров, который печатает `gtm_landing_plan.py`.

**6. Ringostat.** Пул-файл страницы (+ канал ИИ, если есть), `phone_swap_check.py` — «до». `ringostat_xpath_plan.py` → таблица плана → «да» → ввод в кабинет через Chrome (расширение; вход уже выполнен): открыть `…/script_settings/xpaths?project_id=…`, в консоли страницы выполнить JS из отчёта (форма «Добавить XPath»: `data[Xpath][type]=manual`, `text`, `name`, `mask`, `geo_group=1` = All), нажать «Применить настройки» (зелёная кнопка справа сверху, появится «Действие выполнено успешно»). Динамические кнопки (результат квиза): не подменяются — патч кода страницы: взять номер из уже подменённой кнопки первого экрана (текст патча — `Клиенты/Andverpersonalinjury/Коллтрекинг/Правила_подмены_car_accident_lawyer_tilda.md`).

Типовое: кнопка на пустой якорь/хук окна, код кнопки звонка квиза, одинаковые имена полей форм, `lang`.

**8. Подключить рекламу.** Решение пользователя после готовности страницы (кнопки, подмена, форма). Предпочтительно менять адрес в объявлениях текущих групп, а не заводить новые (адрес только в объявлениях; новые группы = дубли ключей и потеря истории; при 4 кликах в день параллельный тест невозможен). Таблица плана (объявление → было → станет, ставки → было → станет), допущения, стоп-правило в деньгах, чистые дни для оценки → «да» → `gads_ad_final_url.py --execute`, ставки → чтение обратно → журнал (две записи), реестр экспериментов (`Эксперименты.md`: гипотеза, основание, альтернативы, база «до», ожидание, стоп, дата оценки), задачи. ## Ловушки (из сессии 24–26.10)
- Живая страница ≠ наши макеты (исполнитель переверстал): классы, формы, id. Всё сверять по живой.
- Форма-окно Tilda открывается только по ссылке на её хук; якорь на пустой `<span>` не открывает. Проверка «есть ли элемент с таким id» этого не ловит — отчёт `page_tracking_check.py` показывает «якорь высотой 0 → ближайшая форма ниже».
- Событие отправки Tilda = `submit_<id формы>`; триггер — regex `submit_form*`.
- Подмена Ringostat запоминается внутри одного браузерного профиля: сравнение «с метками / без» — в разных контекстах.
- Режим «каждая ссылка tel: на отдельной загрузке» в `gtm_test_version.py` не показал событий, хотя клики внутри одной загрузки проходили: использовать `--click` и `--no-tel-places`.
- Тестовые среды GTM `claude-test-*` остаются после обрыва процесса; перед новым запуском удалить (ошибка «Found entity with duplicate name»).
- Новая версия GTM: `gtm.js` из кэша Google первые минуты; не делать вывод о сбое сразу.
- GA4: название измерения без скобок. События с задержкой (mailto) — ждать 5 с.
- Мобильная страница: нижняя плашка скрыта на десктопе, шапочный номер скрыт на мобильном — проверять оба режима.
- Нельзя считать «чистым» день правки (посреди дня); оценку по чистым дням (`window_check.py`).
- `gads_set_conversion_attribution.py` без `--execute` всё равно пишет файл снимка в Статистика/ — не запускать «для чтения».

- Страница целиком в одном блоке Tilda (тип 1370, `rec…`): ТЗ указывает этот id; классы квиза и FAQ свои (`vb-q7k__opt`, `#ldv-faq summary`) — селекторы брать из живого HTML, не из макета. Повторяющийся `id` (пустой якорь + секция): в GTM селектор `.класс#id`, `getElementById` берёт первый (пустой).
- Текстовая ссылка внутри предложения («Prefer to talk? Call <a>…») получает маску кнопки правила Ringostat: на экране «Call Call (888)…». После внесения правил смотреть скриншоты ВСЕХ мест номера с метками Google (десктоп и мобильный), не только `href`. Лечится правкой слова на странице, а не общего правила: оно живёт и на другой странице.
- Кнопка звонка, созданная скриптом страницы после загрузки (результат квиза): телефон зашит константой в код блока → патч «взять `href` у подменённой кнопки первого экрана»; проверять подменой HTML на лету (`page.route` + `fulfill`) ДО ТЗ исполнителю — патч проверяется без правки живой страницы.
- Перед подключением группы к странице: `gads_group_negatives_overlap.py` — минусы кампании могут закрывать семейство запросов группы (Settlement: 54% показов и 6 из 8 кликов), тест без трафика невозможен. И сверить стоп-правило прежнего теста группы в `Эксперименты.md`: оно могло быть уже превышено (Э-01: $325,60 из $300).
- Цели Ads: форм-цель типа WEBPAGE без тега с её `send_to` в контейнере и без `AW-` на странице, по всей видимости, не срабатывает (двойного счёта нет, конверсия приходит только импортом события GA4); колонка «Конверсии» может не включать форм-цели, хотя они «основные» — проверять `gads_conversion_goals_audit.py` и тестовой заявкой пользователя, не по названию.
- Новая рабочая область GTM строится от ПОСЛЕДНЕЙ версии, не от живой: черновик, который не нужен, мешает следующему (версия 10 унаследовала правки версии 9 — дубли событий). Лечение: удалить черновик (`DELETE versions/<id>`; «последнюю» удалить нельзя) и `versions/<живая>:set_latest`, потом пересобрать план. Всегда сравнивать версию с живой по объектам.
- Место кнопки звонка, созданной скриптом страницы: атрибут `data-ldv-cta` в коде кнопки (страница сама пушит `ldv_cta`, место в GA4 берётся из атрибута) — без правок GTM; патч вместе с подменой номера, одним пунктом ТЗ.
- `gtm_test_version.py`: если клик по ссылке `tel:` — ПОСЛЕДНИЙ шаг сценария, событие `click_tel` не успевает попасть в отчёт (ложное «событие не пришло»; на Car и Settlement подтверждено 26.10). Ставить после него любой безвредный шаг (`--click` по FAQ и `--eval "1"`).
- Две формы Tilda в потоке: `submit_formA` / `submit_formB` (по `id` формы), триггер `submit_form*` ловит оба; `form_place_events` в spec даёт `inline_a` / `inline_b`.

- Виджет третьей стороны (Envybox и подобные), пришедший на сайт без нас: сначала прочитать, что он пушит в `dataLayer` сам (код `boot.min.js` по ссылке из `cbk.js` → `whitesaas.com/api?action=load` → `widgetUrl`; искать `dataLayer.push`, `sendGoal`), и подтвердить событием на живой странице (Playwright, клик по кнопке, без отправки номера). Проверить, есть ли глобальные `gtag`/`ga`: если нет, прямые вызовы виджета в GA4 мертвы и нужен триггер GTM по имени события. Получатели заявок — только в кабинете сервиса: просить у пользователя, не гадать. Пример — Landver 27.10 (`Клиенты/Andverpersonalinjury/Трекинг/build_gtm_plan_envybox.py`).

- Тег пользовательского шаблона (OpenAI Pixel `cvt_NS4HN`) в плане: параметры `enableDebug` и `sendEvent` — тип `boolean`, не `template`; иначе GTM молча выбросит `eventName` (тег создаётся, но событие не уходит). Копировать структуру существующего тега целиком (`setupTag` Init, `tagFiringOption`), читать сырой JSON тега через API, а не сводку. Проверять живой контейнер сравнением с рабочим тегом на `submit_form` (запросы `bzr.openai.com/v1/sdk/events`); `gtm_test_version.py` пиксель не показывает. Исправление готового тега — `update_tags` с `set_parameters`/`set_fields`.
