# П-034: нет скрипта замера конверсии «заявка → продажа» по неделям с учётом срока созревания

**Тип:** пробел в скриптах (выгрузка продаж CRM), найден 13.11.2026 при замере для сторожа `yt_cold` (ProfiMet YouTube, id 24468615055).

**Симптом.** Замер конверсии заявка→продажа (6 созревших недель, порог созревания 14 дней, срез Google Ads отдельно) сделан разовым кодом агента поверх готовых функций `profimet_sales_vs_ringostat.load_sheet` и `profimet_sources_dashboard.contacts_with_new_flag`. Код лежал в scratchpad сессии, в `Скрипты/` не сохранён, существующие скрипты не менялись.

**Что известно.** Результат и таблица по неделям: `Клиенты\ProfiMet_YouTube\Работы\2026-11-13_конверсия_заявка_продажа\вердикт.md` (Google 50%, 207 заявок, 104 продажи, заявки 14.09–25.10). Определения там же: заявка = звонок или форма по лестнице 60 дней; продажа привязана к заявке по дате первого обращения; срок заявка→продажа: медиана 0 дней, 90-й процентиль 2 дня (звонки Google - 8).

**Что НЕ установлено.** Нужен ли замер регулярно (пока разовый). Воспроизводится ли разовый код без scratchpad (не проверено). Как считать по `yt_cold` (заявок с `yt_` 4, продаж 1 - выборка мала).

**Обход.** Использовать вердикт 13.11 как есть. Пересчёт по собственным данным `yt_cold` после 8–10 заявок без скрипта не делается.

**Решение.** Не принято. Задача для `script-builder` заведена в `Клиенты\ProfiMet_YouTube\Задачи.md` (срок 18.11, тема инструменты).

**Как проверить.** Скрипт без записи (только чтение CRM) воспроизводит 207 заявок, 104 продажи, 50,2% за 14.09–25.10 из таблицы вердикта; срез Google Ads выводится отдельной строкой; для `yt_cold` - отдельной строкой.

**Связано:** вердикт 13.11; П-031 (другой пробел: нет скрипта чтения Demand Gen на паузе).
