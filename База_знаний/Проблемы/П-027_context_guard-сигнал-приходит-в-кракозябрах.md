# П-027: сигнал хука `context_guard` приходит в модель нечитаемым (кодировка)

**Симптом (дословно, 13.11, первая сессия, где сработал порог):** `[context_guard] �������� ������ ~163 ���. �������, ����� ������� 150 ���. ...` — вместо кириллицы символы замены. Число «163» и путь `База_знаний/Агенты/Чекпоинты/...` угадываются только по цифрам/латинице; сам текст инструкции не читается.

**Установлено:** хук вызывается харнесом и отдаёт `additionalContext` (это первое наблюдение сигнала из харнеса, порог 150 тыс. превышен на ~160 тыс.). Текст доходит повреждённым.

**Вероятная причина (не проверена):** `Скрипты/context_guard.py` печатает `json.dumps(..., ensure_ascii=False)` в stdout; на Windows `sys.stdout` кодируется в кодовой странице консоли (cp1251/cp866), а харнес читает UTF-8.

**Не установлено:** повторится ли при `PYTHONUTF8=1` в команде хука; как харнес декодирует вывод.

**Обход:** сигнал сам по себе доходит (число читается); порог и действие записаны в `Чекпоинт_сессии.md`.

**Решение (предложение, не выполнено, по «да»):** `ensure_ascii=True` в `print(json.dumps(...))` (вывод станет чистым ASCII с `\uXXXX`, кодировка stdout не важна) либо `sys.stdout.reconfigure(encoding="utf-8")`. Проверка: `echo {"transcript_path":"<jsonl>","session_id":"x"} | python Скрипты/context_guard.py --threshold 1 | python -c "import sys,json;print(json.load(sys.stdin))"` и затем сигнал в новой сессии на ≥150 тыс.
