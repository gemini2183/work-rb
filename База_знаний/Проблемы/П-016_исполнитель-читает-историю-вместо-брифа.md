# П-016. Агент-исполнитель читает 13 источников и историю вместо готового брифа: контекст 55 → 224 тыс. токенов до начала работы

**Система:** агенты-исполнители (пилот «супервайзер + исполнители», Landver, испанская кампания, исполнитель 3 «Google Ads», 11.11).

**Симптом (журнал `~/.claude/projects/d--GitHub-work-rb/33277b70-…/subagents/agent-a0d92cb937dd4627c.jsonl`):** 84 вызова инструментов (72 Bash), 243 тыс. знаков ответов, контекст 55 → 224 тыс. токенов к моменту первого отчёта; вес агента ≈ 2,65 млн (скрипт `Скрипты/claude_usage.py`, допущения весов — в его шапке). Около 80 тыс. токенов ушло на чтение Хроники, Решений и образца-скрипта на 450 строк, 13 тыс. — на написание почти копии этого скрипта заново.

**Причина (установлена):** в задании исполнителю стоял список «ЧИТАТЬ» из 13 пунктов (Хроника по 6 записям, Решения, 2 чужих скрипта, методички). Список составил супервайзер, потому что решения по структуре кампании лежали россыпью в Хронике и Решениях и не было брифа с готовыми данными. Из 13 пунктов для сборки нужны 4–5 (Паспорт, тексты страницы, семантика, Excel-эталон настроек, один образец RSA/ссылок). Решение пользователя 11.11: найдена причина — исправлять сразу.

**Что НЕ установлено:** точная доля стоимости на подготовку и на исполнение (оценка по размерам контекста, не замер); протух ли кэш при простое 18 минут перед возвратом 1 (`--returns` в `claude_usage.py` ещё не делит реплики); видят ли агенты индекс памяти MEMORY.md.

**Что сделано (11.11):**
1. Черновик шаблона `База_знаний/Агенты/Шаблон_брифа_исполнителю.md` (не проверен на практике).
2. Исправление назначено на отдельную сессию 2026-11-12 (задача в корневых `Задачи.md`, тема инфраструктура), в текущей сессии разбора токенов не делается.

**План исправления (сессия 12.11, вход: эта запись + шаблон брифа + `Супервайзер_и_исполнители.md`):** (а) правило в `Супервайзер_и_исполнители.md`: решение пользователя записывается в бриф, задание исполнителю = бриф + контракт, без списка «прочитай всё», режим Manual до запуска записывающего исполнителя; (б) универсальный `Скрипты/gads_campaign_builder.py --plan plan.yaml` вместо скрипта, пишущегося агентом заново; (в) файлы агентов `.claude/agents/` (планировщик без записи, дешёвая модель для вики-записи); (г) бриф для Landver Pedestrian+Bicycle как первый прогон. Статус `обходится`, пока не сделано (а) и (б).

**Решение пользователя 2026-11-11:** схема согласована для пробы: планировщик по брифу пишет план в файл и заканчивает; запись в кабинет — скриптом в сессии супервайзера в Manual по «да»; рутина вики — короткий агент на дешёвой модели или скрипт; мелкие правки плана — правкой файла в супервайзер-сессии, крупные — новый короткий агент (не возврат старого). Планировщик пишет в план не только «что», но и «почему» по каждому решению. Настроено пока ничего не было.

**Сделано 2026-11-11 (после решения пользователя «второй план»):** протокол обмена [[Рабочая_папка_задачи]] (папка задачи, номерные файлы, кто что читает и пишет); файлы агентов `.claude/agents/campaign-scout.md`, `campaign-planner.md` (sonnet), `wiki-recorder.md` (haiku); бриф и постановка для Landver Ped+Bike в `Клиенты/Andverpersonalinjury/Работы/2026-11-11_Ped_Bike/`. Для правок существующих кампаний универсальный сборщик не нужен (достаточно готовых скриптов); `gads_campaign_from_plan.py` — только для новых кампаний, не начат. Сразу после создания файлов вызов `campaign-scout` дал `Agent type … not found`, но через несколько минут все три агента появились в списке доступных в той же сессии (перезапуск не понадобился); первая разведка пошла через `general-purpose` с инструкцией из файла. Не проверено: укладываются ли агенты в контекст <100 тыс. токенов.
