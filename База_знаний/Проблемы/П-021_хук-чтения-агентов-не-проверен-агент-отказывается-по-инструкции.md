# П-021. Хук `agent_read_guard.py` не проверен: status-reader отказывается читать запретный файл по инструкции, до вызова инструмента

**Система:** агенты `.claude/agents/status-reader.md` (frontmatter-хук PreToolUse `Read|Bash`), `Скрипты/agent_read_guard.py`; тест Motorcycle 2, шаг 0, 2026-11-11.

**Симптом:** две попытки (вторая с прямой просьбой «вызови Read, это проверка блокировки») — агент ответил, что файл `Инфраструктура.md` в его разделе «не читать», и инструмент Read не вызвал (по 1 вызову инструментов на агента, отказ без обращения к файлу). Файла `Скрипты/logs/agent_read_guard.csv` после обеих попыток нет.

**Что установлено:** манифест чтения как инструкция работает (агент послушался дважды). Хук в этих прогонах не сработал: у хука не было шанса, потому что Read не вызывался.

**Что НЕ установлено:** грузит ли харнес хуки из frontmatter агента и срабатывают ли они на Read/Bash агента; будет ли блокировка, если запретный файл понадобится агенту «по делу».

**Обход:** считать запрет инструкцией, не техническим барьером; смотреть по логам агентов (`claude_usage.py`), что запретное не открывалось.

**Как проверить:** агент без запрета в тексте промпта, но с тем же хуком (тестовый файл агента с `--deny` на безобидный файл), либо вызов хука вручную с JSON-входом PreToolUse; либо перенос хука в `.claude/settings.json` с условием по агенту (не проверено).

## Проверка вручную 2026-11-12
`agent_read_guard.py` вызван вручную с JSON входа PreToolUse: запретный путь (`Хроника_2026-11.md`, агент gtm-checker) → код 2 и сообщение причины, разрешённый (`Паспорт.md`) → код 0. Скрипт работает. **Не проверено:** вызывает ли харнес этот хук для субагента на самом деле. Проверка — агент с заданием «прочитай запретный файл» (маленький, haiku) и запись в `Скрипты/logs/agent_read_guard.csv`; вынесено в новую сессию (задача в корневых `Задачи.md`).

## Решение 2026-11-12 (проверено харнесом на субагенте gtm-checker, haiku)
**Что установлено (3 прогона агента «прочитай запретный файл»):**
1. Хук из frontmatter агента (`hooks: PreToolUse` в `.claude/agents/*.md`) в этой среде (VS Code, Windows) НЕ срабатывает: Read `Хроника_2026-11.md` вернул содержимое, лога блокировки нет. Дважды: с командой `PYTHONUTF8=1 python …` и без префикса (префикс `VAR=1 cmd` не работает в cmd/PowerShell, но причина провала не в нём: хук не вызывался).
2. Хук в `.claude/settings.local.json` (секция `hooks.PreToolUse`) вызывается и для субагентов. В JSON входа есть `agent_id` и `agent_type` (диагностическая запись входа, прогон агента Read `Паспорт.md`): так хук отличает субагента от основной сессии.
3. Решение: `agent_read_guard.py --auto` в settings, matcher `Read|Grep|Glob|Bash|Edit|Write`; из входа берёт `agent_type`, правила `--deny/--allow` читает из frontmatter файла `.claude/agents/<agent_type>.md` (единственный источник правил остаётся в файле агента); без `agent_type` (основная сессия) и для агентов без хука - пропускает. Проверено: gtm-checker, Read `Хроника_2026-11.md` → «PreToolUse:Read hook error … ЗАБЛОКИРОВАНО хуком agent_read_guard (gtm-checker) …», запись в `Скрипты/logs/agent_read_guard.csv`.
**Побочно исправлено:** сообщение хука пишется в stderr байтами utf-8 (консольная кодировка Windows не должна ронять хук кодом 1 вместо 2); префикс `PYTHONUTF8=1` убран из команд хука во всех `.claude/agents/*.md`.
**Как проверить снова:** агент (haiku) с заданием прочитать файл, закрытый его шаблоном `--deny`; в ответе сообщение о блокировке, в логе новая строка с его именем.
**Ограничения:** хук с `--auto` лежит в `settings.local.json` (локально, не в git); при переносе на другую машину повторить. Новый агент получает защиту автоматически, если в его frontmatter есть строка `command: '… agent_read_guard.py … --deny …'`. Проверка по тексту пути: Bash обойти можно (страховка, не защита).
