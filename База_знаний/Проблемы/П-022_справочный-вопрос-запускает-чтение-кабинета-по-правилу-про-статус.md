# П-022. Справочный вопрос («дай ссылки») запускает чтение кабинета и длинный ответ: правило «сначала прочитать» применено шире, чем написано

**Система:** поведение ассистента в сессии по клиенту, Landver (Andverpersonalinjury), 12.11.

**Симптом:** запрос пользователя «новые сайты по Landver — ссылки на них, те, на которые ещё не запущен трафик». Ответ занял несколько минут: запуск `state_digest.py` (первый запуск упал — `secrets/google-ads.yaml` не найден, скрипты запускаются из `Скрипты/`), чтение Хроники, затем таблица с пояснениями о причинах пауз, дублях блоков и открытых вопросах. Пользователю нужны были только ссылки. Следом ассистент сослался на правило как на оправдание, хотя вопроса про статус кампаний не было.

**Причина (установлена):** жёсткое правило в CLAUDE.md («любой вопрос про статус кампании, пауза, бюджет, кто/когда/почему поменял — сначала читать кабинет») ассистент применил к справочному запросу, у которого статус — лишь признак отбора. Ответ был в `Паспорт.md` (раздел «Страницы» и «Аккаунты»), его хватало для списка ссылок с пометкой «по Паспорту на 11.11». Второй сбой: в ответ добавлено то, о чём не просили (причины, оговорки, дубли блоков).

**Что НЕ установлено:** нужно ли для запроса «без трафика» всё же сверять статус кампаний (Паспорт на 11.11, испанскую включили в 05:26 11.11 и в Паспорте это значилось как «ENABLED по digest»). Решение пользователя — не определено.

**Обход:** справочный запрос («дай ссылки / ID / адрес / номер») — отвечать из `Паспорт.md` одной выдачей: то, что просили, плюс одна строка «по Паспорту на <дата>», если признак может устареть. Чтение кабинета — только если пользователь спросил про статус, паузу, бюджет, кто менял. Расширять ответ можно после вопроса.

**Как проверить, что решено:** на следующий запрос вида «дай ссылки/ID» ассистент отвечает за один шаг без запуска `state_digest.py` и без лишних разделов.

Связано: [[feedback_one_question_one_answer_plain]] (память), `Паспорт.md` клиента.

**Повтор 12.11 (вопрос «Motorcycle, всё готово к запуску?»):** через несколько минут после записи правила «при сомнении об объёме спросить» ассистент снова не спросил: запустил `state_digest`, `status.py`, `page_tracking_check` (браузер, десктоп+мобильный), curl HTML, читал Доску и Задачи — около 8 вызовов. Ответ «форма мёртвая на 11.11» уже лежал в карточке `Направления/Motorcycle.md`; нужен был один вопрос: «по записям вчера форма мёртвая, вы говорите, что страница готова — проверить живую страницу?». Правило записано, но не выполнено — это поведенческий сбой, не нехватка правила.
