# П-001. Суточный лимит операций (basic access): ошибка 429, закрываются запись и чтение

**Статус:** открыта  |  **Система:** Google Ads API

## Симптом (дословно)
`Resource has been exhausted (e.g. check quota)`; в деталях `Too many requests. Retry in N seconds` и `Number of operations for basic access`. Падают и запись, и поиск (чтение), и оба сторожа (`Скрипты/_guard_ea.out`, `_guard_profimet.out`). Впервые 2026-11-10 ~17:00 на записи 1 735 операций (копия минусов Landver).

## Причина
Установлено: лимит общий на токен, исчерпан уровнем basic access. НЕ установлено: что именно съело остаток за день (чтения этой сессии, сторожа, другие скрипты). Счётчика запросов в наших скриптах нет. Предположение (не проверено): validate_only лимит не тратит.

## Решение / обход
Обход: ждать сброса (N секунд из ответа, 2026-11-10 — 41 303 с, около 05:00 по Варшаве); большие записи резать порциями ≤ 400 операций и возобновляемыми шагами (`gads_landver_search_rebuild.py --part negatives --chunk N`, идемпотентно); руками в веб-интерфейсе Google Ads работать можно. Постоянное решение — задача в `Задачи.md` (корень): потолок и уровень токена в MCC → API Center, счётчик запросов, доля сторожей, кэш и реже опрос, при необходимости заявка на standard access.

## Как проверить
После сброса: `python Скрипты/gads_landver_search_rebuild.py --customer-id 213-621-6123 --read-back-only` отвечает без ошибки.

## Как не допустить
Перед большой записью: делить на порции, главное писать первым; не гонять много чтений в один день; считать запросы.
