# Google Ads: аудит минус-слов — конфликты с собственными ключами и спросом

Зачем: у аккаунтов, которые вели несколько лет, общие списки минус-слов копятся слоями («временные», «начальные», списки маршрутизации между кампаниями). Через год часть слов режет именно тот спрос, который нужен, а отчёт по поисковым запросам этого **не покажет** — заблокированные запросы в нём не появляются. Проверка по запросам с конверсиями даёт ложный ноль.

## Что проверять (порядок)
1. **Карта подключений:** `campaign_shared_set` (какие общие списки у каких включённых кампаний) + `shared_criterion` (слова списка с типом соответствия). Только включённые кампании.
2. **Свои ключи против минусов:** для каждого включённого позитивного ключа проверить все три уровня — общие списки кампании, кампанийные минусы, минусы своей группы. Правила совпадения: широкое минус-слово блокирует, если **все** его слова есть в запросе (в любом порядке); фразовое — слова подряд; точное — запрос целиком. **Минусы не знают про варианты слов** (множественное число, синонимы не блокируются) — не применять стемминг при проверке.
3. **Слова списка, похожие на целевой спрос:** прогнать слова списка через «слова интента продавца и предметов скупки» (sell, buy, cash, scrap, appraisal, estate, worth, vintage, pre-owned, broken, los angeles…).
4. **Гео-слова при расширении гео:** названия городов в минусах (см. «Negative init» LuxeBrokers: `angeles`, `la`, `burbank`) режут собственный новый охват.
5. **Маршрутизация между кампаниями:** список, который отправляет общие запросы из кампании A в B, должен стоять на A, но **не на B**. Проверка — список подключён ровно к кампаниям-источникам, а в тексте списка нет фраз ключей кампании-приёмника.
6. **Оценка объёма:** Keyword Planner по семействам заблокированных слов для гео кампаний и расширенного гео (`gads_keyword_ideas.py`) — как порядок величины, не точное число.

## Что нашли на LuxeBrokers (2026-10-12)
- Список «watces / generic» (опечатка в названии, 151 точный минус), подключённый к `watches / non-lux`, перекрывал 7 из 10 ключей этой же кампании.
- «Negative init» (457 слов, широкие, подключён ко всем 7 кампаниям) содержал scrap, broken, appraisal, estate, worth, vintage, pre-owned, `angeles`, `la`; «Temp» — free, how, online, brokers (название компании).
- «luxury» (`high-end`) перекрывал 5 ключей в кампании, где они лежали.
- Кампанийные минусы silver (`chain`, `ring`) перекрывали собственные ключи.

Эффект на объём **не измерен** (правки не внесены); оценка пула — [[../../Клиенты/LuxeBrokers/План_наращивания_объёма_2026-10]], раздел 8.

## Ограничения метода
- Датировать минус-слова нельзя: `change_event` ~29 дней, `change_status` 90, у общих списков — нет. Реальная история — только в интерфейсе (до двух лет).
- `customer_negative_criterion` не отдаёт ключевые слова уровня аккаунта в версии API v23 в наших скриптах — не проверено.
- Минусы-«справочные» («scrap gold price», «how to») часть трафика отсекают правильно; убирать слова партиями с недельным контролем по отчёту запросов, не списком.
