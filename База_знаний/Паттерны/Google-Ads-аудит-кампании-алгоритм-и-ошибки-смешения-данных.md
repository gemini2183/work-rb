# Google Ads — алгоритм аудита кампании и ошибки смешения данных

Написано по итогам сессии 2026-08-19 на
[[../../Клиенты/Andverpersonalinjury/index|Andverpersonalinjury]], где несколько раз
подряд были допущены одни и те же по природе ошибки: цифры из разных источников
(разные типы кампании, разные сети показа) молча складывались в одну сумму или
цифра из одного контекста подавалась как факт про другой. Каждый раз пользователь
ловил это по расхождению со своим кабинетом, а не наоборот. Цель документа —
чтобы в следующий раз анализ шёл по чек-листу СРАЗУ, а не через цикл
"ошибся → пользователь поймал → извинился → исправил".

## Правило №1: никогда не давать число без явной метки источника

Любая цифра (клики/расход/CPC/конверсии) в Google Ads всегда живёт в разрезе минимум
двух осей одновременно — **тип кампании** (advertising_channel_type: SEARCH /
PERFORMANCE_MAX / DISPLAY / LOCAL_SERVICES / ...) и **сеть показа**
(ad_network_type: SEARCH / SEARCH_PARTNERS / CONTENT / DISCOVER / YOUTUBE / MAPS).
Формулировка вида "Search дал $39/конверсия" БЕЗ указания, из какого именно среза
это число, — по умолчанию неверна, потому что почти наверняка это агрегат по
нескольким разным сущностям.

**Обязательное правило формулировки**: каждое число в выводах — либо явно
одноосевое ("в кампании X, сеть SEARCH_PARTNERS: ..."), либо явно помечено как
сумма/агрегат с перечислением того, что в нём смешано.

## Каталог допущенных ошибок смешения (конкретные случаи 2026-08-19)

### Ошибка 1 — Performance Max "Network=SEARCH" смешан с обычным Search

Google Ads API возвращает `segments.ad_network_type=SEARCH` и для трафика внутри
Performance Max, и для трафика обычных ручных Search-кампаний — это ДВЕ разные по
природе сущности, использующие один и тот же enum-лейбл. Интерфейс Google Ads для
PMax скрывает эту детализацию под одной строкой "Межсетевой показатель" — то есть
в UI пользователь физически не видит "Network=SEARCH внутри PMax" как отдельную
цифру, только агрегат по всем сетям PMax сразу.

Сложение строк `Network=SEARCH` из PMax-кампании и обычной Search-кампании в одну
сумму дало ложный вывод "чистый Search — здоровый канал, 32 конверсии,
$39/конверсия", хотя реальный чистый Search дал 0 конверсий за тот же период — все
32 конверсии были внутри `pmax / ca`. Поймано пользователем по скриншоту кабинета
(строка "Поиск в Google" = 0 конверсий, "Межсетевой показатель" = 42 конверсии).

**Практическое следствие**: любой GAQL-запрос к ресурсу `campaign` с
`segments.ad_network_type` ОБЯЗАН также тянуть `campaign.advertising_channel_type`
и группировать/выводить по нему в первую очередь, а не только по network. Реализовано
в `Скрипты/gads_campaigns_breakdown.py` — колонка `Channel_type` всегда рядом с
`Network`, вывод в консоль группируется сначала по `Channel_type`.

### Ошибка 2 — площадка/CPC из Search Partners подан как аргумент про чистый Search

При обсуждении длиннохвостых ключевых фраз как способа снизить CPC, был приведён
пример "slip and fall lawyers near me — $0.92/клик" как довод, что более узкая фраза
дешевле. Цифра была взята из данных Search Partners (где сеть партнёров решает
показ по своим правилам, отдельно от аукциона чистого Search) — но подана как
аргумент про то, чего можно ожидать на чистом Google Search, где, по факту
проверенному пользователем в интерфейсе (Keyword Planner suggested bid, ручное
управление ставками), порог входа на первую страницу начинается от $60+ даже по
тем же длинным фразам — независимо от длины фразы, это рыночный порог для personal
injury/LA (см. [[PPC-Personal-Injury-США-борьба-с-дорогим-и-мусорным-трафиком]],
раздел 3).

**Практическое следствие**: цена клика или ставка с Search Partners НИКОГДА не
используется как прокси/оценка цены на чистом Search — это два разных аукциона с
разной логикой ценообразования. Если нужна оценка порога входа на чистый Search —
смотреть только (а) фактический CPC уже потраченных кликов в сети SEARCH этой же
кампании, либо (б) suggested bid из Keyword Planner / ручного режима ставок в
кабинете, который пользователь может проверить напрямую.

### Ошибка 3 (для памяти, не повторно найдена в этой сессии) — conversions без сверки методологии

Общее правило вики уже требует сверки конверсий Директ/Ads с Метрикой/коллтрекингом
перед стратегическим выводом (см.
[[Сверка-конверсий-Директ-Метрика-Коллтрекинг]]) — в этой сессии добавочно
подтверждено: даже ДО такой сверки нужно сначала убедиться, что сами "conversions"
из Google Ads API относятся к тому разрезу (channel_type/network/кампания), который
обсуждается, а не к смеси разных.

## Алгоритм технического аудита кампании — пошагово

Порядок важен: от общего к частному, каждый шаг проверяем фактами API/кабинета, не
интерполируем по памяти или по названию кампании.

1. **Список кампаний целиком** — статус (ENABLED/PAUSED), тип, бюджет, стратегия
   ставок. Не предполагать по названию, что кампания активна — проверить
   `campaign.status` напрямую. Инструмент: `Скрипты/gads_campaigns_list.py`.
   На этой сессии выяснилось: из 15 кампаний аккаунта Andverpersonalinjury реально
   ENABLED было только 2, включая LSA (который считался ещё не запущенным, но по
   факту кампания LocalServicesCampaign существует и имеет бюджет).

2. **Метрики по типу × сети** за период — используя правило №1 (никогда не
   смешивать channel_type). Инструмент: `Скрипты/gads_campaigns_breakdown.py`.

3. **Разбивка по дням** для любой кампании младше запрошенного периода — `--days N`
   НЕ гарантирует, что у кампании есть данные за все N дней; кампания может быть
   создана позже начала периода. Не делать вывод "мало трафика за неделю" не
   проверив, сколько дней кампания реально существовала. Инструмент:
   `Скрипты/gads_campaigns_breakdown.py --by-day`.

4. **Настройки кампании** — network_settings (Search/Partners/Display вкл/выкл по
   отдельности, не одной галкой), гео-таргетинг (positive/negative,
   Presence/Interest — расшифровка ID через `geo_target_constant`, не сырые числа),
   расписание показов, стратегия и уровень ставок. Инструмент:
   `Скрипты/gads_campaign_settings.py`.

5. **Содержимое (группы/ключи/объявления)** — если кампания заведена вручную в
   кабинете (не через скрипты вики, соответственно нет записи в Решения.md о её
   замысле), нужен полный дамп структуры, а не предположение по названию группы.
   Внимание: неравномерное распределение числа ключей по группам — не обязательно
   сигнал о фокусе кампании, может быть просто недочищенный остаток ручной работы
   (см. кейс "Slip and Fall — 177 ключей" — оказалось не фокус, а то, что "руки не
   дошли почистить"). Не делать вывод о замысле кампании по одним числам — спросить
   или найти прямое подтверждение. Инструмент: `Скрипты/gads_campaign_inventory.py`.

6. **Реальные поисковые запросы (search terms)** — то, ПО ЧЕМУ реально показывались
   объявления, не то, что было заложено как ключи. Проверять на гео-релевантность
   явно (искать в тексте запросов названия городов/штатов, не совпадающих с целевым
   гео) — это самый прямой способ поймать нерелевантный/geo-masked трафик с Search
   Partners, без необходимости внешних click-fraud инструментов. Инструмент:
   `Скрипты/gads_campaigns_breakdown.py --search-terms`.

7. **Impression Share / Lost IS (Budget vs Rank)** — прежде чем говорить "мало
   бюджета" или "не хватает ставки", проверить, ГДЕ именно теряются показы.
   `search_budget_lost_impression_share` близко к 0 означает, что бюджет НЕ
   является узким местом, даже если кампания тратит намного меньше дневного лимита
   — тогда причина в `search_rank_lost_impression_share` (ставка/Quality Score), и
   поднимать бюджет бессмысленно, надо работать со ставкой/релевантностью. На
   аккаунте Andverpersonalinjury 2026-08-19: обе новые LA-тестовые кампании — IS
   9.99%, Lost(Budget) 0%, Lost(Rank) 90% — бюджет вообще не был проблемой, хотя
   именно на бюджет и на "не хватает ставки чтобы получать клики на чистом Search"
   изначально указывал пользователь. Инструмент: `Скрипты/gads_impression_share.py`.

8. **Сверка конверсий** (Директ/Ads vs Метрика/коллтрекинг) — см.
   [[Сверка-конверсий-Директ-Метрика-Коллтрекинг]] — обязательный последний шаг
   перед любым стратегическим выводом уровня "кампания не работает"/"канал
   здоровый".

## Готовый набор команд (копировать и подставлять customer-id/даты/названия)

Все скрипты — customer_id напрямую (не через таблицу Adwhite, если клиент там не
заведён — см. `_project.md` клиента), сохраняют CSV в `Клиенты/<клиент>/Статистика/`
и печатают сводку в консоль. Порядок соответствует шагам 1-8 выше.

```
# 1. Что вообще сейчас включено
python gads_campaigns_list.py --customer-id <ID> --client-folder "<Клиент>" --all

# 2. Метрики по типу кампании x сети показа за период
python gads_campaigns_breakdown.py --customer-id <ID> --client-folder "<Клиент>" --days 30

# 3. Разбивка по дням — для кампаний младше периода (проверить реальную дату старта)
python gads_campaigns_breakdown.py --customer-id <ID> --client-folder "<Клиент>" \
    --days 30 --by-day --campaigns "<кампания1>,<кампания2>"

# 4. Настройки: сети/гео/расписание/ставки
python gads_campaign_settings.py --customer-id <ID> --client-folder "<Клиент>" \
    --campaigns "<кампания1>,<кампания2>"

# 5. Структура: группы/ключи/объявления
python gads_campaign_inventory.py --customer-id <ID> --client-folder "<Клиент>" \
    --campaigns "<кампания1>,<кампания2>"

# 6. Реальные поисковые запросы (проверить гео-релевантность вручную по тексту)
python gads_campaigns_breakdown.py --customer-id <ID> --client-folder "<Клиент>" \
    --days 30 --search-terms --campaigns "<кампания1>,<кампания2>"

# 7. Impression Share / Lost IS — бюджет или ставка/QS виноваты в нехватке показов
python gads_impression_share.py --customer-id <ID> --client-folder "<Клиент>" --days 7

# 8. Аудит Search Partners площадок (отдельная узкая задача, не всегда нужна)
python gads_search_partners_audit.py --customer-id <ID> --client-folder "<Клиент>" --days 30
```

Все скрипты запускать с `PYTHONIOENCODING=utf-8` в этом окружении (Windows-консоль
по умолчанию не в UTF-8, вывод с кириллицей/стрелками падает без этой переменной).

## Как использовать этот документ в следующей сессии

Не пересобирать алгоритм заново каждый раз — открыть этот файл в начале
технического аудита Google Ads кампании (по [[../../Клиенты/index|любому]]
клиенту, не только Andverpersonalinjury, паттерн общий), пройти по шагам 1-8 с
готовыми командами выше, дособрать/актуализировать сам документ, если всплывёт
новый тип ошибки смешения данных или новый шаг алгоритма, которого здесь не
хватило.
