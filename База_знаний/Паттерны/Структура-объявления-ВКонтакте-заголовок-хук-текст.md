# Структура объявления ВКонтакте: заголовок vs хук vs текст

Открытый вопрос из обсуждения MVP по [[Агентная-генерация-объявлений-архитектура|агентной генерации объявлений]]:
должен ли "хук" (фраза, останавливающая скролл) жить в заголовке (до 40 симв.,
универсальный формат VK Ads) или в начале текстового поля. Прямого официального
ответа VK не даёт — ниже честно собранная картина из нескольких источников,
статус "не протестировано" до проверки на реальных кампаниях.

## Ключевой технический факт, который важнее общих советов

В ленте ВКонтакте у рекламной записи **видны только первые ~2 строки текста**,
дальше — обрезка по кнопке "Показать полностью". Источник:
https://blog.tochkadostupa.pro/prodayushhie-zagolovki-dlya-postov-34-priyoma/.

Следствие: зона "что реально останавливает скролл" — это **заголовок
(отдельный видимый элемент карточки) + первые 1-2 строки текста**, а не что-то
одно из них. Не стоит проектировать саб-агентов так, будто хук — это только
заголовок или только начало текста; это связка.

## Роль заголовка (по общим рекомендациям, без привязки к конкретной нише)

- VK Ads формально рекомендует: заголовок должен быть конкретным и отражать
  суть предложения (https://ads.vk.ru/help/features/formats).
- Более развёрнуто — заголовок решает отдельную задачу: "вовлечь человека в
  текст, заинтересовать его, сделать так, чтобы он захотел прочитать то, что
  написано дальше" (34 приёма продающих заголовков, tochkadostupa.pro). Это
  предполагает, что заголовок — не финальный крючок сам по себе, а мостик к
  тексту.
- Рабочий список приёмов для заголовка (Дмитрий Румянцев, 34 приёма, полный
  список — см. страницу целиком по ссылке выше): авторитет, скорость
  результата, самоидентификация по профессии/личным данным, геолокация,
  время/срочность, списки, цифры, страх потери, слом шаблона, акцент на боли,
  вопрос к аудитории и др. Многие из них годятся и для короткого поля 40
  символов, и как первая строка текста.

## Роль текста (структура по AIDA/аналогам)

Общая формула, подтверждённая несколькими источниками (yagla.ru, qmedia.by,
elama.ru): **Attention (хук/боль в первой строке) → Interest/Desire (оффер,
раскрытие, усиление) → Action (призыв к действию)**. Учитывая ограничение
видимости (первые 1-2 строки до "Показать полностью"), хук должен быть
физически в начале текста, а не только в заголовке.

## Рабочая гипотеза для роли саб-агентов (требует проверки на практике)

Раз в интерфейсе VK Ads для универсального формата всего 2 генерируемых
текстовых поля (заголовок до 40 симв., текст без жёсткого верхнего лимита —
кнопка CTA выбирается из готового списка, не генерируется), разумная гипотеза:

- **Саб-агент "Заголовок"** — короткий вовлекающий элемент по формуле из 34
  приёмов (не обязательно сам хук в смысле "боли", скорее крючок-мостик:
  конкретика оффера/ЦА/гео/цифра, который заставляет прочитать текст).
- **Саб-агент "Текст"** — пишет весь текст целиком, включая собственный хук в
  первой строке (боль/результат/контраст/цифра — по AIDA), затем раскрытие
  оффера сообщества и объяснение, зачем подписываться, и переход к действию
  (кнопка CTA уже фиксирована формулировкой из списка VK, но текст должен
  логически подводить к ней).

Это не финальное архитектурное решение, а гипотеза для первого раунда
генерации — проверяется реальными тестами, вывод и его результат должны потом
попасть в лог экспериментов инструмента (см. `Инфраструктура.md`, когда
появится сам инструмент), а не только в эту страницу.

## Что явно не найдено ни в одном источнике

- Прямая рекомендация VK "заголовок = хук" или "заголовок = дескриптор" —
  такой рекомендации нет, это остаётся эмпирическим вопросом.
- Ниша-специфичные паттерны (пользователь отдельно отметил, что "по разным
  нишам может быть по-разному") — общие источники этого не покрывают, нужно
  копить самим по мере тестов в `Решения.md` конкретных проектов.
