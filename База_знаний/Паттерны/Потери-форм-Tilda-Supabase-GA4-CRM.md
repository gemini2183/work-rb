# Потери форм между Tilda, Supabase, GA4 и CRM

Метод: `Скрипты/forms_funnel_reconcile.py` (см. [[../../Скрипты/README]]). Эталон — выгрузка Tilda (все отправки на сайте), остальные источники считаются долей от неё. Период 01.10–27.10.2026, тестовые отправки исключены.

## Итог по клиентам (число отправок формы)

| Клиент | Tilda | CRM | GA4 | Supabase (пары по времени ±3 мин) | Supabase (с телефоном) |
|---|---|---|---|---|---|
| ProfiMet | 72 | 71 | 49 (68%) | 64 (89%), плюс 4 лишние строки | 27 — с 19.10 |
| ExpertAgro | 64 | 65 | 58 (91%) | 58 (91%), плюс 4 лишние строки | 19 — с 17.10 |

- **CRM** получает почти всё: ProfiMet 71 из 72 (недостающая — отправка 27.10 11:34 по Варшаве, её нет и в Supabase, вероятно, ещё не дошла). У ExpertAgro в CRM 65 строк при 64 в Tilda: заявка 05.10 09:11 есть в CRM, а в выгрузке Tilda её нет, то есть выгрузка Tilda тоже неполна.
- **Повторные отправки** с одного номера в один день (ProfiMet 05.10, 15.10, 22.10) есть и в Tilda, и в CRM отдельными строками с разными номерами заказа.
- **Supabase**: по времени находит пару для 64 из 72 отправок ProfiMet и 58 из 64 ExpertAgro; ещё по 4 строки не имеют пары в Tilda. Сравнение «число строк против числа отправок» (68 и 62) вводило в заблуждение. Телефон в строке есть не всегда: телефон в строке появился только после правки GTM: ExpertAgro с 17.10, ProfiMet с 19.10. До этого сопоставлять по телефону нечем, только по числу строк за день. После правки доля попаданий: ExpertAgro 19 из 19, ProfiMet 27 из 31.
- **GA4, ProfiMet:** из 23 заявок, которых нет в GA4, у 20 пустой `ga_client_id` в Tilda (у посетителя не было cookie GA, событие не отправилось). Заявки с заполненным `ga_client_id` дошли в GA4 почти все (49 из 52; три потерянных — без метки источника). Заявки с пустым `ga_client_id` не дошли ни одна: Facebook 7 из 7, Google Ads 10 из 10, без метки 3 из 3. Причину (отказ от cookie, встроенный браузер Facebook, блокировщик) данные не показывают: гипотеза.
- **GA4, ExpertAgro:** `form_submit` приходит по два события на каждую отправку (120 событий на 58 найденных заявок), поэтому число событий нельзя сравнивать с числом заявок. Реально потеряно 6 из 64.
- **Метка источника в CRM** потеряна у части заявок: ProfiMet «Нет метки» 30 из 72 (в GA4 у 18 из них канал известен: 15 Google Ads, 3 Facebook), ExpertAgro 22 из 64 (в GA4/Supabase канал известен у 19: 16 рекламных и 3 органических). Канал в воронке собран цепочкой UTM Tilda → UTM Supabase → метка CRM → сеанс GA4; это восстановленный канал, а не данные клиента.

## Чего данные не показывают
- Почему `ga_client_id` пуст у части посетителей ProfiMet (причина не определена).
- Откуда второе событие `form_submit` у ExpertAgro (два тега или два триггера в GTM) — не проверялось.
- Отправки Tilda, которые никуда не дошли, не видны, если Tilda не записала их сама.

## Метки (UTM) по пути Tilda → CRM, октябрь 2026
Метка в Tilda у ExpertAgro — колонки `utm_*` (или адрес страницы), у ProfiMet колонок с метками в выгрузке нет, метка видна только в адресе страницы `referer` в момент отправки (если человек перешёл на другую страницу сайта, метки в адресе уже нет).

| | Метка есть в Tilda | сохранилась в CRM | потеряна в CRM | Метки в Tilda нет | из них реклама по GA4/Supabase | в CRM у них метка |
|---|---|---|---|---|---|---|
| ProfiMet | 44 из 72 | 40 | 3 | 28 | 17 | 0 |
| ExpertAgro | 58 из 64 | 42 | 16 | 6 | 0 | 0 |

- У ExpertAgro потеряны 16 из 58 меток (Google 9, Facebook 7), равномерно по дням и по обеим формам. Кампания у сохранившихся совпадает во всех 42 случаях (пять формальных отличий — это `&mdash;` против `—` в названии).
- У ProfiMet 17 заявок без метки в Tilda GA4 или Supabase определяют как рекламные (GA4 `google / cpc` 15, `facebook / cpc` 1, Supabase 5; часть пересекается); в CRM метки нет ни у одной.
- Причина потери метки в CRM по данным не видна: метка есть в Tilda, а CRM её не показывает.
