# Ключ «продавца» с двусмысленной фразой: проверять запросы, а не текст ключа

**Что случилось.** Для кампании «скупка часов» (клиент покупает часы у людей) в набор фраз добавили «watch buying», потому что один раз показалась как запрос с 2 кликами и 1 заявкой. За 6 дней ключ дал 79% кликов и 75% заявок кампании, но все 28 видимых кликов пришли с запросов покупателя («watch store near me», «watches near me», «luxury watches for sale near me»). Клиент по звонкам сказал то же самое: звонят покупатели.

**Почему так.** Фразовое соответствие берёт запросы, близкие по смыслу, а не только с точным текстом. Слово «buying» без «sell / we buy / buyers» читается и как «покупать часы». Заявка «Calls from ads» не знает, зачем человек звонил, поэтому покупательский звонок засчитывается как заявка и учит автоставку привозить ещё таких же.

**Как действовать.**
1. Фразу без явного глагола продавца («sell», «we buy», «who buys», «cash for») в кампанию продавца не ставить.
2. Через 3–5 дней после добавления смотреть запросы по каждому новому ключу (в API `search_term_view` с `segments.keyword.info.text`), а не только заявки по ключу.
3. Резкий рост заявок после добавления фраз — повод проверить смысл запросов, а не радоваться; доля покупательских звонков известна только по выгрузке «Call details» с пометками клиента.
4. Минус-фразы покупателя (store, shop, for sale) — отдельным шагом, с проверкой конфликта с ключами продавца.
