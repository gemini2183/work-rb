# Аудит Яндекс Директа для потенциального клиента — план проверок и срезов

Цель такого аудита — не «найти ошибки подрядчика», а показать потенциальному клиенту, что мы видим: как сделана первая настройка, что неверно, насколько это критично, сколько это стоило (если можно посчитать) и какие возможности не использованы. Пример и материал — [[../../Клиенты/Novotel_Moscow_City/Аудит_мероприятий_2026-11-02]].

## Источники и оговорки

- Свежие русскоязычные: [vc.ru, методика аудита после перехода на комбинаторные объявления, 31 июля 2026](https://vc.ru/marketing/3038656-audit-yandeks-direkta-metodika-proverki) (тот же текст на [sostav.ru](https://www.sostav.ru/blogs/272128/100132) — один источник, не два); [ppc.world, чек-лист аудита, 05.03.2024](https://ppc.world/articles/chek-list-kak-provesti-audit-reklamnyh-kampaniy-v-yandeks-direkte/) — про интервью с заказчиком, типы кампаний, срезы Мастера отчётов; по минус-словам, расширениям, корректировкам, РСЯ в нём почти ничего.
- Официальное: [список полей отчётов API Директа](https://yandex.ru/dev/direct/doc/en/fields-list) — какие срезы вообще доступны. Официальной страницы «чек-лист аудита» в документации Яндекса я не нашёл.
- Пороги из статей (нецелевые запросы до 10% нормально, больше 25% критично; около 10 конверсий в неделю для автостратегии; решения от 20–30 кликов; «72% аккаунтов без корректировок»; отказы РСЯ выше 80%) — практика агентств, **на наших кампаниях не проверены**. В отчёте клиенту подавать как ориентир, не как стандарт.

## Часть А. Настройки (как сделана первая настройка)

| Блок | Что проверяем | Откуда берём | Критичность, если не так |
|---|---|---|---|
| Цели и измерение | цели с нулём срабатываний; дубли; микроцель в обучении стратегии; звонки в целях; расхождение с CRM (порог статьи 15–20%) | настройки кампаний (API), Метрика | высокая: стратегия учится не на том |
| Стратегия и бюджет | число конверсий в неделю против порога (около 10); лимиты; упор в потолок; частота правок | API, отчёты | высокая |
| Структура и нейминг | логика разделения; дробность; дубли и пересечения; тестовые кампании без сопоставимости | API, список кампаний | средняя |
| Гео и расписание | регион таргетинга против региона бизнеса; расписание; корректировки | API (регионы групп, расписание) | средняя–высокая |
| Семантика | полнота и широта ядра; нецелевое; ключи с минус-словами внутри фразы | ключи, запросы | высокая |
| Минус-слова | кампания / группа / общие списки; актуальность; конфликты с собственными ключами | API | средняя–высокая |
| Автотаргетинг | включён ли; какие категории; доля расхода и цена обращения | API, срез «условие показа» | средняя |
| Объявления | заполненность; УТП; соответствие ключу и странице; метки Calltouch/UTM | API | средняя |
| Расширения | быстрые ссылки с описаниями, уточнения, визитка, отображаемая ссылка, изображения, цена, промо | API (sitelinks, adextensions, vcards, ads) | средняя |
| Корректировки ставок | устройства, пол, возраст, регион, время, аудитории; ретаргетинг | API (bidmodifiers, audiencetargets) | средняя |
| Посадочная и сайт | скорость, мобильная версия, форма, колл-трекинг, соответствие объявлению | вручную / Метрика | высокая, но углублять только по запросу клиента (решение 2026-10-26) |

Комбинаторные объявления (из статьи vc.ru): с 30.06.2026 в ЕПК нельзя создавать одиночные ТГО, с 14.07 старые ТГО переведены автоматически. Для аудита архивных текстовых кампаний не критично, для рекомендаций по новым кампаниям — учитывать.

### Охват в Директе: что можно снять (проверено запросом к API 2026-11-02, Novotel, кампания 705894438)
- **AvgTrafficVolume** — средний объём трафика с позиций, на которых были показы (официальное описание). **WeightedImpressions = Impressions × AvgTrafficVolume / 100.** Читать так: показы шли с позиций, дающих в среднем N% трафика запроса; чем ниже N, тем больше охвата не добрано. Это косвенная оценка, а не доля аукционов. Работает в CAMPAIGN/CRITERIA и др. отчётах, в т.ч. по ключам.
- **AvgImpressionPosition / AvgClickPosition** (только первая страница выдачи), **AvgEffectiveBid** (ставка с корректировками, только оплата за клик) — динамика по месяцам показывает, какой ценой держался охват.
- **ImpressionShare**: API принимает поле только в CAMPAIGN_PERFORMANCE_REPORT и возвращает пусто на всём периоде (янв–июнь 2026); в SEARCH_QUERY и CUSTOM отчётах недопустимо (ошибка 4000). Официального описания не нашли. Долей показов и числа аукционов, в которых участвовали, **в API нет**.
- **«Доля выигрышей» в Мастере отчётов (интерфейс, подсказка Директа, скрин пользователя 2026-11-02):** доля выигранных аукционов за показ в общем числе аукционов, где участвовала кампания; помогает оценить потенциал роста (неохваченный объём показов). Считается на выборке (семплирование), значение может отличаться от истинного; анализировать для группировок от 1 000 показов. Только поиск; ориентир «выше 60%» — мнение блога ([postium](https://postium.ru/share-of-impressions-yandeks-direkt/)), не норма. Имя поля в API не подтверждено: вероятный кандидат — ImpressionShare (CAMPAIGN_PERFORMANCE_REPORT), но на архивных кампаниях за январь–июнь оно пустое. Для архива — снимать в интерфейсе вручную и проверять, заполняется ли за старые периоды.
- Другие способы оценить охват: сравнить показы по ключам с частотностью Вордстата (точная «!фраза»), статус «Мало показов», у живых кампаний — keywordbids (ставка → объём трафика по позициям; на архиве не проверено).
- Пример чтения: Тест_Сайта, объём трафика 54% (янв) → 71% (апр); AvgEffectiveBid 258 → 1519 ₽ в то же время. Причина роста ставки в данных этого нет.

Из Метрики (счётчик, к которому есть доступ): визиты по часам и дням недели, страницы входа, глубина и время по UTM-кампании, цели. Ограничение: считает только то, что попало в этот счётчик.

Из Вордстата (вручную через Chrome): спрос на название, регионы, фразы — для оценки потолка охвата.

## Часть В. Как показать ущерб и возможности цифрой

- **Ущерб** — только там, где хватает данных: расход на сегмент, где цена обращения выше нужной при объёме от 20–30 кликов; расход на нецелевые запросы (доля по порогу статьи — ориентир). Всегда с диапазоном и пометкой выборки.
- **Возможность** — сценарий «тот же расход по цене лучшего сегмента» как верхняя граница и «с учётом ошибки выборки» как нижняя; охват и спрос — по Вордстату; формат/расширение, которых нет, — описанием, без цифры, пока нет данных.
- Чего не знаем (доля показов, качество обращений, продажи) — так и писать «в данных этого нет».

## Часть Г. Порядок работы

1. Цели и измерение (это определяет всё остальное).
2. Настройки по Части А — одним сбором из API (только чтение) по всем кампаниям.
3. Срезы Части Б — по каждой кампании, потом сводно.
4. Ущерб и возможности (Часть В).
5. Клиентская версия (потенциал, без внутренней кухни, без «вины» подрядчика — решение 2026-10-26).
