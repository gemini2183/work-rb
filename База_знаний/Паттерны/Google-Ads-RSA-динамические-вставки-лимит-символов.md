# Google Ads RSA — лимит символов для динамических вставок

Responsive Search Ads поддерживают две динамические вставки прямо в тексте
заголовка/описания: `{KeyWord:default text}` (подставляет текст ключевого
слова, по которому показано объявление) и `{LOCATION(City):default text}`
(подставляет город пользователя по геолокации). Обе — не просто декоративный
синтаксис, они участвуют в проверке лимита символов Google Ads Editor/API
особым образом.

## Правило

Лимит (30 символов Headline, 90 Description) применяется к **видимому
тексту вставки** — тому, что стоит после последнего `:` внутри фигурных
скобок (default text) — а не к синтаксической записи целиком.

```
{KeyWord:Bicycle Injury Lawyer LA}
```

Это 34 символа как строка, но реально проверяемая длина — 25 символов
("Bicycle Injury Lawyer LA", то, что после `:`). Editor принимает такую
строку без ошибки, хотя наивная проверка `len(text) > 30` даст ложное
срабатывание.

Вставка может быть **частью более длинной строки**, не только всей строкой
целиком:

```
Injured In {LOCATION(City):California}?
```

39 символов как строка, но реально проверяемая длина — 22 символа
("Injured In California?" — синтаксис вставки не считается, только "California"
из неё плюс окружающий обычный текст).

## Как считать программно

Заменить вставку на её default-текст внутри строки (regex, не полное
совпадение всей строки), затем взять длину результата:

```python
import re

def displayed_length(text):
    resolved = re.sub(r"\{KeyWord:([^}]+)\}", r"\1", text)
    resolved = re.sub(r"\{LOCATION\([^)]*\):([^}]+)\}", r"\1", resolved)
    return len(resolved)
```

При автоматическом укорачивании текста (напр. срезание "in CA"/"CA" под
лимит) — не трогать текст **внутри** фигурных скобок вставки, только текст
снаружи. Модификация default-текста вставки — отдельная, более рискованная
операция (меняет то, что реально показывается пользователю при подстановке),
не автоматизирована в наших скриптах.

(`{KeyWord:Car Accident Injury Lawyer CA}` и `Injured In {LOCATION(City):California}?`),
naive-проверка длины давала ложные предупреждения о превышении лимита на
обеих строках при генерации гео-вариантов объявления, пока проверка не была
исправлена по правилу выше. Использовано в `Скрипты/gads_geo_ad_group_builder.py`
и `Скрипты/gads_ad_adapter.py` (см. [[../../Инфраструктура|Инфраструктура]]).
