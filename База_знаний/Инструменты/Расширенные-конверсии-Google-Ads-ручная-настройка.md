# Расширенные конверсии Google Ads: предупреждение "рекомендуем добавить код вручную"

## Симптом

В диагностике кампании Search (вкладка "Цели") Google Ads показывает предупреждение:

> В настройках расширенного отслеживания конверсий есть проблемы, влияющие на эффективность.
> При расширенном отслеживании для учёта конверсий на сайте используются собственные
> данные. При текущем охвате вы можете получать более точные данные о конверсиях, если
> исправите ошибки в настройках. Рекомендуем добавить код на страницы в дополнение к
> автоматическому методу настройки.

Таблица указывает конкретное действие-конверсию (например `form_submit_gtm`), источник — обычно **TAG** (тег через GTM), метод — "Основные" / "Автоматический".

## Что это означает

Расширенные конверсии (Enhanced Conversions) — механизм, которым Google сопоставляет
конверсию на сайте с конкретным пользователем/кликом через хэшированные собственные
данные (email, телефон), а не только через клики/cookie. Это повышает точность подсчёта
конверсий, особенно в условиях урезанных cookies/iOS ATT.

Есть два метода включения:
- **Автоматический** — Google сам пытается найти поля email/телефона в HTML-форме на
  странице и захэшировать их значения. Часто промахивается: нестандартные имена полей,
  динамические/JS-формы, поля вне `<form>`, конструкторы сайтов.
- **Ручной (via code / via GTM variables)** — email/телефон явно передаются в тег
  конверсии как переменные (`enhanced_conversion_data`), обычно через `dataLayer.push`
  при сабмите формы + DOM/dataLayer-переменные в GTM.

Google явно рекомендует **не полагаться только на автоматический метод**, а добавить
ручную передачу как дополнение — это увеличивает процент сматченных конверсий.

**Почему это влияет на эффективность:** кампания на скрине использует стратегию
"Максимум конверсий" (автостратегия). Такие стратегии обучаются на сигнале о
конверсиях — чем больше конверсий распознано и качественно сматчено с пользователем,
тем быстрее и точнее обучение (см. блок "Идёт обучение новой стратегии" на той же
диагностике). Недомэтченные конверсии = менее точное обучение = потенциально хуже
результат при том же бюджете.

## Как исправить (типовой путь через GTM)

1. В GTM найти тег конверсии Google Ads (или тег конфигурации GA4, если конверсия идёт
   через него) для нужного действия-конверсии.
2. В настройках тега включить **"Enhanced conversions"** → переключить с автоматического
   метода на **"Manually set variables"** ("Задать вручную").
3. Указать переменные с email/телефоном пользователя. Источник данных — dataLayer,
   который форма должна пушить при сабмите (например `{{DLV - email}}`, `{{DLV - phone}}`).
   Если форма ещё не пушит эти поля в dataLayer — нужна доработка на стороне сайта
   (веб-мастер/разработчик добавляет `dataLayer.push({event: '...', user_email: ..., user_phone: ...})`
   в обработчик сабмита).
4. Опубликовать контейнер GTM.
5. Проверить статус: в Google Ads → Инструменты → Конверсии → открыть действие-конверсию →
   раздел "Расширенное отслеживание конверсий" должен показать "Работает" вместо
   предупреждения. Также можно проверить через Tag Assistant, что тег реально получает
   захэшированные значения при тестовом сабмите.

## Ограничения / что нужно для внедрения

- Нужен доступ к GTM-контейнеру клиента и понимание, куда именно форма пишет данные
  (или доработка со стороны сайта, если dataLayer с email/телефоном ещё не настроен).
- Хэширование (SHA256) Google делает сам на стороне тега — вручную хэшировать не нужно,
  если используется официальный тег Google Ads/GA4 через GTM.
- Это не заменяет базовую настройку конверсии, а дополняет её — автоматический метод
  можно оставить включённым одновременно с ручным.

## Как передавать телефон через GTM API (проверено 2026-11-04, LuxeBrokers)

Переменная типа `awec` (в интерфейсе «Данные, предоставляемые пользователями»), ручной режим: `mode=MANUAL`, телефон — ключ `phone_number`, email — `email`, адрес — `first_name`, `last_name`, `country`, `postal_code`. API молча отбрасывает неизвестные ключи (код 200 ничего не доказывает) — проверять по ответу. В теге awct: `enableEnhancedConversion=true` и `cssProvidedEnhancedConversionValue={{переменная}}`. Проверка до публикации: в запросе конверсии `ec_mode=m` и `em=tv.1~pn.<хэш>`; пустой `em=tv.1` — данные не дошли. Хэш — SHA-256 номера в формате E.164 (+1…) в base64url. Скрипты: `Скрипты/gtm_awct_enhanced_conversions.py`, `Скрипты/gtm_test_ec_form.py`. Эффект на покрытие в диагностике Google Ads ещё не измерен (версия 16 не опубликована).
