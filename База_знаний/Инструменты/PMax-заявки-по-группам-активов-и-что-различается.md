# PMax: заявки по группам активов

## Что можно и нельзя
- **Сигнал группы — подсказка, не таргетинг.** Аудитории и поисковые темы направляют обучение; Google показывает и мимо них (группа `no signal` без сигналов даёт заявки). Бюджет общий, равную долю каждой группе бюджетом не обеспечить: в октябре `search themes` получила 55% расхода, три слабые группы вместе 5%.
- **Звонки Ringostat по группам не развести.** В `utm_content` PMax поле группы пустое (`rb_cid_<id>_|gid_|aid_|pos_|dev_m|plc_|…`): проверено на 57 звонках с 20.09. Различаются только кампания и устройство.
- **Единственный способ видеть заявки по группам — конверсии Ads по группе активов** (`asset_group` + `segments.conversion_action_name`), выбирая только реальные действия: `form_submit_gtm`, `Звонки по объявлениям`, GA4 `Ringostat_calls`, `Ringostat_calls_static`, GA4 `form_submit`; исключая `Клик по номеру` и `addToCart_*`. Оговорка: GA4 `form_submit` и `form_submit_gtm` могут дублировать одну форму (верхняя оценка).
- Для статической PMax на клик по номеру (`pmax01_call_test`) в Ads вообще нет реальных заявок по группам, только клики по номеру.

## Пример (pmax1_test, 01.09–12.10)
Расход / заявки / цена: `search themes` 1 237 € / 52 / 24 €; `no signal` 225 € / 7 / 32 €; `competitors` 340 € / 7 / 47 €; `зп` 234 € / 4 / 58 €; `ци` 185 € / 1 / 185 €; `remarketing` 5 € / 0. Вывод для 22.10: пауза `ци` по любому правилу, `зп` и `competitors` — на границе, `no signal` вопреки записи в плане — не слабая (выборка 7 заявок, перепроверить).

## Правило оценки группы
Группа, потратившая 2 × цель без заявки за 7 дней, — кандидат на паузу; группа, получившая меньше 1 цели расхода, — «не набрала данных», а не «плохая». Раздельные кампании со статическим номером оправданы, если группа набрала ≥ 10 заявок и ей нужны отдельный бюджет или посадочная; при объёме проекта ≈ 4 заявки в день дробить рано.
