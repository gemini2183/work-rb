## Гео — подробно

- Настройка есть в кабинете и меняется в «Настройках → Таргетирование». [справка: `commercial-coverage`]
- Наши данные: из 36 кампаний 28 стоят на «Россия», 8 — на списках из федеральных округов (Северо-Запад, Центр, Урал, Поволжье, Дальний Восток, Сибирь, Юг) и отдельных областей/республик (Астраханская, Ростовская, Волгоградская, Краснодарский край, Калмыкия, Адыгея). [наши данные: `targeting.geo`] Это снимает записанное в `Журнале`/`Решениях` «гео нет в API»: **настройка есть и читается**, а **расход и показы по регионам не отдаются** (репорты `campaigns-daily-stats`, `campaigns-publications-daily-stats` без регионального измерения). Точный CPL по городу из API посчитать нельзя; это по-прежнему верно. [справка + наши данные]
- **Макрос `{region_name}`** (регион, в котором показано объявление) можно подставить в UTM или в произвольный параметр ссылки (`advertising/macros`): тогда регион станет доступен в Метрике и CPL по региону можно будет считать со стороны сайта (визиты и заявки), хотя расход по региону по-прежнему не виден. [справка; не проверено на практике, на наших ссылках макрос не стоит или не проверялся]
- Метрика публикаций (отдельный счётчик) отдаёт пол, возраст, геоданные и интересы **читателей статьи** — всех, кто открыл, а не только перешедших на сайт. [справка: `statistics/settings`] У нас анализ пол/возраст/гео шёл по счётчику сайта 66145201 (только пришедшие на сайт), так что картина про «читателей» неполная. Использовался ли у клиента отдельный счётчик публикаций, из вики не видно.
- Практики: «расширенное гео может показывать рекламу не там, где человек сейчас» (Habr, 2024), «пол, возраст, гео и устройства лучше оставлять широкими, интересы не улучшали результат» (vc.ru, 20.02.2024), для Дзена/VK гео до области, у ПромоСтраниц до города (Habr). [практики, не проверено]. Мелкий локальный бизнес и бизнес с жёсткой привязкой к району в ПромоСтраницах работает плохо: таргетинга на район нет (Habr). [практики]

## Пол и возраст

- Пол и возраст — ручные таргеты; по ним нельзя «ставить корректировки ставок», в отличие от Яндекс Директа (корректировок в справке нет). [в источниках нет]
- В нашем наборе: `gender` `["f"]` у 23 кампаний, `["m","f"]` у 7, `["m"]` у 6; возрасты чаще всего `25_34, 35_44, 45_54` (28 кампаний), `18_24` включали у 3. [наши данные]
- Название кампании у нас содержит таргет («Ж25-54», «М25-44»), а сам таргет — в настройках; расхождение названия и настройки возможно (кампания «Ж25-44 … 2404» имеет возраст `25_34,35_44,45_54` по настройкам). Источник правды — API, не название. [наши данные: `dzen_campaigns_scorecard_2026-10-27.csv`]
- Пол/возраст в статистике ПромоСтраниц — только в «Метрике публикаций» (читатели) и в Метрике сайта (визитёры); не в отчётах API. См. [[Promopages-отчёты-и-API]].

## Устройства

- Список устройств отмечается галочками; справка советует не ограничивать, если цель — не приложение. [справка]
- В API значения `desktop`, `ios`, `android`; макрос `{device_type}` даёт `desktop`, `mobile`, `tablet` для UTM. [справка]
- У всех 36 наших кампаний выбраны все три класса. [наши данные]. Разреза расхода по устройствам в API нет; со стороны Метрики можно резать по `ym:s:deviceCategory` визиты и заявки (CPL по устройству тогда не считается).

## Интересы и автотаргетинг

- Интересы работают только в РСЯ; на старте рекомендуют добавить интересы и сегменты, чтобы Look-a-Like сразу стартовал по близкой аудитории. Больше категорий — шире охват, ниже точность. [справка]
- Автотаргетинг в РСЯ можно выключить; на Поиске нельзя. [справка]
- Автотаргетинг у практиков описывается как двухэтапный: сначала широкий показ по семантике, затем Look-a-Like по тем, кто дочитал/перешёл; оптимизация идёт по CTR, затем по дочитываниям, затем по конверсиям; обучение 7-14 дней (vc.ru 2024). Интересы, по опыту этих авторов, результат не улучшали. [практики, не проверено]
- Наши названия кампаний содержат «интерес_франшиза» и «интерес_открытие бизнеса»: это таргет по списку интересов (две отдельные тематики), совпавший с самыми сильными по CR% в `Решения.md`. Какие именно категории стоят в этих списках, API не отдаёт; нужен скриншот списка интересов в кабинете. [наши данные + пробел]

## Аудитории (сегменты): как устроено

[справка: `commercial-coverage`, шаги 9 и 12; `statistics/pixel`; `statistics/settings`]

- Источник сегментов — **Яндекс Аудитории**: «сегменты, привязанные к вашему аккаунту или к которым у вас есть доступ». Пиксели Аудиторий и Метрики для медийной рекламы, поставленные на события «Открытие» / «Полный просмотр» / «Внешний переход», собирают читателей в сегменты для ретаргетинга в Директе и в самой ПромоСтраницах.
- Три режима:
  1. **Показывать похожей аудитории** (look-alike): подходит на старте для узких релевантных сегментов (например, текущие клиенты).
  2. **Показывать выбранной аудитории**: возврат/удержание; охват ограничен размером сегмента; **если сегмент меньше 200 тыс., справка советует look-alike**.
  3. **Исключить показ на выбранный сегмент**: аналог «минус-аудитории» (например, уже знакомые с продуктом).
- Размер: больше 1000 пользователей, до 5 сегментов в кампании.
- Расхождение: MediaGuru (ppc.world, 05.12.2024) пишет «для таргетинга сегмент должен содержать не менее 200 000 пользователей». Справка называет порогом 1000, а 200 тыс. — рубежом, ниже которого режим «выбранной аудитории» малоэффективен. Вероятно, автор смешал два числа. Верить справке; проверить на практике загрузкой сегмента в 1000-5000 человек. [не проверено на практике]
- Загрузка своих списков (CRM) — через Яндекс Аудитории (Kokoc 2026 называет «списки из CRM, look-alike, ремаркетинг»); сама справка ПромоСтраниц о CRM-списках молчит, только «сегменты из Аудиторий». [практики: Kokoc]; сегменты из Метрики (например, «регистрации за 90 дней») для look-alike и исключения — vc.ru 2024. [практики, не проверено]
- Ретаргетинг внутри ПромоСтраниц = режим «показывать выбранной аудитории» на сегменте читателей/посетителей; ретаргетинг **в Директе/РСЯ** по тем, кто читал статью, — через пиксели и сегменты Аудиторий. Специального раздела «Ретаргетинг» в справке по кампании нет. [справка; [в источниках нет] отдельного раздела]
- «Ключевые фразы/запросы» как отдельный таргет вне Поиска в справке не описаны. Kokoc упоминает «интересы и ключевые фразы» среди ручных сегментов; для РСЯ подтверждения в справке нет. [практики, не проверено; в справке только автотаргетинг по запросам на Поиске]
- Состав наших аудиторий записан в `Клиенты/Франшиза Мокрый Нос Дзен/Аудитории/audiences.md`: файл пуст (шаблон). Есть ли в кампаниях сегменты Аудиторий, из названий не видно («рся» в названии = место показа, не сегмент). Пробел: скриншот блока «Сегменты» у 2602-1.
- Правило использования: если сегмент нужен для look-alike, он должен быть точным: «аудитория сегмента должна включать только тех, кто интересуется вашим продуктом» — иначе эффективность падает. [справка]

## Поиск: автотаргетинг по запросам

Подробнее в [[Promopages-площадки-и-бюджет]]. Для таргетингов важно: на Поиске нужно заполнить минус-фразы и выбрать упоминание бренда; нельзя копировать списки минус-фраз из рекламы на Поиске (запросы, неэффективные там, здесь могут быть целевыми); нельзя ставить в минусы бренд и слова из заголовка. [справка: `advertising-show`] Среди наших кампаний Поиск стоит у четырёх: три только `search` (в названиях `#tgbot`, `2510-1`, `2607-1`, то есть 2026 год) и одна `rsya`+`search` (старая «Цена перехода / Ж25-54 / интерес_открытие бизнеса»); содержимое минус-фраз и выбор «упоминание бренда» у нас не записаны, API их не отдаёт. [наши данные]

## Что уточнить у пользователя / в кабинете

1. Скриншоты блока «Таргетирование» кампании 2602-1: гео, расширенное гео, устройства, места показа, интересы (какой список), сегменты, автотаргетинг.
2. Есть ли в аккаунте отдельный счётчик «Метрика публикаций» (читатели) и подключён ли счётчик сайта 66145201 к разделу «Статистика» с атрибуцией «первый переход».
3. Стоят ли макросы `{region_name}`, `{device_type}`, `{interest}` в UTM ссылок (скриншот «UTM-метки → Изм»).
