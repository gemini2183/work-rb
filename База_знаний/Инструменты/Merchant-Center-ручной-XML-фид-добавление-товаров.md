# Merchant Center: добавление товаров в ручной XML-фид

Источник знания: прямая проверка на реальном кабинете
[[../../Клиенты/EkspertAgro/Мерчант/index|EkspertAgro — Мерчант]] (серия
скриншотов источника `google_merchant_feed_new.xml`), не пересказ внешних
статей. **Статус — протестировано** в части UI-механики загрузки; сам процесс
формирования содержимого XML-файла (кто и как правит товары до загрузки) для
этого клиента ещё не выяснен отдельно.

## Как распознать этот тип источника

В "Источники данных о товарах" → карточка источника показывает:

- **Тип: "Файл (вручную)"** — ключевой признак. Означает, что Google НЕ
  забирает файл сам ни по URL, ни по SFTP-расписанию — файл нужно
  загружать руками через интерфейс.
- Рядом с этим типом всё равно присутствуют кнопки **"Обновить"** и
  **"Обновить через SFTP"** — они ведут к двум разным механизмам (см. ниже),
  и наличие кнопки SFTP не означает, что SFTP реально настроен и
  используется.
- На вкладке "Настройки источника данных" → "Показать дополнительные
  параметры" — если там нет полей адреса/пути SFTP-сервера (только
  разделитель, кодировка, кавычки, валюта, правило для идентификатора), то
  расписание получения через SFTP не настроено, и реальный путь загрузки —
  ручной.

## Как подготовить актуальный XML

Два варианта, в зависимости от того, откуда для конкретного клиента берутся
товары:

- **Автоматическая сборка скриптом** (рекомендуется для EkspertAgro) —
  `Скрипты/merchant_feed_ekspertagro.py` собирает актуальный каталог прямо
  с сайта клиента (Tilda-магазин) через headless-браузер и строит корректный
  XML с нуля, не полагаясь на ручную правку старого файла. Подробности и
  обоснование — `Скрипты/README.md`, раздел "Сборка Merchant Center фида с
  сайта", и [[../../Клиенты/EkspertAgro/Мерчант/Решения|Решения — EkspertAgro (Мерчант)]],
  запись 2026-09-22 (там же — конкретные цифры расхождений, которые показали,
  что ручная правка старого файла ненадёжна: 100 из 121 общих товаров были с
  устаревшей ценой).
- **Ручная правка XML** — взять текущую версию (или получить от того, кто её
  ведёт) и добавить новые `<item>` с обязательными полями: `g:id`, `title`,
  `description`, `link`, `g:image_link`, `g:availability`, `g:price` (валюта
  не задана по умолчанию — указывать явно в каждой строке, например
  `100.00 PLN`), `g:condition`, `g:gtin` или `g:mpn`+`g:brand`,
  `g:google_product_category`. Подходит для разового точечного добавления
  1-2 товаров, не для регулярного обновления всего каталога — риск
  разойтись с реальными ценами на сайте растёт с каждым циклом ручной правки.

## Загрузка готового XML в Merchant Center

1. Открыть источник данных → вкладка **"Настройки источника данных"** —
   убедиться, что это "Файл (вручную)".
2. Подготовить обновлённый XML-файл — см. раздел выше.
3. Нажать синюю кнопку **"Обновить"** (не "Обновить через SFTP" — та кнопка
   предназначена для случая, когда файл реально лежит на SFTP-сервере
   Merchant Center и его нужно просто перечитать, что не тот сценарий).
4. В диалоге "Выберите файл для загрузки" — перетащить/выбрать новый XML.
   Есть чекбокс **"Загрузить файл в тестовом режиме"** — полезно включать
   при первой проверке структуры/атрибутов нового файла, чтобы новые товары
   не начали показываться до проверки точности данных.
5. Нажать "Загрузка".
6. Проверить результат на вкладке "Последнее обновление" — там отдельно
   показывается счётчик **"Добавлено новых товаров"** (в отличие от
   "Всего обновлено товаров" — это число включает и уже существующие
   позиции, которые просто обновились по атрибутам).

## Важные нюансы

- Кнопка "Обновить через SFTP" здесь, скорее всего, нерелевантна — это
  отдельный путь для источников, где расписание получения файла настроено
  через SFTP (адрес/логин видны в дополнительных параметрах). Если этих
  полей нет — используется только ручная загрузка.
- Максимальный размер файла — 4 ГБ, форматы — `.txt` (с разделителем
  табуляцией), `.xml`, `.tsv`.
- Не путать этот ручной источник с автоматическим источником "Найдено
  Google" (сканирование сайта по schema.org/Open Graph) — это два
  независимых механизма добавления товаров в один и тот же Merchant Center
  аккаунт, с разной логикой обновления. См. запись в
  [[../../Клиенты/EkspertAgro/Мерчант/Решения|Решения — EkspertAgro (Мерчант)]].

## Исходная копия старого файла и её актуальность

Копия старого ручного файла (131 товар, загружен 19.12.2025) лежит в
`Клиенты/EkspertAgro/Мерчант/google_merchant_feed_new.xml` — историческая
версия, не использовать как базу для новых товаров. Сверка со свежим
каталогом с сайта (153 товара, собраны скриптом) показала: 100 из 121
общих товаров разошлись по цене, 10 пропали с сайта, 32 новых появились.
Изначально было неизвестно, как формировалось содержимое этого файла
(пользователь предполагал, что собственным скриптом, но не помнил точно) —
вопрос закрыт: актуальный процесс теперь — `merchant_feed_ekspertagro.py`
(см. раздел выше), а не ручная правка этого файла.

**Пример из практики:** при первой сборке товар с ID 828228084394 на сайте
назывался "Copy: Szklarnia Domek Ekspert Mały 2,1x8m z poliwęglanem 6mm" —
незакрытый черновик/дубль клиента (попал в собранный фид как есть, скрипт
не фильтрует такие случаи автоматически). Клиент поправил название на
сайте в тот же день, повторная сборка забрала исправленную версию. Вывод:
скрипт добросовестно копирует то, что есть на сайте — проверять свежий
результат перед загрузкой всё равно стоит, особенно после ручных правок
каталога клиентом. См.
[[../../Клиенты/EkspertAgro/Мерчант/Решения|Решения — EkspertAgro (Мерчант)]],
запись от 2026-09-22.
