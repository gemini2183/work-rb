# RLSA: минимум списка для Search

## Что говорит Google
Источник: [About remarketing lists for search ads (Google Ads Help)](https://support.google.com/google-ads/answer/2701222?hl=en), страница открыта 2026-10-08.
- Сегмент посетителей сайта или пользователей приложения для рекламы в Поиске должен иметь **минимум 1000 cookie**, прежде чем его можно использовать для настройки рекламы в Поиске.
- Срок членства в списке — до 540 дней.
- Сегменты можно использовать для оптимизации ставок по существующим ключам и для ставок по ключам, которые обычно не используются, только для недавних посетителей (так сформулировано в справке; различие «наблюдение/таргетинг» на странице явно не описано).

## Что говорят практики
Источники: [hawksem](https://hawksem.com/blog/google-rlsa/), [webtonic](https://www.webtonic.io/blog/google-rlsa), [megadigital](https://megadigital.ai/en/blog/remarketing-lists-for-search-ads-rlsa/) (общие обзоры).
- Подтверждают порог 1000 для Поиска (для Display порог ниже, 100); список меньше порога получает статус «слишком мал для показа».
- Режим **наблюдения** (bid only): реклама показывается всем по ключам, для списка можно корректировать ставку. Режим **таргетинга**: ключи срабатывают только для пользователей списка, подходит для широких запросов, которые не покупаешь для незнакомых.
- Расхождений с официальной справкой нет.

## Важное для наших кампаний (из базы знаний)
- На Smart Bidding (tCPA, Maximize conversions) процентные корректировки ставок по аудиториям не применяются (см. [[Google-Ads-Smart-Bidding-и-корректировки-ставок]]), поэтому в `Poliweglan` список в наблюдении даёт отчётность и сигнал, а не ставку.
- Размер списка в Search — отдельная цифра (`size_for_search`), у Display она больше.

## Размеры списков ProfiMet на 2026-10-08 (Search / Display)
| Список | Search | Display | Годен для Search (≥1000) |
|---|---|---|---|
| GA4 корзина 60 дн. | 270 | 960 | нет |
| GA4 корзина 45 дн. | 96 | 380 | нет |
| GA4 корзина 30 и 14 дн. | 0 | 16 | нет |
| `user_engagement` 30 дн. | 690 | 1900 | нет |
| `engage_mid` | 600 | 1000 | нет |
| `60sec` 30 дн. | 2000 | 2800 | да |
| `60sec` 14 дн. | 830 | 1600 | нет |
| CRM-покупатели | 11 000 | 10 000 | да (используется как исключение) |

Вывод: Search-ретаргет по корзине сейчас невозможен (270 < 1000); из рабочих сегментов вовлечённости порог проходит только `60sec` (30 дн.). Размеры округлены, источник — API (`size_for_search`).
