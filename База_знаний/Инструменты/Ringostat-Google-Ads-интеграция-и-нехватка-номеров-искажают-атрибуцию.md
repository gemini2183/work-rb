# Ringostat↔Google Ads: интеграция только "тянет расходы", не "заливает конверсии"; нехватка номеров искажает привязку

Найдено внешним поиском (help.ringostat.com) при разборе задачи [[../../Клиенты/ProfiMet/index|ProfiMet]]
(сверка звонков Ringostat vs конверсии Google Ads, разрыв найден по GA4
Data-Driven Attribution — см. [[../../Клиенты/ProfiMet/Решения|Решения]],
запись 2026-09-21).

## Интеграция Ringostat → Google Ads — однонаправленная, только расходы

Официальная документация ([Integration with Google Ads](https://help.ringostat.com/en/articles/6515419-integration-with-google-ads))
описывает ТОЛЬКО один поток данных: Ringostat импортирует расход (Cost/CPPC)
ИЗ Google Ads в свою аналитику, обогащая отчёты Ringostat метриками стоимости.
**Обратного направления — выгрузка звонков как офлайн-конверсий обратно в
Google Ads через gclid / Click Conversion Upload API — в документации не
описано вообще.** Значит идея "настроить у Ringostat офлайн-импорт
конверсий по gclid, чтобы обойти атрибуцию GA4" (см. Решения ProfiMet,
альтернативные варианты устранения разрыва) технически нереализуема как
"включить готовую функцию сервиса" — при необходимости такой связки её
пришлось бы строить полностью самостоятельным кодом (сохранять `gclid` при
визите на сайт → сопоставлять со звонком на стороне Ringostat или своего
скрипта → грузить через Google Ads API `ClickConversionUploadService`),
не как настройку в кабинете Ringostat.

Сопоставление визита с `gclid` при этом Ringostat всё же делает — но только
для внутренних целей самой этой интеграции (сведение расходов), не для
экспорта конверсий: "Synchronization occurs based on GCLid... when ads are
not marked with UTM tags". Если gclid визита не пойман — расход
"размазывается" равномерно по всем gclid этой кампании, чтобы баланс
расходов между системами не разъезжался; это относится к точности
ВНУТРЕННЕЙ статистики расходов Ringostat, не к передаче конверсий наружу.

**Важное следствие для звонков по номеру в объявлении (статический канал,
без визита на сайт):** "If Ringostat has no visits from a certain
advertising campaign, but Google Ads does, Ringostat will not show any
expenses" — то есть Ringostat как система "заточен" под визиты сайта;
чисто звонковые кампании/каналы (человек звонит по номеру в объявлении,
не заходя на сайт) для него во многом слепая зона за пределами самого
факта звонка.

Также отдельно подтверждено: импорт расходов из Google Ads Discovery-кампаний
временно не поддерживается (пока Google не добавит нужный метод API) —
не относится напрямую к звонкам/конверсиям, но стоит иметь в виду при любой
сверке расходов, не только конверсий.

## Нехватка номеров в пуле динамической подмены — официально подтверждённый источник ошибочной привязки

Найдено ([Нехватка номеров](https://help.ringostat.com/ru/articles/6216036-%D0%BD%D0%B5%D1%85%D0%B2%D0%B0%D1%82%D0%BA%D0%B0-%D0%BD%D0%BE%D0%BC%D0%B5%D1%80%D0%BE%D0%B2)):
когда трафик растёт, а число номеров в пуле динамической подмены не
увеличено вслед за ним, **"нескольким посетителям может отображаться один и
тот же номер одновременно, что приведёт к сбору некорректной статистики"**.
Это прямая цитата официальной базы знаний, не домысел/экстраполяция.

Цветовая индикация нехватки на пул (в интерфейсе, раздел с числом
"Номеров в пуле"/"Рекомендовано номеров"):
- **Серый** — недостаточно накопленной статистики, чтобы посчитать
  рекомендацию.
- **Зелёный** — номеров достаточно, действий не требуется.
- **Синий** — номеров больше, чем нужно (запас ~25%).
- **Жёлтый** — номеров недостаточно (дефицит ~20%), рекомендуется
  подключить ещё.
- **Красный** — регулярно фиксируются периоды нехватки (дефицит больше 20%).

**Не подтверждено официальным источником (логическое предположение, не
факт из документации):** какой именно кампании/UTM-контексту в итоге
засчитывается звонок при коллизии (когда два разных посетителя получили
один и тот же номер, а позвонил только один из них) — гипотеза "звонок
присваивается последней сессии/контексту, ассоциированному с этим номером
на момент звонка" правдоподобна логически, но статья не раскрывает
внутренний механизм разрешения такой коллизии. Требует уточнения у
поддержки Ringostat, если понадобится точный ответ, а не предположение.

## Практическое следствие для сверки звонков Ringostat vs Google Ads

Это даёт минимум ДВА независимых, не пересекающихся источника
расхождения между "сколько звонков реально было" и "сколько корректно
атрибутировано в Google Ads":
1. GA4 Data-Driven Attribution может отдать 0% кредита каналу Cross-network
   (Performance Max) в пользу других точек касания в пути — см.
   [[../../Клиенты/ProfiMet/Решения|Решения — ProfiMet]], запись 2026-09-21.
2. Нехватка номеров в пуле динамической подмены может физически перепутать,
   какому посетителю/кампании принадлежит звонок, ещё до того, как данные
   вообще попадают в GA4/Google Ads — ошибка на уровне самого коллтрекинга,
   не атрибуции.

При расследовании подобных разрывов у любого клиента с Ringostat — проверять
ОБА источника независимо, не останавливаться на первом найденном объяснении.
