# GTM: сохранение UTM в браузере для заявок с формы

## Проблема
Тег записи заявки читал `utm_source/medium/campaign` из адреса страницы в момент отправки формы (переменные «URL → Запрос»). Сайт многостраничный, внутренние ссылки метки не несут, поэтому при отправке на другой странице метки пусты. Кейс ProfiMet (Supabase `profimet_leads`, 12.09–12.10): 64 настоящие заявки, 40 (62%) без UTM, доля стабильна по неделям; ещё ≈ 270 строк-пачек без UTM и телефона (одно срабатывание по нескольким формам), телефон пуст в 100% строк.

## Решение (контейнер ProfiMet GTM-TKGN4NT, версия 62)
1. Новый тег Custom HTML на All Pages: если в адресе есть `utm_*` или `gclid`, пишет их в `localStorage['rb_utm']` с меткой времени. Срабатывает только при согласии `ad_storage` (как у соседних GA4-тегов).
2. Тег записи заявки: метки берутся из адреса, а если пусто — из `rb_utm` (срок 30 дней).
Остальное в теге не менялось.

## Согласие
Сохранение меток в браузере — доступ к устройству; для маркетинговых целей по ePrivacy обычно нужно согласие. Поэтому тег требует `ad_storage`; без согласия остаётся прежнее поведение (метки только из адреса). Обход «только для Supabase» не рекомендован: риск несёт клиент; юридической оценки не даём, вопрос клиенту или DPO. Вариант без хранения на устройстве: переносить метки во внутренних ссылках сайта (правка Tilda, не проверено).

## Как сделано
Через API Tag Manager сервисным аккаунтом с правами редактора и публикации: новая рабочая область → правки → `quick_preview` (проверка сборки) → версия → публикация только по явному «да». Читающий `Скрипты/gtm_read_container.py` работает с областью `tagmanager.readonly`; для правок нужны области `tagmanager.edit.containers`, `tagmanager.edit.containerversions`, `tagmanager.publish`. Откат: опубликовать предыдущую версию (61).

## Проверка после публикации
Открыть сайт с `?utm_source=test&utm_medium=cpc&utm_campaign=test_utm` → `localStorage.rb_utm` содержит метки; через 2–3 дня доля заявок без UTM среди «настоящих» ниже 62% (часть без согласия останется). Тестовую отправку формы не делать: отправка идёт в CRM клиента.

## Ловушка: тег по согласию на All Pages (проверено 27.10.2026 в браузере на живых контейнерах)
Тег требует `ad_storage`, а триггер «All Pages» срабатывает один раз при загрузке страницы. Если сайт задаёт согласие по умолчанию `denied` и показывает баннер (ProfiMet), то у нового посетителя в момент загрузки согласия нет → тег не срабатывает; нажатие «принять» на этой же странице тег не перезапускает → `rb_utm` пуст, а на следующей странице меток в адресе уже нет. Пишет только посетитель, который согласился раньше и пришёл по рекламной ссылке повторно.
- ProfiMet (mocnaszklarnia.pl): все типы согласия `denied`; заход с метками → `rb_utm` пуст; `consent update` после загрузки → пуст; клик «Zaakceptuj wszystkie» на стартовой → пуст; вернувшийся с уже принятым согласием + метки → записано.
- ExpertAgro (ekspertagro.pl): согласие не задано (`undefined`), окна согласия за 6 с загрузки не видно (в подвале только ссылки «Polityka cookie», систем согласия Cookiebot/OneTrust и др. нет; показ по гео или по таймеру не проверялся) → тег срабатывает всегда, `rb_utm` пишется. Поэтому «тот же тег» там работает: различие не в теге, а в состоянии согласия сайта. Это заодно значит, что у ExpertAgro метки хранятся без согласия посетителя (юридически — вопрос клиенту).
- Баннер ProfiMet при принятии кладёт в dataLayer событие `consentTypeSelected` (триггер 85 в контейнере уже есть, на нём висит «Banner - Set Update Accepted»).
- Исправление, которое НЕ работает (проверено 27.10, версия 90): повесить тег на то же событие баннера. GTM решает, какие теги запускать, в начале события, а согласие тег баннера выдаёт внутри этого же события, поэтому тег с условием согласия блокируется (приоритет тега баннера не помогает).
- Исправление, которое работает (версия 91, тест пройден, не опубликовано): новый тег на событии баннера кладёт в dataLayer следующее событие `rb_consent_selected`; тег «по согласию» вешается на него. Проверка: «принять все» → `rb_utm` записан; «только необходимые» и без клика → пусто; после ухода на другую страницу метки уходят в Supabase. Скрипт `Скрипты/gtm_consent_retrigger.py`. Годится для любого тега «по согласию», который должен сработать сразу после выбора в баннере.
Проверка воспроизводима: `Скрипты/gtm_utm_persist_probe.py <сайт> banner|update|accept|returning|events` (только чтение, отправки в GA/Supabase перехватываются).
