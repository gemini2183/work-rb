# Приоритет каналов и доля бюджета (Channel prioritization & budget allocation)

Источники (открыты 2026-10-19): справка Google Ads
[answer/18385152](https://support.google.com/google-ads/answer/18385152), блог Google
(blog.google/products/ads-commerce/channel-prioritization-budget-allocation), разборы
PPC Land и Relevant Audience (цитируют Ginny Marvin, Ads Liaison). Справка и блог читались через
пересказ инструмента, не дословно; расхождения источников — ниже. **На наших кампаниях не проверено.**

## Что это
Два необязательных контроля вместо «включено/выключено» для сетей:
1. **Приоритет канала:** High (по умолчанию у всех) или Low. High финансируется первым (в рамках tCPA/tROAS),
   остаток уходит в Low.
2. **Доля бюджета (только для Low):** процент от *среднего дневного бюджета*, «лучшее усилие», не жёсткий потолок.
   5% от $1000 ≈ $50/день. Сбрасывается каждый день, остатки не переносятся. 0% = «Google не будет тратить».

## По типам кампаний
| Тип | Каналы | Доля бюджета |
|---|---|---|
| Search | Google Search, партнёры поиска (SPN), КМС (GDN) — по отдельности | да |
| Shopping | Google Search, SPN | да |
| PMax | «Google-каналы» одним пакетом (Search, YouTube, Maps, Gmail, Discover), SPN и GDN отдельно | да |
| Demand Gen | Google-каналы, GDN | **нет** |

Уровни настройки: аккаунт (карточка «Channel Prioritization» в Account settings), кампания, общий бюджет.

## Ограничения (справка)
- Не применяется к кампаниям с **общим (total) бюджетом кампании** (кроме Demand Gen).
- **Нельзя задать из менеджерского аккаунта** — только внутри клиентского аккаунта/кампании.
- Общие бюджеты: только кампании одного типа, пул считается целиком.
- Эксперименты: можно в custom experiments; все каналы эксперимента в одном приоритете.
- tCPA/tROAS/tCPC **без** упора в бюджет: приоритет почти ничего не меняет, работает только доля для Low.
  Max Conversions/Value, Max Clicks, Manual CPC: High тратит первым, остаток — в Low.
- YouTube/Discover/Gmail/Maps в PMax отдельно от Search **не отделить** (общий «Google-каналы»).

## Display Expansion — срок Февраль 2027
Search-кампании с включённой Display-сетью автоматически переводятся на новую систему, старое распределение
исчезает, расход может сместиться. Сохранить как есть: GDN = Low + доля 50%. GDN перестанет работать в Search с
Target Impression Share. Кампании, где приоритеты заданы раньше, переходят сразу.

## Расхождения источников (не выбирать молча)
- **API:** справка (18.10): «coming soon» для API и Editor; Marvin: «поддерживается через API на запуске». Названий
  полей/версии нет ни в одном источнике.
- **Общие бюджеты и PMax:** справка — несовместимо; Marvin — «полностью совместимо».
- **Темп:** справка — с 15.10 постепенно; Marvin — «недели»/«месяцы». Раньше PMax-отключение партнёров было пилотом.

## Что проверено у нас (2026-10-19)
- **API:** `GoogleAdsFieldService` в v23 и v26 (библиотека google-ads 34.0.0) на слова `priorit`/`allocation`:
  единственное поле — `campaign.shopping_setting.campaign_priority` (старый приоритет Shopping, не про это).
  Релиз-ноты API v26 (14.10) эту функцию не упоминают. **Записать через API пока нельзя.**
- **Интерфейс:** Account settings ProfiMet (755-278-1705): карточки «Channel Prioritization» нет.
  Уровень кампании в интерфейсе не проверен (прямая ссылка на настройки кампании не отрисовалась).
  Остальные аккаунты в интерфейсе не открывались.
- Инструмент: `Скрипты/gads_channel_audit.py` (только чтение) — проба полей + где включены SPN/GDN + расход
  по `segments.ad_network_type` за 30 дней.

## Оценка
- **Полезно:** мягкая замена «выключить сеть» (PMax GDN/SPN раньше выключался только в пилоте); безопасный тест
  расширения на сети с лимитом; возможность проверить в custom experiment.
- **Ограничения:** «лучшее усилие»; не отделяет YouTube/Discover от Search в PMax — а именно там у ProfiMet и
  Корогвы основной расход; нет доли у Demand Gen; нельзя из MCC; нет отчёта «по каналам» в справке (меряем сами по
  `ad_network_type`).
- **Для нашего портфеля сейчас:** польза малая — утечка в GDN/SPN уже почти нулевая везде, кроме EkspertAgro PMax.
