# Tilda: передача UTM из формы в CRM

## Что известно из официальной справки Tilda (help.tilda.cc/formswebhook, прочитано 2026-10-20)
- UTM **не приходят отдельными полями** webhook. Они лежат внутри поля `COOKIES`, и только если у webhook включена опция «Send cookies» («Передавать cookies»); значение вида `TILDAUTM=utm_source…|||utm_medium…`. Если посетитель с UTM-ссылки вернулся не позднее чем через 30 дней, метки в cookie есть; у посетителя без cookie поля `COOKIES` нет.
- Поля формы приходят парами `имя=значение`; у поля с заданным «именем переменной» это имя и уходит в webhook (`customnamefield=yellow`). Страница отправки — не поле Tilda, а `HTTP_REFERER` получателя.
- Поддержка Tilda не помогает с кастомным кодом (по результатам поиска; справка не описывает автозаполнение скрытых полей — **не проверено**).

## Что нашли на ProfiMet (mocnaszklarnia.pl, 2026-10-20)
- На странице три формы Tilda (две заявочные и корзина). Скрытые поля в каждой: `formservices[]` (id служб), `tildaspec-formname`, `tildaspec-elemid`, `tildaspec-phone-part[]-iso`, `Phone`/`phone`, `ga_client_id`. **Полей `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid` нет.**
- Tilda ставит cookie `TILDAUTM` при заходе с UTM даже без согласия на cookie (проверено в чистом браузере); в `localStorage` ничего (тег GTM «UTM - сохранить в браузере» требует `ad_storage`).
- GTM-TKGN4NT (живая версия 81): тег «UTM - сохранить в браузере» хранит метки в `localStorage.rb_utm`; «Supabase - Leads» берёт метки из адреса или из `rb_utm`. **Тега, который заполняет поля формы Tilda для CRM, нет.**
- Доля форм без метки в CRM по месяцам: июнь 16%, август 21%, сентябрь 67%, октябрь 53% (неделя с 31.08 — 88%): резкий рост совпадает с полной пересборкой сайта 31.08; со слов пользователя, в старой версии в формы были добавлены скрытые поля для всех UTM. Инструкции по этим полям в вики не нашлось.

## План восстановления (по одному шагу, с проверкой без отправки формы)
1. **Tilda:** в каждую из трёх форм добавить скрытые поля с точными «именами переменной» `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid` (имена совпадают с колонками выгрузки CRM; **уточнить у того, кто делал интеграцию с CRM, какие имена она читает**), опубликовать страницы.
2. **Проверка автозаполнения** (форму не отправлять): открыть сайт с `?utm_source=test&utm_medium=cpc&utm_campaign=test` и прочитать значения `input[name=utm_source]` в DOM. Заполнены — дальше шаг 4; пусты — шаг 3.
3. **GTM:** тег Custom HTML, который при загрузке страницы и перед отправкой формы заполняет эти скрытые поля из адреса, затем из cookie `TILDAUTM`, затем из `localStorage.rb_utm` (последнее — при согласии). Правка контейнера — по нашему протоколу: черновик → `gtm_test_version.py` → «да» → публикация.
4. **Измерение:** через 3–5 дней доля форм без метки в CRM (выгрузка) и сопоставление с GA4 по минуте; ожидание — возврат к 16–21%.
Альтернатива без скрытых полей: включить «Send cookies» у webhook и научить скрипт CRM разбирать `TILDAUTM` из `COOKIES` (решает разработчик CRM).

## Согласие
`TILDAUTM` — собственный cookie Tilda; чтение его и адреса новых данных на устройстве не создаёт. Хранение в `localStorage` — только по `ad_storage` (как в [[GTM-сохранение-UTM-в-браузере-для-форм]]). Юридическую оценку не даём, вопрос клиенту.
