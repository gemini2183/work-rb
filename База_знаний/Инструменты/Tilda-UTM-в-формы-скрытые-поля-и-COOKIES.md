# Tilda: передача UTM из формы в CRM

## Что известно из официальной справки Tilda (help.tilda.cc/formswebhook, прочитано 2026-10-20)
- UTM **не приходят отдельными полями** webhook. Они лежат внутри поля `COOKIES`, и только если у webhook включена опция «Send cookies» («Передавать cookies»); значение вида `TILDAUTM=utm_source…|||utm_medium…`. Если посетитель с UTM-ссылки вернулся не позднее чем через 30 дней, метки в cookie есть; у посетителя без cookie поля `COOKIES` нет.
- Поля формы приходят парами `имя=значение`; у поля с заданным «именем переменной» это имя и уходит в webhook (`customnamefield=yellow`). Страница отправки — не поле Tilda, а `HTTP_REFERER` получателя.
- Поддержка Tilda не помогает с кастомным кодом (по результатам поиска; справка не описывает автозаполнение скрытых полей — **не проверено**).

## Что нашли на ProfiMet (mocnaszklarnia.pl, 2026-10-20)
- На странице три формы Tilda (две заявочные и корзина). Скрытые поля в каждой: `formservices[]` (id служб), `tildaspec-formname`, `tildaspec-elemid`, `tildaspec-phone-part[]-iso`, `Phone`/`phone`, `ga_client_id`. **Полей `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid` нет.**
- Tilda ставит cookie `TILDAUTM` при заходе с UTM даже без согласия на cookie (проверено в чистом браузере); в `localStorage` ничего (тег GTM «UTM - сохранить в браузере» требует `ad_storage`).
- GTM-TKGN4NT (живая версия 81): тег «UTM - сохранить в браузере» хранит метки в `localStorage.rb_utm`; «Supabase - Leads» берёт метки из адреса или из `rb_utm`. **Тега, который заполняет поля формы Tilda для CRM, нет.**
- Доля форм без метки в CRM по месяцам: июнь 16%, август 21%, сентябрь 67%, октябрь 53% (неделя с 31.08 — 88%): резкий рост совпадает с полной пересборкой сайта 31.08; со слов пользователя, в старой версии в формы были добавлены скрытые поля для всех UTM. Инструкции по этим полям в вики не нашлось.

## План восстановления (по одному шагу, с проверкой без отправки формы)
1. **Tilda:** в каждую из трёх форм добавить скрытые поля с точными «именами переменной» `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid` (имена совпадают с колонками выгрузки CRM; **уточнить у того, кто делал интеграцию с CRM, какие имена она читает**), опубликовать страницы.
2. **Проверка автозаполнения** (форму не отправлять): открыть сайт с `?utm_source=test&utm_medium=cpc&utm_campaign=test` и прочитать значения `input[name=utm_source]` в DOM. Заполнены — дальше шаг 4; пусты — шаг 3.
3. **GTM:** тег Custom HTML, который при загрузке страницы и перед отправкой формы заполняет эти скрытые поля из адреса, затем из cookie `TILDAUTM`, затем из `localStorage.rb_utm` (последнее — при согласии). Правка контейнера — по нашему протоколу: черновик → `gtm_test_version.py` → «да» → публикация.
4. **Измерение:** через 3–5 дней доля форм без метки в CRM (выгрузка) и сопоставление с GA4 по минуте; ожидание — возврат к 16–21%.
Альтернатива без скрытых полей: включить «Send cookies» у webhook и научить скрипт CRM разбирать `TILDAUTM` из `COOKIES` (решает разработчик CRM).

## Согласие
`TILDAUTM` — собственный cookie Tilda; чтение его и адреса новых данных на устройстве не создаёт. Хранение в `localStorage` — только по `ad_storage` (как в [[GTM-сохранение-UTM-в-браузере-для-форм]]). Юридическую оценку не даём, вопрос клиенту.

Связано: [[GTM-сохранение-UTM-в-браузере-для-форм]], `Клиенты/ProfiMet/Решения.md` (20.10.2026, «Метки у форм»).

## Проверка cookie TILDAUTM на живом сайте ProfiMet (2026-11-05, чистый браузер)
- Ставит сам скрипт Tilda на странице при заходе с `utm_*` в адресе. Без согласия на cookie. Первая сторона (`mocnaszklarnia.pl`), живёт 30 дней, `Secure` и `HttpOnly` нет (JS страницы читает), `SameSite=Lax`.
- Формат `utm_source=…|||utm_medium=…|||utm_campaign=…|||` (+ `utm_content`, если был). Значения приводятся к нижнему регистру (`A` → `a`). Нет `gclid`, `fbclid`, `gbraid`, `wbraid`: заход только с `gclid` cookie не создаёт и не меняет.
- Держится между страницами сайта (переход на `/ofirmie` без меток — cookie на месте). Новый заход с другими `utm_*` перезаписывает старые целиком (последний источник побеждает), заход без меток не стирает.
- Расширить настройками Tilda нельзя (сама cookie — код Tilda); рядом можно хранить свою cookie/`localStorage` — это уже наш тег GTM.
- Каким путём метки попадают в выгрузку CRM, не проверено: по справке Tilda — через поле `COOKIES` при включённой опции «Send cookies» у webhook (скрытых полей `utm_*` в формах нет). Проверить: настройки webhook в Tilda или сырой запрос в CRM.

## Откуда метки в выгрузке и почему их нет у половины форм (ProfiMet, проверено 2026-11-05 на таблице заявок Tilda)
- Таблица заявок Tilda (`Tilda_Leads_…`, лист «Лист1», 193 строки): колонки только `Imię_Nazwisko, Miasto, Adres, Kod_pocztowy, phone, Wiadomość, ga_client_id, orderid, paymentid, products, price, Currency, referer, formid, Form name, sent, requestid`. **Колонок `COOKIES`, `utm_*`, `gclid` нет**, то есть `TILDAUTM` в эту интеграцию не приходит (опция «Send cookies» не включена или таблица её не получает; настройку webhook не видели).
- Метка источника видна только в `referer` — адресе страницы в момент отправки. С 01.09: 176 форм, метка в адресе у 80. На главной `/` метка есть у 77 из 138; на остальных страницах (каталог, карточки товара, «О фирме») у 3 из ~38. Отправка с внутренней страницы = метка потеряна: внутренние ссылки меток не несут.
- В адресе встречаются `utm_source` (74 строки), `fbclid` (5), `gbraid` (1); `gclid` в этой выгрузке отдельно не считали.
- В CRM метка наследуется, судя по цифрам, оттуда же: Tilda 44 с меткой → CRM 40 (потери 3), у форм без метки в адресе CRM метку не показывает ни у одной (`Паттерны/Потери-форм-Tilda-Supabase-GA4-CRM.md`). Как именно CRM получает метку (из `referer` или другим путём), не проверено.
- Чинится двумя путями: включить «Send cookies» у webhook (дают `utm_*` до 30 дней, без click-id) и/или наш тег GTM, заполняющий скрытые поля / колонки Supabase из `rb_utm`, `TILDAUTM` и адреса.

## Причина найдена по скриншотам Tilda (2026-11-05)
- Интеграция «Сервис приёма данных Google.Sheet» (таблица `Tilda_Leads_16901306960_20260831130547`, имя содержит дату создания 31.08.2026 13:05): «Посылать Cookies» и «Посылать UTM» **выключены**; «Отправлять только после оплаты» выключено. Поэтому в таблице нет колонок `utm_*`, есть только `referer`.
- Внутренний список «Заявки из форм» в Tilda (форма Cart, 04.11.2026) показывает `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`: Tilda метки хранит и видит, наружу не отдаёт.
- Совпадение дат: интеграцию заново создали 31.08, в этот же день доля форм без метки в выгрузках выросла с 16–21% до 53–67% (связь по датам, не доказана: старые настройки до пересоздания не видели).
- Не проверено: настройки интеграции Tilda → CRM клиента (отдельная, скрин не получен); попадёт ли `gclid` в «Посылать UTM» (справка Tilda говорит про utm-поля).
- «Посылать Cookies» не включать: уйдёт вся строка cookie (в том числе идентификаторы аналитики), нужен только `utm_*`.
