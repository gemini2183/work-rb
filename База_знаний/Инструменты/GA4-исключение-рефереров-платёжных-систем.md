# GA4: конверсии "приписываются" платёжному шлюзу (referral hijacking)

## Симптом

В отчёте GA4 (Трафик по источникам/каналам) весь или почти весь объём ключевых
событий (конверсий) числится за источником вида `pay.monobank.ua / referral`
(или аналогичным доменом другой платёжной системы), независимо от того,
откуда реально пришёл пользователь (реклама, органика, прямой заход).

Пример (клиент [[../../Клиенты/Корогва/index|Корогва]], 2026-09-08): 45 из 45
событий `custom_purchase` (100%) приписаны `pay.monobank.ua / referral`.

## Механизм

Стандартная связка "оплата на стороннем домене платёжной системы":

1. Пользователь заходит на сайт с рекламы/органики — GA4 фиксирует исходный
   source/medium в сессии.
2. В чекауте нажимает "оплатить онлайн" → браузер уходит на домен платёжного
   шлюза (`pay.monobank.ua` и т.п.) — **это уход на другой домен**.
3. После оплаты шлюз делает редирект обратно на сайт, на страницу
   "Спасибо за заказ" (где обычно и стреляет конверсионное событие).
4. GA4 по умолчанию не знает, что уход на этот домен и возврат с него —
   легитимный шаг оплаты, а не переход по внешней ссылке с чужого сайта.
   Он видит новый заход "с домена pay.monobank.ua" и **создаёт новую сессию**
   с этим источником, затирая исходный канал. Конверсия на странице
   "Спасибо" записывается уже в новую (реферальную) сессию.

## Как исправить

**Основной механизм — список нежелательных переходов (Unwanted referrals):**

GA4 → Администратор → поток данных (Веб) → Настроить тег (Configure tag
settings) → Показать все настройки → **"Создание списка нежелательных
переходов"** → добавить домен(ы) платёжных систем (`pay.monobank.ua`, и
любые другие шлюзы, если используется несколько — LiqPay, Portmone, Fondy
и т.д.).

Как работает: GA4 при построении сессии смотрит на реферер. Если домен
реферера — в списке нежелательных переходов, GA4 **не создаёт новую сессию**
и не переатрибуцирует источник, а сохраняет исходный source/medium через
переход.

**Дополняющий механизм — настройка доменов (Cross-domain measurement):**

Там же, в настройках тега — пункт **"Настройка доменов"**, чуть выше списка
нежелательных переходов. Стоит добавить туда те же домены платёжных систем.
Разница: список нежелательных переходов просто "не путает" источник задним
числом, а cross-domain measurement протаскивает клиентский ID (`_gl`
параметр) через сам redirect на шлюз и обратно, обеспечивая более полную
и надёжную склейку сессии как одного визита. Механизмы дополняют друг
друга, не взаимоисключающие — имеет смысл настроить оба.

Путь в интерфейсе подтверждён скриншотом пользователя 2026-09-08 (Admin →
Data Streams → поток → Configure tag settings → Show all → "Создание
списка нежелательных переходов" / "Настройка доменов").

## Ограничения

- Правило **не ретроактивное** — уже накопленные исторические конверсии,
  ошибочно приписанные платёжному домену, не переразметятся задним числом.
  Эффект будет виден только на новом трафике после настройки.
- Если на сайте несколько способов онлайн-оплаты (разные платёжные шлюзы),
  нужно добавить домен каждого, иначе часть конверсий продолжит утекать.
