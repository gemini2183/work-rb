# Tilda: события форм, форма-окно и триггеры GTM

Найдено на [[../../Клиенты/Andverpersonalinjury/index|Andverpersonalinjury]] (landverpersonalinjury.tilda.ws/california-car-accident-lawyer). Общее для сайтов на Tilda.

## Событие отправки формы
- Скрипт форм Tilda (`tilda-forms-1.0.min.js`, прочитан 2026-10-24) после успешной отправки делает `dataLayer.push({event: "submit_" + formId})`, где `formId` — атрибут `id` самого `<form>` (`form5114761803`, число = номер блока). То есть событие называется `submit_form5114761803`, а не `submit_form`.
- Триггер «пользовательское событие» с условием **регулярное выражение** `submit_form*` ловит все формы страницы (так настроено у Landver с 2026-08, подтверждено на форме A и окне B). Условие «равно `submit_form`» не сработало бы.
- Различать форму A (в потоке страницы) и окно B по событию ненадёжно (номера блоков меняются при пересборке). Надёжнее переменная JS «окно сейчас открыто»: `document.querySelector('.t-popup_show') ? 'popup' : 'inline'` (у Landver — `ldv form place`, параметр `form_place` у `form_submit`).
- Начало заполнения формы (аналог `form_start`, который GA4 на Tilda-формах не видит) — слушатель `focusin` на поля `form.t-form` (не `hidden`), один раз на форму; событие `ldv_form_start` в dataLayer.

## Форма-окно (блок T702) открывается только по своему хуку
- Окно помечено `data-tooltip-hook="#имя-хука"`. Открывается кликом по ссылке `href="#имя-хука"` (проверено: добавленная ссылка с хуком открыла окно, класс `t-popup_show`).
- **Якорь с другим именем окно не открывает.** У Landver кнопка «Get my free case review» вела на `#ldv-form-2` (пустой `<span>` высотой 0 в подвале): страница просто прокручивалась к подвалу, окно оставалось закрытым. Установка `location.hash = '#хук'` из кода окно тоже не открыла — только клик по ссылке.
- Проверка «битых якорей» по наличию элемента с таким `id` такой случай не ловит (элемент есть, но не ведёт никуда): смотреть, открывается ли форма на деле.

## Триггеры GTM, проверенные на Tilda
- **Видимость окна:** элемент по CSS `.t-popup[data-tooltip-hook="#хук"]`, частота «раз за страницу», доля 50%, **обязательно «следить за изменениями DOM»**: окно показывается переключением класса, без него триггер не срабатывает.
- **Прокрутка:** триггер «Scroll Depth», вертикальные пороги в процентах `25,50,75`, старт `WINDOW_LOAD`; значение — встроенная переменная `Scroll Depth Threshold` (её нужно включить). GA4 отдельно шлёт `scroll` на 90%, поэтому свой триггер дублирует только 25/50/75.
- **Вопросы FAQ в виде `<details><summary>`:** триггер «клик» с условием «Click Element соответствует CSS» `.блок-вопроса summary, .блок-вопроса summary *`; текст вопроса — `Click Element.closest('summary').innerText`. Клик по `summary` видится как обычный `gtm.click`.
- **Клик по номеру:** триггер «клик по ссылке» с условием `Click URL содержит tel:` ловит и динамически созданные кнопки (кнопка звонка в результате квиза). Место кнопки лучше брать из атрибута `data-…` самой ссылки (переживает правки вёрстки и подмену номера Ringostat, который меняет только внутренности и `href`).

## Подводные камни проверки
- После публикации версии контейнера `gtm.js` у Google ещё несколько минут отдаётся из кэша: первая проверка сразу после публикации может показать старую версию (так было у `faq_open` 2026-10-24: через несколько минут заработало).
- Проверка в временной среде GTM (`Скрипты/gtm_test_version.py`) надёжна для кликов по CSS-селекторам, сценариев квиза и имитации `submit_…`; режим «каждая ссылка `tel:` на отдельной загрузке» на этой странице событий не показал, хотя клики внутри одной загрузки проходили, — использовать `--click` с селектором каждой ссылки и `--no-tel-places`.
- Не проверено: реальная отправка формы (создаёт заявку у клиента) и приход события в Google Ads как конверсия.
