# Ringostat: механизм подмены номера

Найдено и проверено на практике при разработке `Скрипты/phone_swap_check.py` и
настройке коллтрекинга клиента [[../Andverpersonalinjury/index|Andverpersonalinjury]]
(подпроект Andverpersonalinjury, landverpersonalinjury.com). Общее знание о
том, как работает Ringostat — не специфично для этого клиента.

## Как задаётся правило подмены

В кабинете Ringostat, раздел "Каналы трафика" + "XPaths" + "Пулы номеров":

1. **Канал трафика** — условие по UTM (`utm_source`/`utm_medium`/`utm_term`/
   `utm_content`/`utm_campaign`), можно использовать `.*` как "любое значение".
   Пример: канал "Google Ads" = `utm_medium: cpc` (source/term/content/campaign
   — любые).
2. **Пул номеров** — список телефонных номеров, привязанный к каналу. При
   срабатывании канала Ringostat выдаёt посетителю **один номер ИЗ ПУЛА**, не
   обязательно один и тот же при каждом заходе — похоже на ротацию по
   сессии, не строгое отображение "1 UTM-комбинация = 1 фиксированный номер"
   (подтверждено эмпирически: два прогона с идентичным `utm_source=google&
   utm_medium=cpc` дали разные номера одного и того же пула — `+18883783267`
   и `+18883025461`, оба валидны для этого канала).
3. **XPath-правило** — где именно на странице искать элемент с номером,
   чтобы его подменить. Задаётся либо через упрощённый конструктор (выбор
   "Class"/"Text"/"Id" — Ringostat сам собирает XPath по одному атрибуту),
   либо через **"Manual mode"** — единственный режим, куда можно вставить
   произвольный составной XPath (с `and`/`not`/`contains` и т.п.).
4. **Маска** — шаблон вида `(###) #-LAWINJURY (######)`, где `#` — цифра,
   остальное — фиксированный буквенный/пунктуационный текст.

## Маска должна описывать ВЕСЬ текст элемента, не только номер

Подмена всегда заменяет **весь textContent найденного по XPath узла**, а не
вырезает и заменяет подстроку внутри существующего текста. Отсюда следует
не "point-replace невозможен", а обратное — **маска должна описывать текст
элемента целиком**, включая всё, что должно остаться неизменным, а не
только фрагмент с номером.

Первая попытка на hero-тексте landverpersonalinjury.com (короткая маска
`(###) #-LAWINJURY (######)`, только под сам номер, при XPath на весь
`<span>` с предложением) стёрла весь остальной текст, оставив только голый
номер — потому что Ringostat заменил весь textContent найденного узла на то,
что попало под маску, а остальной текст в маску просто не был включён.

**Рабочее решение** — задать маску как полный текст узла, с `###` только на
месте цифр номера, весь остальной текст — 1:1 как в оригинале (включая
пунктуацию и НЕ ASCII-символы вроде типографского апострофа `’`, не обычного
`'` — Playwright/DevTools нужно использовать, чтобы получить точный текст
узла, набор вручную рискует подставить не тот символ и сорвать совпадение).
Пример реального рабочего правила из кабинета клиента ("our office",
адресный блок офиса Beverly Hills — маска включает полный адрес +
"Phone: " + номер-шаблон, не только номер) подтверждает, что это штатный,
предусмотренный Ringostat способ, не костыль.

Проверено эмпирически на hero-тексте LA-страницы: маска
`Harmed in Los Angeles? Landver Law’s tenacious personal injury attorneys
pursue top compensation for injured residents across Los Angeles. You pay
nothing unless we recover. Call (###) ###-#### for a free consultation
today.` (без буквенного "LAWINJURY" — см. следующий раздел, почему его
намеренно убрали именно в этом правиле) при том же XPath, что и раньше,
подставила номер точечно, сохранив весь остальной текст предложения.

Значит **не требуется** править вёрстку/контент сайта, чтобы получить
точечную замену внутри длинного текста — правки на стороне Ringostat
(правильно составленная full-text маска) достаточно.

## Отсутствие публичного API для пулов и правил подмены

Проверено 2026-08-18 (документация help.ringostat.com, ringostat.readme.io):
у Ringostat есть публичный API для call log, сотрудников, webhooks — но
**нет** эндпоинта для выгрузки пулов номеров или правил подмены (Traffic
Channels / Insertion settings / XPaths). Это только UI кабинета.

Следствие: пул номеров и условия подмены для автоматической проверки
(`Скрипты/phone_swap_check.py`) приходится вести **вручную** по скриншотам
кабинета — нет единого источника правды между Ringostat и вики, нужно
актуализировать при каждом изменении настроек в кабинете.

## Vanity-номера: буквенная фраза в номере может не иметь смысла для всех номеров пула

Основной ("дефолтный") номер клиента часто подбирается как vanity number —
номер, чьи цифры соответствуют запоминающемуся слову на буквенной телефонной
клавиатуре (2=ABC, 3=DEF, 4=GHI, 5=JKL, 6=MNO, 7=PQRS, 8=TUV, 9=WXYZ).
Пример: `844-452-9465` кодирует `LAWINJURY` (буквы L,A,W,I,N,J,U,R,Y →
5,2,9,4,6,5,8,7,9 → `529465 87 9`, первые 6 цифр после кода города и "4"
совпадают со словом).

**Важно:** маска в Ringostat (`(###) #-LAWINJURY (######)`) отображает
фиксированный буквенный текст "LAWINJURY" **поверх любого номера пула**,
даже если реальные цифры этого конкретного номера с этими буквами вообще не
связаны. Проверено: номера пула "Google Ads" (`8883783267`, `8883448725`,
`8883025461`) с "LAWINJURY" буквенно не совпадают — маска просто рисует
единый брендовый лейбл поверх разных номеров ради визуальной консистентности
с оригинальным vanity-номером.

**Потенциальный риск для UX:** для посетителя, кликающего по номеру (мобильный
или ПК с обработчиком `tel:`), это не проблема — реальные цифры уходят по
`href`, буквы посетитель не набирает. Но для посетителя, читающего номер с
экрана ПК и переписывающего его вручную (записать, продиктовать, ввести в
другое устройство без автоперехода по `tel:`) — текст вида "(888)
3-LAWINJURY (025461)" может запутать: неочевидно, что "3-LAWINJURY" —
это тоже цифры (первая часть номера через буквы), а "(025461)" — оставшиеся
цифры открытым текстом. Смешение двух форматов в одной строке для человека,
не знакомого с логикой vanity-номеров, читается как два разных куска
контактной информации, а не один номер. Не проверено на реальных
конверсиях/жалобах — зафиксировано как наблюдение/риск, не как
подтверждённая проблема.

## Icon-only кнопки звонка (номер без текста) и XPath для inline-SVG

Найдено на [[../../Клиенты/ProfiMet/index|ProfiMet]] (mocnaszklarnia.pl,
2026-09-01), при разработке `Скрипты/phone_xpath_discovery.py`: не любой
`<a href="tel:...">` на странице содержит видимый текст номера. Частый
паттерн для мобильной вёрстки и соцссылок — кнопка-иконка без текста
(`<a href="tel:..."><img></a>` или `<a href="tel:..."><svg>...</svg></a>`),
где номер существует только в атрибуте `href`.

Если на такой элемент завести обычное XPath-правило с текстовой маской
(full-replace, см. предыдущий раздел) — Ringostat впишет цифры номера как
**текст рядом с иконкой**, ломая вёрстку кнопки, которая изначально не
рассчитана на текстовый контент. Отличить такой узел от обычного текстового
можно по отсутствию видимого текста / наличию `<img>`/`<svg>` внутри.

**Решение, подтверждено поддержкой Ringostat (2026-09-01): маска может
содержать произвольный HTML, а не только текст с `#` на месте цифр.**
Плейсхолдер номера — `<t>` — можно поставить прямо ВНУТРИ атрибута (не
только в текстовом содержимом узла). Ringostat заменяет outerHTML найденного
элемента на всю HTML-строку маски целиком, подставляя номер туда, где стоит
`<t>`. Пример для icon-only кнопки (иконка `mob_phone.svg`, ProfiMet):

    XPath:
    //a[contains(@class,'tn-atom') and starts-with(@href,'tel:') and .//img[contains(@src,'mob_phone.svg')]]

    Маска:
    <a class="tn-atom" href="tel:<t>"> <img class="tn-atom__img" src=".../mob_phone.svg" alt="" /></a>

Значит full-replace textContent (см. раздел выше про длинные тексты) —
не единственный режим работы маски, это скорее частный случай, когда маска
не содержит HTML-тегов. Когда маска — валидный HTML с `<t>` внутри атрибута,
Ringostat подставляет номер именно в этот атрибут, оставляя остальную
разметку (включая `<img>`) нетронутой — visual вид кнопки не страдает.

Практическое следствие: XPath для icon-only элемента не обязательно
привязывать к конкретной DOM-копии блока (fixed/sticky vs обычная — см.
следующий раздел) — можно взять widely-matching XPath по узнаваемому
признаку самой иконки (класс + имя файла в `src`), если задача — подменять
номер одинаково во ВСЕХ местах показа этой иконки на странице разом (так и
сделано на ProfiMet: одна и та же icon-only кнопка встречается в обычном
хедере, sticky-копии и блоке соцссылок одновременно — проверено
`Скрипты/phone_xpath_discovery.py` — и клиент подтвердил, что везде должен
показываться один и тот же номер за один визит).

Проверено, что блок формы "Кнопка выдачи номеров Call me" (HTML-код +
чекбоксы для мобильных/всех устройств) к этой задаче отношения НЕ имеет —
это отдельная функция экономии номеров пула при нехватке (показывает кнопку
"узнать номер", когда одновременных посетителей больше, чем свободных
номеров), не связана с подменой в icon-only элементах — не путать.

**Важный технический нюанс XPath 1.0**, всплывший при попытке составить
правило для inline-`<svg>`-иконки: голый шаг `svg` в XPath-выражении
(например, `a[svg]`) **никогда не совпадает** с реальным `<svg>`-элементом.
Причина — `<svg>` живёт в отдельном XML-namespace
(`http://www.w3.org/2000/svg`), а безымянный шаг в XPath 1.0 ищет элемент
БЕЗ namespace. При этом браузерный `querySelector('svg')` в JS находит
такой элемент без проблем — JS не требует явного совпадения namespace,
поэтому расхождение легко не заметить, если проверять структуру через
DevTools/JS, а потом составлять XPath вручную. Проверено эмпирически:
`//a[svg]` дал 0 совпадений на реальном инлайн-`<svg>` внутри соцссылки-
телефона ProfiMet, при этом `//a[*[local-name()="svg"]]` находит его
корректно. **Обход — везде использовать `*[local-name()="svg"]` вместо
голого `svg`** в любом составном XPath, где нужно проверить наличие
SVG-потомка. Это ограничение самого языка XPath 1.0, а не Playwright —
значит правило с голым `svg` не заработает и в движке XPath кабинета
Ringostat, если у клиента иконка реализована как inline-SVG (а не `<img>`
со ссылкой на файл `.svg`, что namespace-проблемы не имеет, т.к. `<img>` —
обычный HTML-элемент).

## Sticky-хедер на Tilda — отдельный DOM-узел, свой XPath

Найдено на [[../../Клиенты/ProfiMet/index|ProfiMet]] (mocnaszklarnia.pl,
2026-09-01): сайт сделан на Tilda, XPath-правило было задано по хедеру
начального экрана, но подмена не срабатывала именно в **sticky-хедере**,
который появляется при скролле вниз.

Причина — архитектура Tilda: блок хедера (`.t396`) рендерится **двумя
параллельными DOM-копиями** одного и того же контента — обычной, в потоке
документа, и fixed-копией с классом `t396__artboard-fixed-active`, которую
Tilda JS активирует (`position: fixed`, показывает) только во время
скролла. Это не один и тот же узел, который меняет позицию через CSS — это
буквально второе поддерево DOM с собственным набором дочерних элементов и
собственной `<a href="tel:...">`. XPath, ведущий к номеру в обычной копии,
физически не совпадает ни с одним узлом в fixed-копии — отсюда и
несрабатывание маски именно при скролле.

Решение — задать **второе** правило подмены (второй XPath) специально для
fixed-копии, по классу, а не по числовым индексам div (индексы уезжают при
правках вёрстки в редакторе Tilda):

    //div[contains(@class,"t396__artboard-fixed-active")]//a[starts-with(@href,"tel:")]

Найдено через Playwright: открыть сайт headless-браузером, проскроллить
(`window.scrollTo`, с паузой на анимацию/JS), затем обойти DOM в поиске
`a[href^="tel:"]`, видимых в верхних ~150px экрана, и проверить, лежат ли
они внутри `.t396__artboard-fixed-active` (`element.closest(...)` в
браузерном JS). Через обычный WebFetch/просмотр исходного HTML эту разметку
не найти — fixed-копия и её активный класс появляются только после
скролла, на клиенте, через JS Tilda.

**Общий вывод для будущих клиентов на Tilda:** если XPath-правило заведено
по хедеру, но подмена не работает именно при скролле (в статике на верхнем
экране — работает) — в первую очередь проверять, не Tilda ли это, и не
нужно ли отдельное правило для `.t396__artboard-fixed-active` (или
аналогичного fixed-класса, если Tilda сменит именование).

## Статус

Протестировано на практике (XPath Manual mode, ротация пула, full-replace
поведение маски, full-text маска для точечной замены внутри длинного текста
— всё подтверждено эмпирически на landverpersonalinjury.com, 2026-08-18).

Не протестировано:
- работает ли эта же логика (full-replace, full-text маска, отсутствие API)
  на других инсталляциях Ringostat — вероятно да, так как это общая
  архитектура сервиса, а не специфика одного аккаунта, но явно не
  проверялось на другом клиенте;
- раздел про sticky-хедер Tilda (`t396__artboard-fixed-active`) — XPath
  найден и подтверждён структурно (DOM-анализ через Playwright), но реальная
  подмена номера в кабинете Ringostat с этим XPath ещё не проверена вживую
  на ProfiMet (задача заведена, ждём внесения в кабинет);
- раздел про icon-only кнопки и HTML-маску с `<t>` в атрибуте — способ
  подтверждён ОФИЦИАЛЬНО поддержкой Ringostat (не наша догадка, не
  документация третьих лиц), но ещё не проверен вживую в реальном кабинете
  (правило подготовлено, не внесено на момент записи, см.
  `Клиенты/ProfiMet/Задачи.md`).
