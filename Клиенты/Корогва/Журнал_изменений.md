# Журнал изменений — Корогва

Фактические изменения в трекинге и кабинетах: было → стало, зачем, результат, откат. Источник для ежемесячного отчёта клиенту. Запись ниже восстановлена 09.11.2026 из [[Решения]] (28.09.2026); замера после внедрения в вики нет.

## [2026-09-28] И-001 (ретро) | трекинг | GA4, тег «КОРОГВА» (`G-8PS48XHNFG`) → Настройки → «Создание списка нежелательных переходов» | добавлены условия «Домен перехода содержит» для `monobank.ua`, `liqpay.ua`, `privatbank.ua`, `wayforpay.com`, `fondy.eu`, `portmone.com` | вручную в интерфейсе GA4 с доступом владельца тега, настроено 28.09
- Было: после оплаты на платёжной странице покупатель возвращается по ручной кнопке; на странице «Спасибо» (`corogva.com/checkout/order-received/…`) `document.referrer` = `https://pay.monobank.ua/`, GA4 заводит конверсию `custom_purchase` как новую сессию с источником «платёжный шлюз» (подтверждено прямой проверкой payload `collect`, заказ #35659). Исключение через GTM-переменную `ignore_referrer` не сработало.
- Стало: нативный список нежелательных переходов в GA4 Admin; домены шлюзов в «Настройку доменов» (cross-domain, `_gl`) осознанно не добавлялись, чтобы не менять URL на стороне платёжного шлюза.
- Зачем: конверсии переатрибутировались на платёжный шлюз вместо реального источника трафика.
- Результат на сегодня: нет данных — в вики нет замера после внедрения; запись названа «ожидает проверки».
- Откат: удалить добавленные условия в списке нежелательных переходов тега.
- Для отчёта клиенту (EN): We configured Google Analytics to ignore payment-gateway referrals, so online purchases are credited to the original traffic source rather than to the bank's payment page.
