Правила привязаны к нему, а не к числовым id Tilda и не к тексту номера: переживает правку вёрстки, если атрибут не убирают. Принцип (см. [[../../../База_знаний/Инструменты/Ringostat-механизм-подмены-номера]]): XPath на сам `<a>`, маска только из внутренностей, без внешнего `<a>`; ГЕО группа — **All** (не «not set»); `href` Ringostat выставляет сам.

## Кнопка звонка в результате квиза — НЕ подменяется (проверено 2026-10-24 после внесения правил: href остался +18444529465)
Её создаёт скрипт страницы после ответов на вопросы, а в нём зашито `PHONE_URL = 'tel:+18444529465'`. По нашим записям Ringostat проходит по странице при загрузке (см. раздел про sticky-хедер Tilda в базе знаний), а такой кнопки к этому моменту нет; повторно ли он просматривает страницу при изменении — не знаем. Страховка в коде блока квиза (одна замена в `renderResult`) работает в любом случае:

```js
var live = document.querySelector('a[data-ldv-cta="hero_call"]');
var callHref = (live && live.getAttribute('href')) || PHONE_URL;
var callText = live ? live.textContent.replace(/\s+/g, ' ').trim() : 'Call ' + PHONE + ' · 24/7';
var call = add(btns, 'a', 'ldvq5__button ldvq5__button--call', callText);
call.href = callHref;
```
вместо
```js
var call = add(btns, 'a', 'ldvq5__button ldvq5__button--call', 'Call ' + PHONE + ' · 24/7');
call.href = PHONE_URL;
```
Номер берётся из уже подменённой кнопки первого экрана, поэтому в результате квиза показывается тот же номер, что и везде за этот визит.
