## [2026-09-04] Google Ads / Ringostat | сверка номеров звонящих по цели "Calls from ads" за август | нужно было понять, какая доля звонков, засчитанных Google Ads конверсией "Calls from ads", реально долетает до Ringostat (и наоборот) | доля пересечения — **0%**. Источники: (1) Google Ads Reports → Calls, отчёт "Call details" за 1–31 августа 2026, выгружен клиентом вручную из интерфейса (`Клиенты/LuxeBrokers/Call details.csv`) — Google Ads API отдаёт по звонкам только `caller_area_code`/`caller_country_code`, полный номер через API недоступен (privacy-ограничение, подтверждено официальной документацией developers.google.com/google-ads/api/fields и форумом разработчиков), поэтому пришлось использовать ручной экспорт из UI; 96 строк, 53 уникальных нормализованных номера (есть повторы и строки без номера, "--", у пропущенных/сорвавшихся звонков). (2) Ringostat API `calls/list` (`Auth-key` из кабинета клиента, project id 141688), поле `caller_number`, тот же период — 26 звонков, 23 уникальных номера. Оба набора нормализованы к формату "1XXXXXXXXXX" (US, 11 цифр с кодом страны) перед сравнением. Пересекающихся номеров — 0 из 53 (Google Ads) и 0 из 23 (Ringostat). Проверено, что это не артефакт настройки: (a) даты в обеих выборках покрывают весь август без пропусков; (b) `utm_campaign` ID в звонках Ringostat (`21863567679`, `21863784402`, `21874137004`, `21874148347`, `22025494312`, `23733296589`) точно совпадают с реальными ID кампаний аккаунта LuxeBrokers (customer_id 953-486-5605, сверено напрямую через Google Ads API) и с названиями кампаний в столбце Campaign у Call details ("diamonds", "watches / lux", "jewelry / non-lux" и т.д.) — то есть Ringostat-ключ действительно от этого же аккаунта/периода, не от другого проекта. **Вывод: два набора звонков технически не пересекаются вообще** — Google Ads "Calls from ads" и Ringostat call log фиксируют, по-видимому, РАЗНЫЕ множества звонков на этом аккаунте (гипотезы, не проверено: у сайта может быть несколько независимых номеров/схем показа — часть кликов по номеру в объявлении может идти не через номер, подключённый к Ringostat-коллтрекингу, либо Google засчитывает конверсию по самому факту клика/начала звонка без прохождения через АТС Ringostat, либо часть звонков дублируется/обрывается до соединения и попадает в один источник, но не в другой). **Ограничение методологии** (см. также `База_знаний/Паттерны/Сверка-конверсий-Директ-Метрика-Коллтрекинг.md` — та же логика приоритета данных и честного признания несходимости, хоть она и писалась про Директ/Метрику): нельзя делать вывод "кампания X не работает" или "Calls from ads завышена/занижена" по одной лишь этой сверке — причина расхождения не установлена, а не просто велика; нужно отдельно разобраться в архитектуре коллтрекинга на сайте (сколько номеров показывается, какие из них реально подключены к Ringostat, есть ли номера показа, не покрытые никаким коллтрекингом вообще) прежде чем доверять любой из двух цифр как полной. См. [[Задачи]] — вынесена задача разобраться в причине

## [2026-08-05] Yelp | детальный разбор механики Yelp Ads | нужно было понять таргетинг, форматы объявлений, лимиты символов, посадочные страницы, аукцион и рычаги оптимизации, прежде чем заводить кампанию | полностью описано в [[../../База_знаний/Инструменты/Yelp-платформа-обзор|Yelp-платформа-обзор]]: (1) форматы объявлений и точные лимиты символов/изображений (Search/Showcase/Slideshow Ads); (2) таргетинг — категория + Keyword Boosting (boost/block тем, бесплатно, встроено) + гео (радиус или до 25 локаций) + расписание показа, без демографии; (3) назначение клика — бизнес-страница Yelp / прямой звонок / внешний сайт / форма Request a Quote внутри Yelp, выбирается через ad_goals; (4) аукцион — auto-bidding без ручной ставки в self-serve, рекламодатель управляет только месячным бюджетом, аукцион ранжирует по predicted CTR + цена + релевантность (Final Price per Click); нашли в Master Advertising Terms, что max bid price технически существует, но только через Purchase Order в managed-размещении (сейлз Yelp или Yelp Advertising Partner Program), не в обычном self-serve кабинете; (5) метрики и рычаги оптимизации после запуска — CTR/lead-through-rate/cost-per-lead/ROAS, блокировка невыгодных тем, буст ценных, правка радиуса/креатива/цели клика, бюджета. Открытые вопросы вынесены в [[Задачи]]: доступность max bid price, и организационный вопрос — заводить self-serve или через Yelp Advertising Partner Program (агентский вопрос, не только по этому клиенту)
