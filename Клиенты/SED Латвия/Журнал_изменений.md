## [2026-09-02] И-002 (ретро) | трекинг | GTM-TMV7VSWQ, настройки сайта Tilda → Аналитика | поле «Google Tag Manager ID» | значение `GTM-TMV7VSWQ` → пусто | вручную пользователем в Tilda и публикация сайта, по согласованию
- Было: контейнер GTM грузился дважды на каждой странице (два одинаковых `<script src=…gtm.js?id=GTM-TMV7VSWQ>` в `document.scripts`: встроенное поле Tilda и ручной код в HEAD); события «Загрузка контейнера» и «Команды update для режима согласия» срабатывали дважды подряд.
- Стало: остаётся только ручной код в HEAD; проверено на живом сайте (Playwright, «Результат подтверждён» в записи «Решений»).
- Зачем: порядок критичен — `gtag('consent','default',…)` должен выполниться строго до `gtm.js`; в ручной вставке это гарантировано (consent-скрипт стоит первым), во встроенном поле порядок определяет сама Tilda.
- Результат на сегодня: измерено — дубль контейнера устранён (проверка после публикации); влияние на цифры отчётов не измерялось.
- Откат: вернуть значение `GTM-TMV7VSWQ` в поле «Google Tag Manager ID» (вернёт дубль, делать нельзя без причины).
- Для отчёта клиенту (EN): We removed a duplicate Google Tag Manager load on the website, so tags and consent signals now fire once per page.
