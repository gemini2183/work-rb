## 1. Как всё устроено (откуда берутся списки)

В аккаунте 43 списка по API (71 до чистки 2026-10-07), плюс 4 списка, которые видны только в интерфейсе. Источников пять:

| Источник | Как создаётся | Как попадает в Ads | Примеры |
|---|---|---|---|
| **Сайт → GTM → GA4 → аудитория GA4** | Событие отправляет тег GTM (или сам GA4 автоматически); в GA4 создана аудитория по условию на событие | GA4 автоматически выгружает аудиторию в Ads как список «Website visitors» только для чтения (`read_only`), тип REMARKETING | корзина, лиды, engage_*, user_engagement, 60sec |
| **CRM → Customer Match** | Список клиентов из CRM загружается в Ads (контактные данные) | Тип CRM_BASED, редактируемый | `Profimet — уже купившие клиенты` |
| **Тег Google Ads / конверсии (система Google)** | Google создаёт сам | Тип RULE_BASED, только для чтения | All visitors (AdWords) ×7, All Converters |
| **Сборка Google из других списков** | Google или пользователь | LOGICAL, LOOKALIKE | AdWords optimized list, look-a-like ×3 |
| **Автосписки Google, видны только в интерфейсе** | Google создаёт сам | В API (`user_list`) не отдаются | Conversion-based ×3, Google-engaged audiences |

**Цепочка для списков GA4:** посетитель принимает cookie (без «Zaakceptuj wszystkie» GA4 на сайте не стартует) → тег GTM отправляет событие в GA4 → пользователь попадает в аудиторию GA4 на N дней → Ads получает список → в Ads размер берётся только по тем, кого Google смог сопоставить с рекламным профилем. Поэтому размер в Ads меньше, чем в GA4 (для корзины ~42% на Display).

### Как собраны `engage_*` в GTM (версия 61, читали глазами в интерфейсе)

Три триггера типа «Группа триггеров» с условием «все условия» (срабатывает, когда выполнились все составляющие):

| Триггер-группа | Состав | Тег GA4-события |
|---|---|---|
| `engage_low` | `Scroll25_group` И `time_15sec_group` | `GA4 - event - engage_low` |
| `engage_mid` | `Scroll50_group` И `time_45sec_group` | `GA4 - event - engage_mid` |
| `engage_hi` | `Scroll90_group` И `time_90sec_group` | `GA4 - event - engage_hi` |

Отдельно в GTM есть простые события по времени (`time_15sec`, `30`, `45`, `60`, `90`, `120`, `180`, `240`, `300sec`) и по прокрутке (`scroll10`, `25`, `50`, `75`, `90`). Каждый — триггер-таймер или глубина прокрутки, обёрнутый в группу триггеров (`time_XXsec_group`, `ScrollXX_group`) и привязанный к своему тегу GA4-события. Точные интервалы таймеров и пороги прокрутки внутри триггеров я не открывал (не проверено).

### Нюансы

- **`user_engagement` — автоматическое событие GA4** (его не создавали в GTM). По документации Google оно срабатывает, пока страница в фокусе, то есть присутствует почти у всех посетителей. Отсюда списки 7/14/30 дней почти равны по смыслу «все недавние посетители, принявшие cookie»; цифры в GA4 за 7, 14 и 30 дней почти одинаковые (8 460 / 8 482 / 8 504). Это не проверено по документации, а выведено из чисел.
- **Все они появляются только у принявших cookie:** GA4 на сайте стартует после «Zaakceptuj wszystkie» (проверено Playwright 2026-10-06), значит в аудитории нет тех, кто не согласился.
- **`engage_*` — события по странице, не по сессии:** группа триггеров срабатывает, когда на одной странице выполнены оба условия (время и прокрутка). Человек, прочитавший страницу, попадает в `engage_*` сразу.
- **Эти списки нигде не подключены в включённых кампаниях.** В интерфейсе `engage_hi`, `engage_mid` и `user_engagement (30 дн.)` числятся «In use» только из-за кампаний на паузе; `user_engagement (14 / 7 дн.)` и `60sec (7/14)` — «Not in use». `engage_mid` помечен «Customer Type: Purchasers» — см. раздел 11 (это не просто ярлык).
- **Объём на Search:** списки меньше ~1 000 для Search по документации Google не работают (не проверено на нашем кабинете); ни один из них на Search ≥ 1 000 не доходит (максимум 2 200 у `60sec (7)`).
- **Хорошие кандидаты на ретаргетинг** (когда понадобится вместо корзины): `60sec (7)` (2 800 на Display), `user_engagement (30 дн.)` (1 900), `engage_mid` (1 000).

Настоящих лидов ~266 за 60 дней, до Ads доходит часть (согласие на cookie, нет client id). Пересоздавать аудиторию не будем (решение 2026-10-07): в Ads это размер не увеличит. Для исключений лидов список слишком мал (24 человека).

Отдельно: **`Unique_Calls`** (id 8624241354 в Ads, 0 человек) — аудитория GA4 (условие: `Ringostat_calls` с параметром `call_unique` = 1). **Это аудитория-триггер:** при вступлении в неё GA4 шлёт событие `Unique_Calls`. Удалять нельзя, она нужна для события; в Ads копия пустая. См. [[../../База_знаний/Инструменты/Ringostat-передача-звонков-в-GA4-события-и-типы]].

## 9. Общие нюансы работы со списками

- **Размеры округлены** (две значащие цифры) и разные для сетей: Search, YouTube, Display, Gmail. Показываются «Too small to serve» для маленьких. Для сопоставления использовать API (`size_for_display`, `size_for_search`), снимки — `Статистика/gads_crm_list_size_snapshots.csv`.
- **Списки GA4 в Ads — только для чтения** (`read_only`), но Google всё равно принимает их удаление через API (`validate_only` проверено; 2026-10-07 удалены 13 штук). Если аудитория остаётся в GA4, GA4 может создать список заново (не проверено; проверка 08.10).
- **При удалении списка подключения к нему (критерии в кампаниях) не удаляются сами.** Остаются «осиротевшие» критерии в кампаниях на паузе (~40). Сначала снимать подключения, потом удалять списки.
- **Режимы использования:** «Targeting» ограничивает показ аудиторией (`dspl_rtg_basket`), «Observation» только копит статистику (Search/PMax); исключение (negative) на уровне кампании скрывает рекламу от людей из списка.
- **Статусы в интерфейсе:** «In-use» — подключён хоть к какой-то кампании, включая паузные и экспериментальные.
- **Согласие на cookie** сильно режет GA4-списки (GA4 стартует только после «принять все»; 64% новых посетителей видят баннер, 46% увидевших принимают все — см. [[../../База_знаний/Инструменты/Ringostat-передача-звонков-в-GA4-события-и-типы]]).

## 10. Что не проверено

- Точные интервалы таймеров и пороги прокрутки внутри триггеров GTM `time_*` / `Scroll*`.
- Что именно входит в `Google-engaged audiences` и в `AdWords optimized list`.
- Как именно Google использует метку «Purchasers» у широких списков в `Search | Brand | Pl` (режим «только новые клиенты») — см. раздел 11; не проверено в настройках кабинета.
- Доля совпадений CRM-списка и дата/размер последней загрузки.
- Минимальные размеры для показа (Display ~100, Search ~1 000 — по документации Google, на нашем кабинете не проверено).
- Возвращает ли GA4 удалённые списки (проверка 08.10).

## 11. Метка «Customer Type» (тип клиента) — что это и почему важна

**Что это** (официальная справка Google «About audience customer types» и пересказ в профильных новостях PPC; в кабинете не перепроверено): метка, которая говорит Google, в какой стадии отношений с бизнесом находятся люди из вашего собственного списка («Purchasers», «Cart abandoners», «Qualified leads», «Disengaged customers» и др.). Метку можно поставить вручную в Audience Manager; Google также ставит её сам, когда настроены цели жизненного цикла клиента или синхронизируются некоторые аудитории GA4 (например, стандартная «Purchasers»). Метки действуют только на собственные (first-party) списки.

**Зачем:** режимы цели «привлечение новых клиентов» используют списки «Purchasers», чтобы отличить новых клиентов от существующих (ставить выше за новых, или не ставить за существующих вообще).

**Что стоит в нашем аккаунте** (ресурс `user_list_customer_type`, API 2026-10-07; категория 3 = PURCHASERS): метка «Purchasers» у пяти списков:
- `engage_mid` (8575354546),
- `GA4 - Добавили товар в корзину (60 дн.)` (8365998003),
