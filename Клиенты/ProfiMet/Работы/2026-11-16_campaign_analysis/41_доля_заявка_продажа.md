## 2. Доля заявка -> продажа

Точка как есть: 187 / 359 = 52,1 %.

| Версия | Точка | 80 % (Вильсон) | 95 % (Вильсон) |
|---|---|---|---|
| Как есть (без поправки на хвост) | 52,1 % | 48,7-55,5 % | 46,9-57,2 % (из CSV) |
| Хвост по консервативной границе, поправка ÷0,80 (скрипт: «около 65 %») | 65,1 % | 60,9-69,3 % | 58,7-71,5 % |
| Хвост по нижней границе, поправка ÷0,95 (мой расчёт) | 54,8 % | 51,3-58,4 % | 49,4-60,2 % |

Что в поправке на хвост и насколько она надёжна:
- Скрипт считает порог зрелости 3 дня (большее из двух P80 задержки) и пишет: продажи позже 3 дней после заявки не видны, «по определению P80 около 20 %», справочно ÷0,80 = 65,1 %, в расчёте не используется (sales_pace CSV, предупреждение).
- Но сам CSV показывает, что 20 % - верхняя граница, а не оценка. Задержка по старым касаниям (не позже 17.09, 2662 продажи): среднее 2,1 дня, медиана 0, P80 = 0, P95 = 14 дней. Значит доля продаж с задержкой больше 3 дней меньше 20 % (P80 = 0 дней) и не меньше примерно 5 % (P95 = 14 дней). Отсюда поправка лежит между ÷0,95 и ÷0,80, то есть доля с учётом хвоста 55-65 % (точка), а не фиксированные 65 %.
- Точную долю продаж позже 3 дней в готовых скриптах я не нашёл: CSV хранит только среднее, медиану, P80, P95. Поэтому внутри диапазона 55-65 % точку выбрать нельзя.
- Дополнительная неопределённость: заявки и продажи из разных систем (CRM и Ringostat/Supabase), номера не сопоставлены. Продажи с источником «Нет метки» частично не засчитаны Google (sales_pace.py предупреждает в таких случаях, число в этом прогоне не выведено в CSV), это тянет долю вниз; повторные касания номера в разные недели тянут вверх или вниз, оценить нельзя.
- Недельная доля шумная (35-70 %), последняя зрелая неделя 02-08.11 дала 34,6 % при возрасте 8 дней, то есть хвост её не объясняет; тренд вниз в последних двух зрелых неделях (48,5 %, 34,6 %) не проверен.

## 4. Можно ли решать по доле до 80 %

Проверка границ: 80 % не попадает ни в один интервал. Верхняя граница 95 % как есть - 57,2 %, с самой жёсткой поправкой на хвост - 71,5 %. Допустимая цена заявки при 80 % была бы 34,4 €, а верхний край самой оптимистичной версии даёт 30,7 €. По этим данным доля 80 % не подтверждается; максимум, что интервал допускает, это около 65-70 % при условии, что хвост равен 20 % (его верхней границе).

## 5. По кампании Poliweglan отдельно

Доли «заявка -> продажа» по кампании готовых скриптов нет. Есть:
- `Скрипты/profimet_price_per_sale_by_campaign.py --from --to`: продажи (по метке первого обращения за 60 дн., кампания и группа) и расход по кампаниям, цена продажи. Но заявок по кампании там нет, звонки из объявлений и «Нет метки» кампании не получают, доля не считается. В `Статистика/` готового результата этого скрипта нет, в этом задании он не запускался.
- `pace_vs_plan.py` / `leads_standard`: заявки по кампаниям (звонки по `camp`, формы по `camp`), но продаж по кампании не даёт.
- `sales_pace.py`: только общая доля по аккаунту.

## Пробел (для script-builder)
Нужен скрипт `profimet_lead_to_sale_by_campaign.py --from --to [--campaign "Search | Poliweglan | Pl"]` (только чтение): по каждой кампании без yt_ считает заявки (leads_standard, по дате первого касания, по `camp`) и продажи (метка первого обращения за 60 дн., как в `profimet_price_per_sale_by_campaign.py`), по зрелым неделям; доля, интервалы Вильсона и Клоппера-Пирсона 80 и 95 %, число заявок и продаж без кампании отдельной строкой. Плюс в `sales_pace.py` вывод: интервал 80 %, эмпирическая доля продаж с задержкой > порога зрелости (по старым касаниям), и доля с поправкой на хвост по этой измеренной доле вместо условных 20 %. Ожидание по размеру: на кампанию 3-10 продаж за зрелое окно (оценка по аналогии с `ea_lead_to_sale_trend.py`; для ProfiMet не проверено), интервал будет очень широким.

## 6. Что не установлено
- Реальная доля продаж с задержкой более 3 дней (известны только P80 = 0 и P95 = 14 дней по старым касаниям): поэтому поправка дана вилкой 55-65 %.
- Совпадение заявок и продаж по номерам: не сопоставлялись, доля приблизительная.
- Сколько заявок без названия кампании (5 за 01-15.11) были yt_.
- Влияние «Нет метки» и звонков из объявлений (call_view, 5 за период) на заявки и продажи.
- Доля по кампании Poliweglan.
- Интервал Клоппера-Пирсона не считался (нет готового расчёта); интервал 80 % Вильсона посчитан вручную.

## Вердикт
- Доля заявка -> продажа как есть: 52,1 % (187/359, 11 зрелых недель 24.08-08.11, без yt_); 80 %: 48,7-55,5 %; 95 %: 46,9-57,2 %.
- Хвост по времени даёт вилку: с учётом хвоста 55-65 % в точке (÷0,95 ... ÷0,80); 95 % самой оптимистичной версии: 58,7-71,5 %. Точную поправку установить нельзя: нет измеренной доли продаж позже 3 дней.
- Допустимая цена заявки (43 € x доля): как есть 22,4 € [20,2-24,6 при 95 %]; с хвостом 23,6-28,0 € в точке, до 30,7 € в самой оптимистичной границе.
- Доля 80 % не попадает ни в один интервал (цена заявки при ней 34,4 € против максимума 30,7 €); решать по ней нельзя без новых данных.
- Разброс по неделям 35-70 % шире биномиального интервала, интервалы оптимистичны по узости; заявки и продажи по номерам не сопоставлены.
- По кампании Poliweglan доли нет, готового скрипта нет (раздел «Пробел»).
