Google «50 конверсий за 30 дней» для оптимизации: при 22 € это 1 100 €, при 50 € - 2 500 €; 300 € дают 6-14 заявок (арифметика, цены 22-50 €). Порог недостижим, это называю прямо: кампания будет обучаться на малом числе событий, недобор показов допустим по политике. 95 % интервал Пуассона для 6 заявок 2,2-13,1, то есть цена заявки 23-136 € (расчёт по таблице Пуассона, скриптом не проверял).

**Стратегия.** Старт Maximize conversions без цели (как образец), затем tCPA 33 € отдельным шагом. Почему не без цели: `dg_lookalike_test` без цели дал 67,77 € и 0 основных конверсий (10_данные.md), цель душит показы, если она ниже реальной цены (`dg_lookalike_test` не доказывает, `demand_gen` с 5 € давала ~100 показов в день). 33 € выше допустимой 22 € и ниже ожидаемой ~50 €: компромисс, `yt_cold` с 33 € показы получал. Менять цель не более чем на 20 % за раз. Альтернативы: без цели (потеря управления ценой), 22 € (душит показы, риск как у `demand_gen`), Максимум кликов (для новой DG можно выбрать только при создании цели «Clicks»; в нашем билдере не поддержано, заявки не оптимизирует). Не проверено: принимает ли API tCPA прямо при создании (тогда шаг 2 не нужен).

**Сторож** (`gads_spend_guard_cpa.py --client ProfiMet`, файл `D:\GitHub\work-rb\Клиенты\ProfiMet\guard_config.yaml`): добавить строку `{id: <новый id>, name: dg_montaz_warm_lal, target: 30, total_limit: 300, since: "<день включения>"}` без управления бюджетом (как `search / montaz`). Что это даёт при grace 2, dry_mult 3, abs_mult 2 (значения из текущего конфига):
- Допустимый расход за день (2 + заявки) × 30: 60 € при 0 заявок; вероятность ложной паузы при допустимой цене 24 € e^(−60/24) = 8 % (Алгоритм 2.6).
- «Расход без заявок подряд» 3 × 30 = 90 €: e^(−90/24) = 2,4 %.
- Аварийный предел 2 × бюджет = 60 €/день.
- `total_limit` 300 € с даты включения = конец теста.
- Без записи в конфиг незнакомая ENABLED-кампания получает минимальную защиту: пауза при расходе ≥ min(1 × бюджет, 2 × цель по плану 30) = 30 € при 0 заявок. Значит строку нужно внести до включения.
- Конфиг читается один раз при старте: после правки процесс перезапускать (README, раздел сторожа). Правка боевого конфига и перезапуск требуют «да».
- Сторож считает заявки по `utm_campaign` (Ringostat + Supabase). Пока в Ringostat нет канала под `utm_campaign=dg_montaz_warm_lal`, звонки сторож этой кампании не припишет, и она может встать на паузу «без заявок» напрасно. Звонки из объявлений он берёт из Ads по кампании.
- Сторож по цели 30 € работает для `search / montaz` с `target: 50`; для DG выбрано 30 как верхняя граница успеха (ниже), а не 50, потому что тест холодный и дорогой.
