# ProfiMet: первое касание у продаж ноября с меткой «Телефон» и «Нет метки»

**Пробел: нет скрипта «продажа -> форма Supabase по телефону» и «продажа -> событие GA4 по телефону».** Supabase и GA4 в готовых скриптах проверяются только для форм «Нет метки», которые УЖЕ есть строкой в CRM (`profimet_our_leads.resolve_unlabeled`: gclid CRM, Supabase, Tilda, GA4 по минуте ±3 мин). Для продажи, чьё первое касание в CRM - звонок «Телефон» или «Нет метки», более раннюю форму в Supabase, которой нет в CRM, ни один скрипт не ищет. Нужен скрипт (бриф для `script-builder`): по списку заказов взять телефон (последние 9 цифр), найти формы Supabase за 60 дней до первой строки заказа, дать UTM/gclid/страницу. Одноразовый код не писал.

## Что посчитано

- Период: продажи с датой продажи 01.11 - 15.11.2026 (источник: `profimet_orders_list.py`, лист CRM `mocnaszklarnia.pl`). Заказов 72. Единица - заказ, не штука.
- Метка клиента = «Метка по гипотезе клиента» из того же списка (есть форма - источник формы, иначе заказ менеджера = «Телефон»).
- Окно: 60 дней до первой строки заказа, история номера по обоим сайтам ProfiMet (правило `sales_with_source` в `profimet_sources_dashboard.py`, режим «наш»). Первое касание в окне должно быть рекламным Google Ads.
- Источники касаний: строки CRM (`profimet_sales_vs_ringostat.py`, колонки первого касания), звонки Ringostat (он же, первый звонок в окне), формы CRM без метки через Supabase/Tilda/GA4 (`profimet_our_leads.py --list`, 01.10-15.11). Глубина GA4: минутный срез около 60 дней, для форм ноября глубины хватает.
- Построчная таблица: `orders_first_touch.csv` (рядом).

## Не проверено

- Касания проверялись на сайте mocnaszklarnia.pl для CRM-цепочки; SEO-сайт - через Ringostat.
- Дашборд «наш режим» считает продажи по дате первого касания (когорта), здесь - по дате продажи: числа с дашбордом (33 продажи) сравнивать нельзя.
