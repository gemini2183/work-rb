# ProfiMet: числа и особенности источников для анализа кампаний

Сюда вынесено всё клиентское из [[Алгоритм_анализа_кампании]]. Общие страницы цифр клиентов не содержат. Пороги не откалиброваны. YouTube (`yt_`) - отдельный проект, в расчёты по Google Ads (поиск, PMax, Display) не входит; у `yt_cold` свои пороги (Паспорт ProfiMet_YouTube).

## Целевые показатели (на 16.11, этап 1)
- Цена продажи 43 €; допустимая средняя цена заявки на месяц ≤ ~22-24 € (доля «заявка → продажа» 52,1 %). Подробности и расчёт: [[Процедура_догон_плана_месяца_лог]], Этап 1.
- Правило остановки по расходу без заявок при допустимой цене 24 €: 48 € ≈ 13 %, 72 € ≈ 5 %, 96 € ≈ 2 %. Кандидат «расход без конверсий» при 22-24 € - 48 €.
- Пример интервала (прикидка вручную, не скриптом): 22 заявки на 666,7 € (цена заявки ≈ 30,3 €): 95 %: 20,0-48,4 €; 80 %: ≈23-41 €.

## Источники заявок ProfiMet
- Основной: Ringostat и Supabase (звонки сайта, формы). Звонки из объявлений: `call_view` из Google Ads.
- Конверсии-формы Ads - только направление: расхождение 1,29, по неделям нестабильно (1,46 / 1,50 / 1,38 / 0,71; цифры агентов 16.11, допуск ±9 %). Звонки Ads для Brand и Poliweglan ×0,97.
- Без `yt_`.

### Формы Supabase (проверено 16.11, чтение агента)
Источник: `Клиенты/ProfiMet/Работы/2026-11-16_campaign_analysis/38_supabase_формы_по_дням.md`.
- Таблица `profimet_leads`. Сырые строки без будних провалов с 28.09, но в них мусорные пачки: сырой счёт завышен в 3-10 раз. Считать только очищенные формы (`mark_bursts`, повторы телефона за день).
- Настоящих форм обычно 0-6 в день, из них 2-3 Google.
- Будни с нулём настоящих форм: 02.10, 28.10, 29.10, 05.11 (весь день пачки, неразличимо).
- 13-15.11 не похожи на обычный поток (Google-форм 0). Возможная потеря, не установлено.
- Поле даты одно - `created_at` (UTC, запись в базу). `gclid` пуст до 27.10; Google определялся по `utm_source`. Потеря до записи в базу не проверена.

## Перенесено из методологии (16.11, до очистки 18.11)
Сама методология теперь общая: [[Методология-выбора-метода-и-периода-анализа-кампаний]]. Ниже клиентские числа и результаты проверок на истории ProfiMet.

**Рамка и допуски (решения пользователя 16.11).** Клиент оценивает месяц к месяцу; допуск от плана ±15 % (бюджет, заявки, цена заявки). Цена продажи (цель 43 €): закладка +3 % (44,3 €), максимум +5 % (45,2 €); ниже цели не нарушение. Допуски не независимы: расход +15 % при заявках −15 % даёт цену заявки около +35 %; ограничивает цена продажи. Допустимая цена заявки: при +3 % 43 × 1,03 × 0,521 = 23,1 € [20,8..23,7]; при +5 % 23,5 €. Доля заявка→продажа 52,1 % [46,9–57,2] (Уилсон 95 %); заявки (Ringostat/Supabase) и продажи (CRM) без сопоставления номеров. Неопределённость доли (около ±10 %) больше допуска 3 %.

**Вес выходных 0,13** по расходу и заявкам (окно 05.10–15.11, `pace_vs_plan.py`).

**Точность по кампаниям, 01–15.11 (leads_standard, расчёт мой):** аккаунт 58 заявок ≈ ±26 %; `pmax1_test` 25 ≈ ±39 %; `Search | Brand | Pl` 19 ≈ ±45 %; `Search | Poliweglan | Pl` 7 ≈ ±74 %; `search / montaz` 1 - вывода нет. Интервалы Гарвуда (проверено расчётом): 58 → 44,0..75,0 → цена 11,6–19,8 €; 25 → 16,2..36,9 → 8,2–18,7 €; 19 → 11,4..29,7 → 11,0–28,5 €; 7 → 2,8..14,4 → 15,7–80,7 €.

**Пример доли бюджета на тесты (16.11, не проверен скриптом):** прогноз цены продажи по месяцу 29 € [26–32], цель 43 €; худшая граница 32 €, тесты в 3 раза дороже базы → s ≤ (1 − 32/43) ÷ (1 − 1/3) ≈ 0,38, то есть до ~38 % бюджета на тесты не выводят цену продажи за 43 €.

**Бэктест окна уровня (16.11, `period_backtest.py --backtest`, `Клиенты/ProfiMet/Работы/2026-11-16_selector/`).** WAPE, меньше лучше, окна 7 / 14 / 21 дн.: аккаунт 0,321 / 0,385 / 0,431; Brand 0,356 / 0,405 / 0,457; Poliweglan 0,373 / 0,441 / 0,515; pmax01 0,446 / 0,543 / 0,586; у аккаунта 14 и 21 дн. статистически хуже динамической модели (p_Холм 0,013 и 0,009). pmax1_test (18 точек) и szklarnia/tunel (27) - окна не различимы. Вес затухания 0,8 не подтверждён: модель выбрала 0,3-0,5 в неделю. Рабочее правило: 7 дней для аккаунта, Brand, Poliweglan, pmax01; 14 дней для малых без значимости. Проверен только горизонт «следующая неделя». Ошибка 16.11: сводка назвала лучшим окно 2 недели по сеткам объектов (18 недель); на общей выборке (50-56 недель) лучше 1 неделя.

**Окно сегментов (рабочее правило 16.11, не проверено):** начало - дата последней крупной правки; конец - сегодня; потолок 3 недели (4+ недели хуже динамической модели: p_Холм 0,045 при 4 нед., 0,006 при 5); судить по накопленному расходу: «расход без заявок» при S ≥ 3 × T.

**Результат проверки сегментов (`segment_backtest.py`, `Клиенты/ProfiMet/Работы/2026-11-16_segment_backtest/50_скрипт.md`):** шаг 0 (сверка данных) пройден у устройств, часов, каналов, дней недели, групп объявлений, ключей Brand, групп активов pmax1_test; не пройден у гео, запросов Search (покрытие расхода 29,0 %), поисковых категорий PMax (32,7 %), ключей Poliweglan. Шаг 1: подтверждено 3 из 35 сочетаний; калибровка e^-k: 250 из 280 корзин внутри интервала. Шаг 2: ни одно окно не лучше эталона (уровень кампании). Шаг 3: нет порога k с верхней границей доли ложных ≤ 5 % (лучшее 19,4 % у дней недели, 24,2 % у часов). Порог 3×T остаётся неутверждённым. Ограничения: малые выборки (до 101 флага), конверсии Ads 7268,6 против 3420 заявок стандарта, даты правок не использованы.

**«Клик по номеру» в PMax** завышался YouTube и Discover; микроконверсии - только после проверки связи с заявкой.
