# Журнал изменений — ProfiMet

**Назначение.** Единый список того, что мы реально поменяли в Google Ads, GA4, GTM (и рядом), с состоянием «до» и «после». Отличие от остальных файлов: [[Решения]] хранит стратегию и рассуждения, логи кампаний — рутинные правки, а здесь только факты изменений, по одному блоку на изменение, в одном формате. Снимки «до» лежат в `Статистика/`.

**Формат записи** (заголовок парсится: `grep "^## \["`):

```
## [ГГГГ-ММ-ДД] И-NNN | Уровень (аккаунт/кампания/список/GA4/GTM) | Объект | Действие | Было → Стало
- Зачем:
- До (снимок / база метрик):
- Проверка после (прочитано обратно из аккаунта?):
- Откат:
- Что измерять и когда:
- Результат на сегодня: (измерено — с цифрой и периодом; гипотеза — так и написать; пока нет данных — так и написать)
- Для отчёта клиенту (EN): одно предложение простым английским о пользе действия, без выдуманных результатов
- Связано: [[Решения]] запись …
```

**Правила для агента отчётов.** В клиентский текст идёт только «Для отчёта клиенту (EN)» и измеренные цифры из «Результат на сегодня»; гипотезы не подавать как результат. Показы, клики, расход брать свежо из отчётов, здесь они — срез на дату записи. ID не меняется; итог эффекта дописывается строкой «Итог …» под записью.

**Как правильно заполнять:** писать значения «было → стало» цифрами и названиями объектов с id; не пересказывать рассуждения (они в [[Решения]]); указывать файл снимка «до»; ставить дату проверки эффекта (потом дописать результат отдельной строкой «Итог …»). Кто сделал: если не указано иное, Claude по протоколу «таблица плана → «да» → запись → чтение обратно» (CLAUDE.md).
