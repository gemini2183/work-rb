## 16.10 — срез месяца по цене заявки (первая часть пересмотра по схеме ProfiMet И-066)
- **Срез:** Google Ads, 01–15.10, расход по кампаниям 4 224 zł. «Заявка» = `form_submit_web` + `Calls from ads` + `Ringostat_calls`; «Клик по номеру» (CONTACT) не считаю (решение пользователя 14.10). Формы включают спам — не отделён. Источник: запрос к API 16.10 (кампания × день × действие).
- **Итог:** 35 заявок на 4 224 zł = **121 zł** (план 110). Сводка `state_digest` показывала 54.3 заявки — в них 19.3 «Клик по номеру»; для цены заявки брать 35.
- **Половины месяца (расход / заявки / zł за заявку):** 1–8.10: 1 560 / 15.0 / 104; 9–15.10: 2 664 / 20.0 / 133.
- **По кампаниям:** `general_pmax` 2 527 zł / 22 заявки (форм 18 + звонков из объявлений 4) / 115 (1–8: 689/7/99; 9–15: 1 838/15/123); `shop_search` 1 167 / 9 / 130 (1–8: 136, 9–15: 117, клик 3.19 → 1.49 zł); `shop_pmax` 368 / 3 / 123 (9–15: 314 zł на 1 заявку — YouTube, клик 0.18 zł); `general_pmax_rozmiary` 109 / 1 / 109; `rozmiary / katalog` 53 / 0 (26 кликов по 2.06 zł); `poliweglan` — показов за месяц нет.
- **Всплески `general_pmax`:** 10.10 (580 zł) и 12.10 (626 zł) вместе 1 206 zł из 2 527 (48%) и 8 заявок → 151 zł за заявку; остальные дни 1 321 zł / 14 заявок → 94 zł. Деньги уходят в дни всплесков медийной сети.
- **Цена клика × коэффициент конверсии:** `general_pmax` клик 0.56 → 0.85 zł (+52%) при коэффициенте ≈ 0.6–0.7% (без изменений) — рост цены заявки идёт от цены клика. `shop_search` клик подешевел, коэффициент 2.3% → 1.3%.
- **Не сделано:** бренд отдельно (брендовых кампаний нет, запросы бренда только внутри `shop_search`); сверка с CRM-таблицей клиента (кампания, исход, причины); перевод в цену продажи — нужны курс злотого и граница в EUR от пользователя.

## 14.10 (вечер) — продажи без рекламной метки: кому на самом деле принадлежит первый контакт
- **Источник данных:** выгрузка продаж CRM «ea- продажи.xlsx» (68 продаж, 27.07–13.10, почти всё с 01.09), Ringostat API (1 286 входящих звонков с 05.12.2025; **исходящих в API нет** — все `call_type = in`), формы Tilda 01–14.10. Номера сопоставлялись по последним 9 цифрам; уникальность — по схеме проекта мониторинга (единое множество звонивших по Google Ads / Facebook / SEO / без источника, первый звонок = unique). Скрипт — `ringostat_sales_attribution.py`, таблица — [[Статистика/sales_attribution_2026-10-14.csv]].
- **Часовые пояса (проверено совпадением времён):** «Дата» в продажах — UTC (продажа записана через 0–2 минуты после начала входящего звонка), формы Tilda — Москва (UTC+3), Ringostat API — местное с явным смещением. Без приведения к UTC всё «сдвигается» на 2–3 часа.
- **Измерено (68 продаж):** источник «Телефон» — 26, «Нет метки» — 25, «Facebook» — 7, «Google Ads» — 10. Из 26 «Телефон» у **24** (92%) первый контакт в Ringostat — реклама; у «Нет метки» таких 1. Итого 25 продаж записаны не на рекламу, хотя первый контакт рекламный: Google Ads 20, Facebook 5; все 25 — уникальные звонки по нашей схеме и по флагу Ringostat `unique_call`.
- **Это в основном не обратные звонки, а заказы по входящему:** у 21 из 25 продажа записана в течение 3 часов после входящего звонка из рекламы, у 20 — в первые минуты (до 6 минут; менеджер оформляет заказ во время или сразу после звонка и ставит источник «Телефон» по умолчанию). Позже — только 4: через 72 ч, 97 ч, 168 ч и 5 383 ч (последняя — продажа 01.09 с датой-заглушкой 00:00 и звонок 19.01, вес низкий). Гипотезу про исходящие перезвоны по звонкам проверить нельзя (в API Ringostat исходящих нет), но по времени большинство случаев на неё не похоже.
- **Куда уйдут продажи при пересчёте:** Google Ads с 10 до 30 (+20), Facebook с 7 до 12 (+5). Разбивка рекламных первых звонков: shop_pmax 7, `Google CPC General - pm` (PMax «Теплицы», статический канал) 7, Facebook 5, shop_search 2, `performmax_*` 2, `general_pmax` 1, Google CPC Merchant 1. Кампанию определяет `utm_campaign` в Ringostat; у статического канала кампании нет.
- **«Нет метки» (25):** 24 оформлены скриптом сайта (корзина Tilda), одна — менеджером. 7 из них совпали с формой Tilda за 01–14.10 — у всех форма без UTM (корзина или квиз без метки), то есть это заход без метки, а не потерянная реклама. Остальные 17 — до 01.10, форм за этот период в выгрузке нет, звонков тоже нет: источник по имеющимся данным **не восстановить**.
- **Ограничения:** (1) «первый звонок из рекламы ↔ продажа» — совпадение номера и времени, а не доказательство, что именно реклама привела к покупке; (2) Ringostat хранит звонки с 05.12.2025; (3) у 13 продаж с метками Google/Facebook звонков нет — они пришли через сайт/корзину, это не ошибка; (4) одна продажа с меткой Facebook (30.09 15:05, UTM «—») имеет первый контакт Google Ads PMax (звонок в 15:09) — возможно, ошибка в обратную сторону.
- **Наблюдение, не проверено:** у 5 звонков с `utm_source=facebook` пул номера называется «Google CPC General» — похоже, пул отдаётся по каналу `General`, а не по UTM. На атрибуцию звонка в нашей схеме не влияет (категория берётся по UTM), но для отчёта по пулам нужно знать.
- **Что предложить клиенту:** источник «Телефон» в CRM оставлять только при отсутствии входящего из рекламы за последние N дней; либо подтягивать источник из Ringostat по номеру автоматически. Пока — ежемесячный пересчёт этим скриптом для отчёта.

Расхода и кликов по площадкам API не отдаёт — какая площадка сожгла деньги, не знаем.

## 14.10 (позже) — посадочные страницы и идея Search на отфильтрованный каталог
- **Факт (чтение кабинета):** у всех объявлений `final_url` = `https://ekspertagro.pl/` (главная): четыре группы ассетов `general_pmax` и все RSA в `general / search / poliweglan` и `general / search / szklarnia/tunel`. Обе поисковые кампании на паузе (с какой даты — не выяснено). В `general_pmax` включена только группа «Заинтересованные покупатели» (кампания на паузе).
- **Факт (сайт, Playwright):** главная без цен и карточек (опросник из 5 вопросов, ссылка «Katalog»). Каталог `https://ekspertagro.pl/szklarni` — Tilda Store с фильтрами: толщина поликарбоната 4/6 мм, профиль 20x20/40x20, длина, ширина, высота, площадь. Фильтр кодируется в URL и применяется при прямом заходе: ширина 3 м + длина 6 м → 6 карточек (1 949–2 549 zł), 3x4 → 6 карточек (1 599–2 049 zł); + толщина 6 мм → 3 карточки (3x6: 2 549 / 2 449 / 2 179 zł). Ключи фильтров: ширина `tfc_charact:9246142[1500649011]`, длина `tfc_charact:9246152[1500649011]`, толщина `tfc_charact:9456082[1500649011]` — зависят от каталога в Tilda и могут смениться при его правке. Карточка товара: цена, характеристики, кнопка «Zamówienie», телефон.
- **Shopping за год (14.10.2025–14.10.2026, конверсии Ads, не сверены с Ringostat), позиции 3x4/3x6:** 3x6/4 мм 40x20 — 28.8 конв., 134 zł; 3x4/6 мм 40x20 — 23.4 конв., 74 zł; 3x4/4 мм — 9.8 (109 zł); 3x6/6 мм — 9.5 (168 zł); профиль 20x20 даёт заметно меньше (6 мм: 0.1 конв.). Лидер по объёму — 2,5x2 м/4 мм (68.3 конв., 161 zł) — вне идеи про 3x4/3x6.
- **Решения пользователя 14.10:** посадка Search — широкий выбор (каталог с фильтром ширина+длина), дальше человек фильтрует сам; на «6 mm» отдельную карточку не делаем (не уверены, что Google так разнесёт запросы); старые поисковые кампании не переделываем, весь Search собираем заново.
- **Проверка трекинга на страницах каталога и карточки (14.10, Playwright + публичный GTM-5FBCZLMC + скрипты Tilda):**
  - Подмена Ringostat: при `utm_source=google&utm_medium=cpc&utm_campaign=general_pmax` на главной, каталоге с фильтром и карточке (desktop и mobile) везде `+48 172 508 541` (пул PMax), статический номер сайта не показан.
  - GTM-5FBCZLMC и скрипты Ringostat, Метрики, Facebook грузятся на всех трёх типах страниц.
  - Конверсия формы: в контейнере тег срабатывает на событие dataLayer, подходящее под регулярку `submit_form*`, без условий по адресу страницы; это событие `submit_<id формы>` шлёт собственный скрипт Tilda (`tilda-forms-1.0.min.js`), он подключён и на каталоге, и на карточке. «Клик по номеру» — отдельный триггер на любой клик по `tel:`.
  - **Не проверено:** реальная отправка формы заказа («Zamówienie») на карточке — тестовую заявку не отправляли (создала бы конверсию и строку в Supabase). Подтверждение — первая реальная форма после запуска: сверить Ads и Supabase.
  - Побочный вывод: регулярка срабатывает на **любую** форму Tilda (опросник, обратный звонок, заказ) — все они считаются как `form_submit_web`.
