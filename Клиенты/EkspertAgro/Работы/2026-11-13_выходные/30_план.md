## 3. Сторож (`guard_config.yaml`)

Изменений в конфиге не требуется (`python gads_spend_guard_cpa.py --client EkspertAgro --print-config` выполнен, без API: общий аванс 2, предел 2 x бюджета). Личный `grace` не ставить (по брифу): он не зависит от дня недели.

Как сторож ведёт себя в субботу (код `gads_spend_guard_cpa.py`, чтение строк ~940-1130 и README «Универсальный сторож», «Сторожа: рабочее окно»):
- Окно `stop_at 18:00` / `start_at 07:30`: суббота 08:00-14:00 внутри окна, дня недели в правилах нет. Последний такт в 18:00 - после закрытия показов в 14:00.
- Паузы субботы: предел 2 x 50 = 100 (ставит `no_resume`, утром не включает); «цена заявки» 208 zł (позже предела); «темп» 20 zł/30 мин при 0 заявок. Правило «расход без заявок подряд» (`dry_mult 3` x 104 = 312): считает расход с последней заявки, копится через дни; день без расхода добавляет 0, день с заявкой обнуляет; включение кампании из паузы обнуляет счёт (строка кода «кампанию включили после паузы»). Значит: нулевые выходные не создают ложной субботней паузы, а запас на момент включения (через `gads_set_campaign_status.py`) - 312 zł с нуля. Состояние на 13.11 16:01 (`gads_spend_guard_state.json`): у `shop_pmax` счёт 0, сегодня 88,28 при базе 13,75 и 0 заявок.
- Обратное: суббота без заявок на ~100 zł оставляет на пн-вт ~212 zł запаса до паузы «подряд»; такая пауза - с `no_resume` (утром не включит). Это не ложное срабатывание, а правило, но стоимость эксперимента включает риск потери утра понедельника. Смягчить без правки кода нельзя (личного `dry_mult` в конфиге нет); если захотите - вопрос 5.
- Утреннее возобновление (07:30 каждый день, включая сб и вс): включает только то, что сторож сам поставил на паузу по «цена заявки»/«темп». В субботу 07:30 это не спровоцирует показ, пока не наступит 08:00.
- Правка расписания сторож увидит как «ВМЕШАТЕЛЬСТВО (не сторож): расписание показов 5 -> 6 интервалов» (Telegram), паузу из-за правки не ставит.
- Работает ли процесс в субботу, не знаю: задача стартует при входе пользователя, не будит ПК (`Get-ScheduledTask`, 13.11). Факты по логу `gads_spend_guard_cpa_log.csv`: записи в сб 31.10 (00:00-23:46), сб 07.11 (00:00-18:17), вс 08.11; 12.11 строки только 00:01-00:14 (`ResourceExhausted`), потом пусто до 13.11 10:17. Следствие: 12.11 включённые кампании работали без сторожа (расход `shop_pmax` 56,95 за день, `window_check.py`).
