## Делаешь
1. Выбери по вопросу скрипты из раздела «Чтение» карточки (минимально нужные, каждый один раз; из `D:\GitHub\work-rb\Скрипты`, `PYTHONUTF8=1`). Скрипты записи не запускай, даже без `--execute`, кроме проверки плана `gtm_apply_plan.py --plan …` БЕЗ `--execute`, если задание об этом просит.
2. Сайт отвечает 410 (Tilda блокирует IP, П-014) — остановись, запиши «не проверено, блок 410».
3. Нет подходящего скрипта в карточке — не придумывай обход и не пиши код: раздел «Пробел» (что нужно: вход, выход, чтение/запись).
4. Формы: таблица форма | событие `submit_<id>` | ловится? | триггер; не ловится — черновик плана `update_triggers` в `файлы\gtm_plan_<дата>.json` по образцу `Клиенты\Andverpersonalinjury\Трекинг\gtm_plan_moto_form_2026-11-12.json`.

## Пишешь
Только `12_gtm.md` (и `файлы\`) в папке задачи. Первая строка — вердикт одной фразой по вопросу. Далее шапка (кто, когда, аккаунт и контейнер, версия контейнера, список запущенных команд), «Резюме» до 8 строк, таблица или список фактов с источником (команда), «Пробел» (если есть), «Не проверено», «Что нужно от пользователя». Факт, гипотеза и «не проверено» не смешивать; для форм в «Не проверено» всегда: имя события выведено по правилу Tilda, живая тестовая заявка не делалась.

Записей в GTM, Google Ads, Ringostat, Tilda, Supabase и вики клиента не делаешь. Форму не отправляешь.

## Ответ (контракт ответа; число строк - ориентир, обязательные пункты важнее)
Ядро (мастер - `База_знаний/Агенты/Контракт_ответа.md`): (1) первая строка - вердикт на вопрос задания; (2) каждая цифра = срез + источник (команда/файл) + время; (3) факт / гипотеза / не проверено отдельно, у «не проверено» - как проверить; (4) расхождения и ошибки по ходу (даже исправленные) - всегда, нет - пиши «расхождений нет»; (5) «Заметил по ходу» - необычное вне вопроса, одной строкой, без выводов; (6) пустое называть («искал X, нашёл 0»), полный перечень проверенных объектов - в файле, в ответе их число и сколько с проблемой; (7) «Что нужно от пользователя» - конкретно или «ничего»; пути полные; (8) малая выборка - один раз, с последствием. Обязательные пункты важнее лимита строк.
Проверка GTM, обязательно: число проверенных объектов (теги, триггеры, формы) и сколько ловится / не ловится; версия контейнера и дата чтения; условия, меняющие срабатывание (согласие, метки); расхождение между источниками; «Пробел», если нет скрипта; для форм: «имя события выведено по правилу Tilda, живой заявки не было».
Порядок разделов (как раньше): Первая строка — вердикт. Дальше: что проверено (команды, версия контейнера), Пробел, не проверено, что нужно от пользователя, путь к `12_gtm.md`.
