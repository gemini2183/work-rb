1. **Страница** (пропусти, если в постановке сказано «страницу проверяет page-check» — тогда её результат в `11_страница.md`, а в «Страница» своего файла дай ссылку на него): `page_tracking_check.py --url <адрес> --client-folder <Имя>` — один раз; затем `phone_swap_check.py --client-folder <Имя> --pool-file "Коллтрекинг/Пул_номеров_<страница>_tilda.yaml"` — один раз (путь относительно папки клиента; без `--pool-file` скрипт проверяет главный сайт, а не страницу, П-004). 2. **Образец:** ближайшая действующая кампания клиента (по Паспорту) — `gads_campaign_settings_xlsx.py --customer-id … --campaign-id … --client-folder …`; в данные пиши путь к xlsx и 5–8 строк сути (стратегия, бюджет, гео, языки, цели, число групп).
3. **Состояние объекта:** если задача про существующую кампанию — `gads_campaign_settings_xlsx.py --campaign-id <кампания объекта>` (гео, язык, цели, ключи с одобрением, объявления, ссылки, ассеты); `gads_campaign_state_dump.py` гео, ключи и объявления не печатает (П-017), годится только для статусов и ставок групп. В `10_данные.md` — путь к xlsx и 5–8 строк сути по объекту. Не бери «готовый снимок» вместо свежей выгрузки без явного указания в задании.
4. **Объёмы и ставки по ключам** — `gads_keyword_volumes.py` (если в постановке есть список ключей или тема), показать диапазон ставки «верх страницы» и объём.
5. **Стоимость в операциях API** — `gads_clone_plan.py` / журнал `gads_quota_ledger.py`, сколько уже потрачено за сутки (лимит 15 000).

Не гоняй лишних запросов к кабинету: суточный лимит API (П-001); упёрся в лимит — остановись и сообщи.

## Ответ (контракт ответа; число строк - ориентир, обязательные пункты важнее)
Ядро (мастер - `База_знаний/Агенты/Контракт_ответа.md`): (1) первая строка - вердикт на вопрос задания; (2) каждая цифра = срез + источник (команда/файл) + время; (3) факт / гипотеза / не проверено отдельно, у «не проверено» - как проверить; (4) расхождения и ошибки по ходу (даже исправленные) - всегда, нет - пиши «расхождений нет»; (5) «Заметил по ходу» - необычное вне вопроса, одной строкой, без выводов; (6) пустое называть («искал X, нашёл 0»), полный перечень проверенных объектов - в файле, в ответе их число и сколько с проблемой; (7) «Что нужно от пользователя» - конкретно или «ничего»; пути полные; (8) малая выборка - один раз, с последствием. Обязательные пункты важнее лимита строк.
Проверка, обязательно: число проверенных объектов (формы, теги, номера, ссылки) и сколько работает / не работает; адрес и код ответа сайта; версия контейнера и дата чтения; мобильный экран и десктоп - что проверено; условия, меняющие срабатывание (согласие, метки); расхождение между источниками (страница против кабинета); образец кампании и его дата.
Порядок разделов (как раньше): Сделано / Проверено (источник, время) / Не проверено и как проверить / Блокеры / Что нужно от пользователя / Пути к файлам. Страница готова или нет — первой строкой.
