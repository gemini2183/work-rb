Клиентский дашборд «Аналитика → Ads + FB» (скрины 20.10, фильтр 01.10–19.10): **Звонки** = первый звонок номера за всю историю Ringostat (не правило 60 дн); **Конверсии** = звонки + формы GA4 (сеансы `form_submit` по источнику сеанса: google/cpc → Google, facebook* → Facebook, остальное → «Нет метки»); **Продажи** = единицы товара из списка заказов (Дата UTC, Заказ, Телефон, Товар, Кол-во, UTM, Площадка), источник = метка заказа в CRM (форма по UTM; заказ менеджера → «Телефон»); учитываются только заказы, **первое обращение которых в нашей выгрузке не «Телефон»** — 01.10–19.10 это 75 из наших 101, цена продажи 3705,26/75 = 49,40 € = клиентская. Курс USD→EUR у клиента для расхода Facebook 0,8244.

**Why:** пользователь искал, кто неправильно считает цену продажи (у нас 36,69 €, у клиента 49,40 €). Наша ошибка: Итого делили на все 101 проданный заказ, включая 26 с первым обращением «Телефон».

**How to apply:** цену продажи по рекламе считать на заказы, начатые Google/Facebook/«Нет метки» (по первому обращению), заказы «Телефон» показывать отдельной строкой, а не в делителе рекламы; по Google считать по первому обращению (65 €), не по метке клиента (188 €). Не выяснено: почему клиент не берёт «Телефон»-заказы и входят ли среди них рекламные. Данные и скрипты: `Скрипты/profimet_sources_dashboard.py` (Google Таблица «ProfiMet — по источникам (дашборд)», режим B7 «как у клиента»), `profimet_orders_list.py` (вкладка «Заказы»).
