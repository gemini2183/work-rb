Главная задача пользователя: СВОЙ дашборд заявок ProfiMet (затем ExpertAgro), заявки совпадают с BigQuery, расхождения с другими платформами находить быстро и оспаривать у клиента; потом продажи.

Сделано 05.11: `Скрипты/profimet_leads_matrix.py` (матрица «платформа × канал», блок «СВЕРКА С ЭТАЛОНОМ BigQuery»). Звонки: правило Ringostat 60 дн = BigQuery до единицы (за 01.10–04.11: Google 129, Facebook 18, SEO 58). Формы 01–27.10: BigQuery = GA4 сеансы (33 / 4 / 16); Facebook в Tilda/Supabase/CRM по 9 — GA4 не получает (нет cookie GA; все 12 форм без GA-cookie есть в Supabase, 11 из 12 с UTM). Фильтр BigQuery (`ga4_profimet/main.py`, стр. 103) оставляет только google/cpc, facebook/cpc, google/organic — НЕ менять (решение пользователя, BigQuery эталон). Tilda_Leads не пополняется с 27.10 (у ExpertAgro с 26.10). Tilda не хранит `utm_*`, метка читается из `referer`; CRM иногда знает метку точнее адреса Tilda (4 формы). Сноска клиентского дашборда про двойной счёт — пользователь ещё пришлёт; прежний замер 22.10: 5 дублей из 136.

Решено: Supabase — самая полная база форм для источников. Тег 147 «UTM - сохранить в браузере» кладёт utm_* и gclid в `localStorage` только при `ad_storage`; тег 117 «Supabase - Leads» согласия не требует. План: колонки `fbclid`, `gbraid`, `wbraid` (пользователь добавляет), перенос меток по внутренним ссылкам пока нет согласия, `in_app` по желанию. gbraid/wbraid нужны для загрузки продаж в Google Ads, не для определения источника.

ВЕЧЕР 05.11 (вторая сессия): вкладка «Платформы» построена в Google Таблице дашборда `1yQ4YnDv…` (`Скрипты/profimet_platforms_tab.py --execute`, листы «Платформы», «Платформы_данные»; после `--rebuild-sheet` основного дашборда записывать заново). Основной лист «Дашборд» обновлён по 04.11 (стоял на 19.10). Продажи 06.10–04.11 по схеме клиента (наше воспроизведение): 127 заказов, Google 32 / Facebook 5 / «Нет метки» 25 / «Телефон» 65; из 25 «Нет метки» 13 — рекламные формы с потерянной меткой (Google 11, Facebook 2). Список для клиента: `Клиенты/ProfiMet/Статистика/client_list_lost_marks_2026-10-06_2026-11-04.csv`. Осталось: список продаж из дашборда клиента за 06.10–04.11 (ждём от пользователя), определение «формы» для нашего дашборда, сноска клиента про двойной счёт.
