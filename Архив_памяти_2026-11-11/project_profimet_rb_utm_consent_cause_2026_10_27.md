Причина установлена 27.10 браузерной проверкой живых контейнеров (`Скрипты/gtm_utm_persist_probe.py`). ProfiMet: согласие `denied` по умолчанию + баннер; тег 147 требует `ad_storage` на All Pages → у нового посетителя не срабатывает, клик «принять» его не перезапускает. ExpertAgro: согласие не задано (`undefined`), баннера нет → пишет всегда. Баннер ProfiMet при принятии шлёт событие `consentTypeSelected` (триггер 85 уже есть).

**Why:** ответ на открытую задачу в Клиенты/ProfiMet/Задачи.md; «конфиг тега одинаковый» — различие в состоянии согласия сайта, не в теге.

**How to apply:** следующий шаг — добавить тегу 147 второй триггер 85, проверить порядок с тегом 86 через `gtm_test_version.py --click` по баннеру, публиковать только по «да» пользователя. Заодно вопрос клиенту ExpertAgro: метки там хранятся без согласия посетителя. См. [[project-forms-funnel-state-2026-10-27]].

**Обновление 27.10 (позже):** версия 90 (триггер 85 прямо на теге) не сработала — GTM решает, какие теги запускать, в начале события, согласие баннер выдаёт внутри него. Версия 91 (тег на событии баннера кладёт `rb_consent_selected`, на него тег 147) протестирована и работает, НЕ опубликована, живая v89, откат v89. Ждёт «опубликуй» пользователя, потом замер доли заявок с метками через 3–5 дней. ExpertAgro: окна согласия не видно, согласие в GTM не настроено вообще (все теги notSet, кроме нашего 29).
